# 概念组表与缺口清单模板

两份表是综述的骨架。表写对了，草稿基本就是把它连成句子；表写歪了，草稿再顺也是在编。

## 一、概念组表

```
| 组 | 在争什么 | 各篇立场 | 证据差 | 本组现状 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |
```

### 列说明

**组**：编号加一句可争论的话，例如 `G1 长文档要不要先切块`。不要写名词（「长文本」「检索」），名词组名会让人不自觉地把不相关的东西塞进来。

**在争什么**：写成问句，一句话。判断标准是这句话能不能被回答成「能 / 不能 / 看条件」。答不了的问句说明还没分组清楚。

**各篇立场**：`作者(年)：立场` 一行一个，用分号隔开。立场要能对立，全是「提出了改进」就说明这组没有真争论，只是并列。

**证据差**：只写四类差异——数据规模与来源、评测设置与切分、基线选择、是否同分布。不写模型结构差异，那是方法细节，读者可以自己查。这一列的目标是回答「它们的数字能不能放在一张表里」。

**本组现状**：一句话，写这一组目前卡在哪，或已经收敛到什么共识。写不出就说明这组还没读完。

### 填表时的三个检查

1. 每组二到五篇。超五篇拆组，只有一篇标「孤例」。
2. 同一篇可以出现在两组吗？可以，但要在第二组注明「另见 G1」，不要把同一段介绍抄两遍。
3. 组名里的关键词，在「各篇立场」里必须都能对上。对不上的那一篇，放错组了。

## 二、缺口清单

```
### 方法缺口
- 谁与谁之间：…
  补上需要：…

### 数据缺口
- 谁与谁之间：…
  补上需要：…

### 场景缺口

### 矛盾未解

### 重复验证不足
```

### 每条的三段式

`缺口名` → `谁与谁之间` → `补上需要什么`。三段缺一段，这条缺口就不能用：

- 只有缺口名：是口号，读者没法核。
- 有缺口名和谁与谁，没有补法：读者知道有问题，但不知道该不该自己做。
- 三段齐了：读者能判断这是不是他的机会。

### 写的分寸

- 一条缺口只写一个「谁与谁」。两个合并写，读者会以为是一件事。
- 缺口不是批评某篇论文写得差。措辞对准「这两者之间没有比较 / 没有数据」，不对准「作者疏忽」。
- 同一类缺口超过三条时，合并成一条并列举，避免清单变长变水。
- 最后一条通常是「重复验证不足」，因为多数领域的领先结论都只出自一两个团队。写这条时要给篇名，不要泛泛说「缺乏独立验证」。

## 三、两表与草稿的对应关系

草稿的每一段对应一组，段落里的比较句对应「证据差」列，转折句对应「本组现状」，缺口句对应缺口清单。

写草稿时如果发现某句话在两表里都找不到落点，那句话是填充句，删掉。

## 四、落盘

- 两份表放在草稿之前，不要塞进附录。读者先看地图再看叙述。
- 组编号在草稿里继续沿用（「如 G2 所示」），不要换一套称呼。
- 篇数、年份、指标数字原样抄。作者写 2021，不要写「近年」。
