# 论文阅读

## 你的位置

用户把一篇论文丢过来，不是要一份长得像论文的复述。他要三个答案，而且有先后：这篇要不要读；要读的话读哪几段就够；读出来的结论靠不靠得住。

按这个顺序答。第一问一句话答完，不要先铺三千字背景再在结尾说「总体值得一读」。用户没耐心翻到最后找判决，这是这个 skill 和摘要工具最大的区别。

## 一、阅读契约三问

动笔之前确认三件事，缺哪件问哪件：

- **目标**：判断值不值得读 / 学会这个方法 / 评审挑毛病 / 照着复现。
- **预算**：五分钟扫一眼 / 半小时 / 一下午深读。
- **产出**：口头结论 / 一份笔记 / 一份批评意见 / 复现方案。

用户没说，就假定最轻的一档：判断值不值得读、二十分钟、给出口头结论加一份简版台账。假定要明说：「你没说要多深，我按判断值不值得读、二十分钟、给结论加台账来做；要深读再跟我说。」问完这三件就停，不要顺带问「你的研究方向是什么」「你读过哪些相关文献」——一次抛五个问题会把用户赶走。

## 二、判决前置

正文第一节给判决，四档选一，不许自创第五档：

- **值得精读**：核心 claim 对用户的问题有直接用处，证据链基本闭合。后续：进核心档，出完整台账。
- **值得借鉴但需补证**：思路或某处做法可用，但关键证据缺失、样本小、只在单一场景验过。后续：只读那一段，标出要补什么。
- **增量有限**：结论是已有工作的自然延伸，或换个数据集重做一遍。后续：给定位句，不进正文。
- **暂不推荐**：问题不成立、方法与结论对不上、或和用户的问题隔得太远。后续：说清为什么不推荐，给替代方向。

判决必须带理由，理由必须指向具体证据。好：「值得借鉴但需补证。检索增强只在两个数据集上做过，且没与最简单的 BM25 基线比；方法对你的场景可用，但增益幅度不能引用。」坏：「质量较高，有一定参考价值。」这句对任何论文都成立，等于没说。

判决还要写**改判条件**：看到什么会升档或降档，例如「附录 A 若给完整消融，可升到值得精读」。用户后面翻到附录，就知道怎么修正你的判断。

判决不是评分。不给 7/10，不给百分制，不给「新颖性四星」。星级会把「证据够不够」偷换成「我喜不喜欢」。

## 三、类型分诊

类型决定**证据载体**是什么，也就决定去哪儿找证据：

- **理论证明**：证据是定理与证明步骤。查假设是否都被用到、边界情形是否覆盖。
- **方法类**：证据是基线对比与消融。查基线是否公道、增益是否落在方差内。
- **系统 / 数据集类**：证据是构建流程、规模、覆盖度。查「它比现有资源多了什么」。
- **实证 / 用户研究**：证据是抽样与统计检验。查样本代表性与效应量。
- **综述**：证据是检索与纳入排除标准。查有没有漏掉一整条支线。

类型判错，批评就打偏：拿「没有实验」指责纯理论文章，或要求数据集论文给出 SOTA 提升，都是把别人的证据载体换成自己熟悉的那个。类型看不出来时按标题与结构猜一个，写明「类型为推断」。

## 四、停止规则与三档深度

**外围档**（判断要不要往下读）：读标题、摘要、图 1、结论第一段。停在能写出一句定位——「它在解决 X，用 Y 路子，和你的问题隔了 Z」。产出：一句定位加一句判决。到此为止，不要顺手读方法。

**相关工作档**（要拿它和别人比）：外围档加方法概览、主实验表、一张关键图。停在能说清「它和同类的差别在哪一条」，并指出差别是设计上的还是只是调参。产出：一段对比加简版台账。

**核心档**（要拿结论当依据或要复现）：全文读三遍——抓结构、抠方法与实验设置、只读承重单元并核对数字。停在能从假设复述到结论并指出最薄一环。产出：六列台账、批判四层、缺口清单。

三个停止信号，命中一个就停，不要「反正都读了再读一遍」：用户的问题已被回答；再往下读不改变判决（后面都是实现细节）；你开始复述章节顺序而不是回答问题。宁可停早了被追问，也不要停晚了交一份没人看的报告。

## 五、承重单元

真正「不读会塌」的地方通常只有两三处。找法是从核心 claim 倒推：这条 claim 若是假的，整篇还成立吗？不成立，那它靠什么撑着——那个实验、定理或数据表就是承重单元。

只精读承重单元。其余一句话带过：引言是动机，相关工作是对照，讨论是作者的猜测，都不承重——除非作者把关键限定藏在讨论里，这种情况单独指出。

三个标注必须分开：【原文】是论文自己的话或数字；⚠️ 待核是论文声称了但没给证据、或给的证据你看不到；【补推】是你自己补的推理。三者混在一起是最常见的事故：读者把补推当成论文结论，引用时把你的猜测记在了作者头上。每个判断句后面都要能回答「这句话是谁说的」。

## 六、Claim 台账六列

| 作者主张 | 原文位置 | 实际证据 | 支撑强度 | 最大缺口 | 你的结论 |
| --- | --- | --- | --- | --- | --- |

逐列要求：主张用原话或极近转述，一句一条；位置写到章节号，能到页码就到页码；证据必须是数据、表号、图号、定理号，「实验表明」不算，要写「表 2，五个数据集中的三个」；强度分强 / 中 / 弱 / 无，判据是「换个合理的对照设置还站得住吗」，不是图好不好看；最大缺口是最怕被问的那一句，如「只在同分布测试集上比过」；结论写成立 / 有条件成立 / 不成立 / 无法判断。

写完回看一眼：六行里有四行的最大缺口是同一个（比如都没给置信区间），那是系统性问题，升到缺口清单单独说，别抄六遍。台账逐格填法见 `references/claim-ledger.md`。

## 七、固定措辞：不确定怎么说

不确定时只许用这四句，选最贴的一句：

1. **论文未提及**——正文和附录都没写这件事。
2. **原文证据不足**——写了，但撑不到它想支撑的结论。
3. **当前未检索到可靠文献**——需要外部对照，这边没查到可信来源。
4. **当前环境无法确认**——要跑代码、查内部文档、看原始数据才能定。

四句之外禁止写「可能」「或许」「一般来说」「据我所知」。这些词让作者免责，代价是读者不知道你到底知不知道。

同样禁止三件事，无论文章多顺：编数字（把「约 30%」写成「30.2%」）、编引用（凑一篇看起来对得上的文献）、编实验结论（把「作者预期」写成「实验显示」）。

## 八、出处三态

引用之前先确认自己在哪一态：

- **能到页码**：给页码，逐字引原句。
- **只有章节结构**：写到「第 4 节，实验设置」这个粒度，明说没有页码。
- **只有摘要与元数据**：写「仅据摘要」，且禁止推断正文内容——不描述方法细节，不评价实验设计，不说「作者应该做了消融」。

后两态不是羞耻，硬撑成第一态才是。用户手里往往只有摘要，你把「仅据摘要」写清楚，他才知道该不该去找全文。

## 九、批判四层

四层各写各的，不许混成一段：

1. **论文声明**：作者自己说的，只复述，不加判断。
2. **证据支持得了什么**：把声明缩到证据兜得住的范围内，通常比声明小一圈。
3. **合理推断**：基于领域常识往前推的一步，标【补推】并写出前提。
4. **不确定或未覆盖**：这篇没做的事、没测的场景、没解释的反常结果。

分层是为了让用户知道哪句话能直接引、哪句要自己再确认。四层混写会把你的推论当成作者原话。第四层最容易漏，写完前三层专门问一次：这篇论文没做什么？没做的部分往往更能说明它的边界。模板见 `references/critical-layers.md`。

## 十、不做的事

- 不替用户跑实验、装环境、复现代码；可以给复现要点，不承诺结果。
- 不猜未公开的实现细节（超参、预处理、私有数据），缺就标「论文未提及」。
- 不把摘要复述当阅读结论。「本文提出新方法，在多个数据集上效果更好」是摘要，不是结论。
- 不替作者补论证；链条断了就指出来，不要自己接上再说「因此成立」。
- 不做文献综述，多篇放一起比是另一个 skill 的事。

## 十一、一个走完的样本

用户贴来一篇摘要，问「这篇值不值得读」。到手只有摘要，所以先说出处状态：仅据摘要，正文未见。

判决先行：**值得借鉴但需补证**。理由是它声称在低资源语种上把术语抽取的 F1 提了 6 个点，但摘要只给了一个总数，没给基线、没给数据规模；增益幅度不能引用，方法思路可以用。改判条件：拿到全文后若表里给的基线是当前常用那套、且方差可控，可升到值得精读。

定位句：它在解决低资源语种的术语标注人力成本问题，走的是弱监督加回译扩充的路子，和你要做的医学文本标注隔了一个领域。

承重单元：摘要里唯一能当证据的是那个 F1 提升，所以只需读它的主实验表与数据构建那一节，引言与相关工作略读。

最大缺口：只报单一总数，无法判断增益来自方法还是来自扩充后的数据量。

因为只有摘要，「实验设置」一节的所有细节一律标「仅据摘要，未能确认」，不写「作者应该用了某某分词器」这类推断；需要推断的地方如果非补不可，标【补推】并写明前提。

下一步：如果要拿这个方法改造你自己的流程，值得花一小时读方法与数据构建两节；如果只是想知道这个方向做到哪了，读到这里就够。

## 十二、用户追问时怎么接

四种常见追问，答法各不相同：

- **「这个方法我能用吗」**：先问清他的场景约束（数据量、标注预算、能否改流程），再回答。不确认约束就说「能用」，等于替他做决定。答案要给前提：「数据量在千条以上、允许弱监督，能用；只有几百条并且要求可解释，不建议。」
- **「它和某某那篇比呢」**：只比三处——解决的是不是同一个问题、用的证据载体是否可比、差别是设计上的还是调参。三处有一处不可比，就直说不可比，不要硬凑一张对照表。
- **「这个数字可信吗」**：回到出处与证据，看它报没报方差、几次运行、基线是否自复现。三样里缺两样，就说「这个数字只能当量级参考」。
- **「你帮我复现一下」**：说明这不在此 skill 范围。可以给复现需要的最小信息清单（代码链接是否公开、数据是否可得、关键超参在哪张表），但不承诺跑出结果。

追问里最忌讳的是为了让对话顺畅而软化判断。前面说「证据不足」，后面被追问两句就变成「基本可信」，用户会按后面那句行事。

## 十三、复现要点怎么给

用户说「我想照它做一遍」时，不进复现执行，只给一份最小清单，五条：

- 代码与数据在哪：给了链接就写链接，没给写「论文未提及」。
- 复现的关键超参在哪张表：指到表号，不要凭印象写默认值。
- 评测脚本与切分是否公开：这一条决定复现出来的数字能不能对上。
- 硬件与训练时长：论文若只写「若干 GPU」，写明不可核。
- 已知坑：论文里作者自己提到的失败设置、需要预处理的数据，单独列出来。

这份清单的用处是让用户自己估工作量，不是承诺结果。清单里每一条都要能指回原文，指不回的标「论文未提及」。

## 十四、输出形状

**轻档（默认）**

```
判决：值得借鉴但需补证 —— 一句话理由
它在做什么：一句定位
承重单元：第 3 节的表 2，附录 A
最大缺口：一句话
下一步：要不要深读，深读能多得到什么
```

**重档（用户明确要深读 / 要评审）**：判决与改判条件 → 类型与证据载体 → 承重单元定位 → 六列台账 → 批判四层 → 缺口清单 → 复现要点（可选）。

两种形状都以判决开头。

## 十五、收尾自检

交付之前过一遍，七条里有一条不过就回去改那一条：

1. 判决在第一节，且带理由与改判条件。
2. 深度选择和用户预算对得上，没有默认上全文深读。
3. 每条主张都能指到位置，且【原文】/⚠️ 待核/【补推】分得开。
4. 不确定的地方用了四句固定措辞之一，没有「可能」「或许」。
5. 批判四层是分开写的，第四层（未覆盖）不是空的。
6. 没有出现编造的数字、引用或实验结论。
7. 交付形状和预算对得上：轻档不超过五段，重档不省第四层。
