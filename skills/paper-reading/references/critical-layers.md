# 批判四层：模板与判据

写批评最容易出的事，是把「作者声称」「数据说明」「我觉得」混成一句话。读者分不清哪句能引、哪句要自己再确认，整段批评就废了。

四层分开写，是让每句话都带出处身份。

## 骨架

```
### 一、论文声明
（作者自己说了什么，只复述）

### 二、证据支持得了什么
（把声明缩到证据兜得住的范围内）

### 三、合理推断
（我的推论，标【补推】并写前提）

### 四、不确定或未覆盖
（没做的、没测的、没解释的）
```

四层固定顺序：从作者往外走，越往后离证据越远。顺序反过来，读者会先接受你的结论再去看证据。

## 第一层：论文声明

- 只写作者明说的，不加「显然」「实际上」。
- 引用要给位置：摘要第几句、第几节、图注。
- 允许压缩，不允许加强。作者写「在多数设置下优于基线」，你不能写成「优于基线」。
- 这一层可以整段用引号包住，标明是转述还是原话。

这一层写不好，后面三层全歪：你把作者的弱结论读成强结论，再一批评，批的是自己造的稻草人。

## 第二层：证据支持得了什么

写法是把第一层的话改写到「证据刚好兜住」为止。常见缩法：

| 作者写的 | 证据兜得住的 |
| --- | --- |
| 显著提升 | 在这三个数据集上高 1–3 点，未报方差 |
| 通用方法 | 在英文新闻域上验过，其他域未测 |
| 证明其必要性 | 去掉该模块后指标下降，未排除参数量的影响 |
| 优于现有方法 | 优于它自己复现的两个基线 |

这一层的每句话都要能回指到表号、图号或定理号。指不到，就退回到「原文证据不足」。

注意区分两件事：

- **证据不足以支持**：方向可能对，但这次没测够。写「证据不足」，不要写「结论错误」。
- **已证明无效**：对照组明确更好，或该设定下失败。这才叫「不成立」。

把前者写成后者，是审稿意见最常见的冤枉。

## 第三层：合理推断

- 必须标【补推】。不标就等于冒充作者的话。
- 每一条都要写前提：「若该数据集与你的场景同分布，则……」
- 推断链最多两步。三步以上的推断说出来像结论，其实全是猜。
- 推断可以带方向判断（「这条路更可能在低资源场景先落地」），但要说明依据是领域常识还是这篇的数据。

用户拿推断去做决定之前，应当知道这是推断。标出来就是尽到了告知。

## 第四层：不确定或未覆盖

写完前三层，专门空一段来列这篇**没做**的：

- 没测的场景（其他语言、其他规模、其他硬件）。
- 没解释的反常结果（某个数据集掉了点，没给原因）。
- 没交代的流程（数据清洗规则、标注一致性、超参搜索范围）。
- 没比较的对象（最新基线、更简单的方案）。

这一层不是挑刺清单，是边界说明。用户读完应当知道：这篇在什么范围内可信，出了这个范围要自己补。

措辞用固定四句：论文未提及 / 原文证据不足 / 当前未检索到可靠文献 / 当前环境无法确认。不要写「可能作者没做」，读起来像暗示。

## 三种常见混层，见到就拆

1. **把推断写成声明**：「作者认为该方法可以推广到医疗领域」——作者可能只说了「值得进一步研究」。回到第一层核对原话。
2. **把证据不足写成不成立**：「因为没有和 BERT 比，所以结论无效」——应写「未与 BERT 比较，相对优势未知」。
3. **把未覆盖写成缺陷**：「没有做多语言实验，是明显短板」——如果论文题目就限定单语，这不算缺陷，只是边界。先看它自己划的范围。

## 交付时的排列

- 四层用小标题分开，不要合成一段议论文。
- 第二层与第三层之间加一句过渡，说明哪句开始是推论。
- 第四层放最后，篇幅不必长，三到五条即可。

需要压缩篇幅时，压缩第一层（复述可以短），不要压缩第四层。前三层读者自己能补，第四层只有你知道。
