# Claim 台账：逐格怎么填

台账是核心档的产物。它的作用不是记录论文说了什么，而是把「作者说的」和「证据撑得住的」分开放，让读者一眼看出中间那段落差。

## 骨架

```
| 作者主张 | 原文位置 | 实际证据 | 支撑强度 | 最大缺口 | 你的结论 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |
```

列序不要调。「主张在前、结论在后」是有意的：读者先看到作者要什么，再看到你判了什么，落差自己会说话。把结论放第二列会让人先入为主。

## 第一列：作者主张

- 一句一条。一句话里有两个可独立证伪的判断，拆成两条。
- 用原话或极近的转述，允许压缩语序，不允许换概念。作者写「在低资源场景下」，你不要写成「在小样本场景下」。
- 不写限定词之外的评价。「提出了一种新方法」可以，「提出了一种很好的新方法」不行。
- 优先抄摘要最后一段与结论第一段，这两处是作者自己划的重点；再补方法节里作者反复强调的那句。

数量控制：一篇论文值得进台账的主张一般三到六条。超过八条说明你在把每个段落都当主张，回到承重单元那一节重挑。

## 第二列：原文位置

按能拿到的粒度写，三态对应三种写法：

- 有页码：`p.7，表 2`
- 只有结构：`第 4.2 节，主实验`
- 只有摘要：`摘要，第 3 句`，并在整张表前面注明「仅据摘要，正文未见」

不要写「文中提到」「作者认为」这种没有位置的说法。位置是这条记录可被核对的唯一保证。

## 第三列：实际证据

写具体载体，不写结论。

- 好：`表 3，四个数据集里三个有提升，第四个下降 1.2 点未解释`
- 坏：`实验结果证明了有效性`
- 好：`定理 2，前提是分布独立，附录 B 给了证明`
- 坏：`有理论保证`

有反例要写进去。只抄支持的那一半，等于替作者做筛选。

## 第四列：支撑强度

四档：强 / 中 / 弱 / 无。

| 强度 | 判据 |
| --- | --- |
| 强 | 有对照、有多组设置、方差已报，换合理设置结论仍成立 |
| 中 | 有对照但设置单一，或只有一组数据，看不出稳健性 |
| 弱 | 只有单点结果、自评、案例展示，或与主张之间隔了一步推理 |
| 无 | 声称了但正文没有对应证据，或证据与主张不是一回事 |

判强度时问一句：如果把对照组换成一个更朴素的基线，这条结论还站得住吗？站得住才算强。

## 第五列：最大缺口

这一格最容易被写空。填法是从「审稿人会先问哪一句」倒推，只写一条，写最致命的。

常见缺口类型，可以直接对号：

- 对照缺口：没和最强基线比，或基线是作者自己复现的。
- 规模缺口：只在单一数据集、单一样本量上验过。
- 统计缺口：没报方差、没做显著性检验、只报最好一次。
- 外推缺口：结论只在同分布下成立，却被写成通用结论。
- 机制缺口：有效果但没解释为什么有效，消融只做了「全删」。
- 数据缺口：数据来源、清洗规则、标注一致性未交代。

如果六行的最大缺口反复是同一类，那不是六条缺口，是一个系统性问题，单列到缺口清单里。

## 第六列：你的结论

四选一：成立 / 有条件成立 / 不成立 / 无法判断。

- 成立：证据撑得住主张，且缺口不影响用户要用它的那个场景。
- 有条件成立：必须写出条件，写成「在 X 前提下成立」。条件是这一格的全部价值，不许省。
- 不成立：说清是主张本身错，还是证据不支持。
- 无法判断：写缺什么才能判断，并且用固定措辞（论文未提及 / 原文证据不足 / 当前未检索到可靠文献 / 当前环境无法确认）。

## 台账之外的缺口清单

台账只记单条主张。跨条的系统问题写在台账下面，三到五条，每条一句：

```
## 缺口清单
1. 全部实验都只在作者自建的数据集上做，第三方复现未出现。
2. 报的是五次取最好，方差未给，增益 1.2 点落在常见波动范围内。
3. 与最强基线未比较，比较对象是两年前的版本。
```

每条都要能回答「这是谁与谁之间的缺口」——是这篇与某条基线之间、还是这篇内部主张与证据之间。

## 落盘时

- 台账用 Markdown 表格，不要用列表代替。表是给人横向扫的。
- 表头上面先写一行判决，不要让读者翻到最后才知道你的态度。
- 数字原样抄，不要四舍五入，不要换算单位。作者的 0.612 就是 0.612。
