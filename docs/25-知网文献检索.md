# 知网文献检索：能做什么，不能做什么

## 结论先说

0.12.0 起，导入面板多一段「④ 知网检索」。**不用登录、不用配账号、不用装东西**，输入主题词就能搜知网的中文文献，勾几条一键存成一本能读、能划线、能问 AI 的「文献集」。

能力和边界在同一句话里：**检索我来，登录和下载你自己来。**

- **能**：搜到真实题录——标题、作者、期刊、年期、文献类型、关键词、被引次数、下载次数、原文链接、正文开头约 160 字。
- **不能**：拿完整摘要，拿 PDF 全文。这两样知网只在登录后给。

这不是没做完，是知网的免费页面本身就到这儿。原因写在下面第二节，都是实测出来的数字，不是推测。

---

## 一、它从哪儿拿数据

知网有两套检索。新的一套在 `kns.cnki.net`，也就是你平时在网页上用的那个；老的一套在 `search.cnki.com.cn`。

**插件只走老的那一套。** 原因是新的那套在程序里根本进不去：

| 入口 | 程序里访问的结果 |
| --- | --- |
| `kns.cnki.net/kns8s/defaultresult/index?kw=` | 302 到 `/verify/home?captchaType=blockPuzzle`，极验滑块页，2355 字节 |
| `kns.cnki.net/kns/brief/result.aspx`（更老的版本） | 同上，落到滑块页 |
| `kns.cnki.net/knavi/journals/index`（期刊导航） | 同上 |
| `search.cnki.com.cn/search/listresult` | **200，正常返回 HTML 结果** |

滑块那条路我把浏览器指纹头带全了（`sec-ch-ua`、`sec-fetch-*`、`upgrade-insecure-requests`、`accept-encoding: br`）、把首页拿到的 cookie 也带上了，一样落到验证页。**程序过不去，只能用真人在浏览器里过。** 插件不做这件事，也不该做。

老站是知网二十年前留下的检索页，现在还在跑。它返回的是一段 HTML 片段，不是 JSON。插件把「HTML 转成结构化题录」写成纯函数，所以解析能脱网测；把「发请求」单独隔开，所以测试可以注入假 fetch。这两个文件是 `lib/cnki.js`。

---

## 二、能拿到什么，拿不到什么

### 拿得到

单条题录有这些字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 检索词命中的部分会带红色高亮，插件会剥掉标签 |
| 作者 | 逐个列出；学位论文的导师不会被误当成作者 |
| 期刊名 | 期刊、会议论文有；学位论文没有（本来就没有） |
| 年期 | 形如 `2007年03期`，学位论文是日期 |
| 文献类型 | 期刊 / 硕士论文 / 博士论文 / 中国会议 |
| 关键词 | 从 `data-key` 拆开，多个词分列 |
| 被引次数 | 精确数字 |
| 下载次数 | 精确数字 |
| 原文链接 | 指向知网详情页，点开是新标签 |
| 摘要片段 | 正文开头，最长 160 字（见下） |

### 拿不到

- **完整摘要。** 这是最需要说清的一条。知网的免费详情页，摘要恒定截断在 128 字，结尾带 `...`。我把期刊页、学位论文页、会议论文页三种都试过，全部一样；`?print=1`、`CJFDTotal-` 大小写变体、`_e.htm` 导出页，字节数一模一样或干脆没有摘要。页面里**没有**隐藏的完整版本（没有 JSON-LD、没有 `citation_abstract`、没有 `DC.Description`，唯一的 meta description 就是关键词串）。
- **PDF 全文。** `pay.cnki.net/zscsdoc/download?...` 会 302 到 `mall.cnki.net/loginspace.aspx`，返回的是一个 11KB 的登录页 HTML，不是 PDF。未登录拿不到。
- **参考文献表。** 详情页有七个分区的标题（引证文献、参考文献、共引文献、同被引文献、二级引证文献、二级参考文献、相似文献），但每个分区下面只有数据库名，没有条目。
- **基金、DOI、作者单位、分类号。** 免费页面里就没有这些字段。手机版页面多一个机构，但摘要一样截断。
- **按文献类型、学科、研究层次筛选。** 参数传什么值都无效，实测返回恒为期刊。
- **按作者精确检索。** `Author=` 是松散匹配，跨学科混排。
- **年鉴、专利。** 没测通，不承诺。

### 摘要片段到底多长

我把上限定在 **160 字**，比知网给的 128 字留一点余量。文献集里的摘要段落**只可能是知网原样给的这段文字**，代码里没有任何「补全」「推测」「拼接」的逻辑，而且每篇后面**必然**跟着这一句：

> （以上为知网免费页面提供的前 128 字以内片段，不是完整摘要。完整摘要与全文需登录知网获取。）

这条写死在 `lib/papercollect.js` 里，有测试守着。**把片段包装成完整摘要算缺陷，不算优化。**

## 三、四种找法

面板上是一个中文下拉，里面四个选项。它们背后是知网的两个检索字段乘四个排序参数：

| 下拉里写的 | 背后参数 | 什么时候用 |
| --- | --- | --- |
| 经典文献（被引最高） | `Title=词&Order=4` | 刚进一个领域，想知道公认的那几篇是哪几篇 |
| 最新发表 | `Title=词&Order=2` | 追前沿，看这两年谁在写 |
| 相关度 | `content=词&Order=1` | 说不准该怎么描述，先随便看看 |
| 下载最多 | `Title=词&Order=3` | 想知道「大家都在下什么」 |

三种带排序的找法都走篇名检索（`Title=`），只有「相关度」用自由词（`content=`）。
代价是**学位论文和会议论文基本只能从「相关度」拿到**——`Title=` 系列回来的几乎全是期刊
（见下面「覆盖范围」一节）。排序正确性优先于类型覆盖：一个排错的榜单比搜不到学位论文
更容易骗人。

### 为什么三种排序都必须用篇名检索

这是实测踩出来的坑，值得单独说。

知网的被引降序（`Order=4`）是**全局排序**，不是「先按词筛再按被引排」。用自由词检索再按被引排，回来的是全库里被引最高的文章，跟你搜的词可能毫无关系：

| 检索方式 | 20 条里有几条标题真的含「滑坡」 |
| --- | --- |
| `content=滑坡&Order=4` | **4 条** |
| `Theme=滑坡&Order=4` | 8 条（40 条里 18 条） |
| `Title=滑坡&Order=4` | **39 条**（40 条里） |

`content=滑坡&Order=4` 的头两条是《中国亏损上市公司盈余管理实证研究》和《股权再融资、盈余管理与上市公司业绩滑坡》——「滑坡」在这是业绩滑坡。

所以面板上带排序的三项（经典文献、最新发表、下载最多），**后台都强制切到篇名检索**。
用了篇名检索，排序就稳了：`Title=地质灾害&Order=4` 连翻五页零重复，被引从 1155 一路降到 129；
`Title=滑坡&Order=3` 的下载数是 27027, 11993, 11151…，单调不增。反例是
`content=滑坡&Order=3`：20 条里只有 1 条标题含「滑坡」，首条是《中国特色社会主义理论体系
的传统文化基础研究》，下载数 52967——比真榜单还大，界面上完全看不出来。

### 覆盖范围

- **篇名检索、主题检索**基本只出期刊（偶尔夹几篇博士论文）。
- **自由词检索**才成批出学位论文（硕士、博士）和会议论文。

实测：「滑坡」下载最多（`Title=`）是 15 篇期刊 + 5 篇博士论文，「相关度」（`content=`）是
18 篇硕士 + 2 篇博士；「教学改革」只有「相关度」能出中国会议。

这是知网自己两套字段的差异，不是插件挑食。想找学位论文，**要用「相关度」这一档，并在词里
带上「硕士学位论文」「博士学位论文」这类词**——两个条件缺一不可。只在「下载最多」或「经典文献」
里加这类词没用：实测「滑坡 硕士学位论文」在「下载最多」下仍是 15 篇期刊 + 4 篇博士 + 1 篇硕士，
在「经典文献」下 20 篇全是期刊；只有「相关度」给出 20 篇硕士论文。而面板默认停在「经典文献」，
所以第一次找学位论文一定要先手动把下拉切到「相关度」。

### 翻页：服务端认到第 20 页，界面目前只取第 1 页

单页固定 20 条。服务端的 `page` 参数最多认到 20 页（400 条）——再深不是人判断得了的量，
也容易把对方站点打疼。但**面板现在没有「下一页」，一次搜索只显示前 20 条**：`page` 是
接口能力，不是界面能力，这里不写没做出来的东西。

想换一批结果的正确做法是换词或换年份，而不是往后翻。

## 四、勾几条，存成一本文献集

这是这一版真正往前走的那一步。原来搜完只能「挑出来 → 自己下 → 拖回书架」，现在：

1. 勾上想留的几篇
2. 点「存成文献集」
3. 书架里立刻多出一本《文献集 · 3 篇》

这本书是货真价实的 EPUB：能打开、能翻页、能划线圈句、能问 AI。圈子一段选「论文分析」模式，拿到的是四档判决那套格式（作者声称 / 证据支持 / 你的推断 / 论文没覆盖）。

每篇一章，内容是：

```
标题
作者 · 期刊 年期 · 被引 N · 下载 N
文献类型
关键词：甲 / 乙 / 丙
原文：<知网详情页链接>
摘要片段
（以上为知网免费页面提供的前 128 字以内片段，不是完整摘要。……）
```

**为什么做成书而不是一个列表？** 因为检索的价值不在「查到了」，在「留下了能反复读的东西」。列表关掉就没了，书会一直在书架上，你的划线、笔记、问答也都归它。

### 已在本地的会标出来

搜出来的每一条，如果它已经在你的书架里（按归一化后的标题比对：去掉书名号、各种引号、空白、标点，全角标点与半角标点视为相同；全角字母数字不算相同），会带一个「已在本地」的角标。这样重复的不会再存一遍。

同一批题录存两次，只会有一本书——因为书的内容完全由题录决定，字节相同，哈希就相同，导入天然幂等。

## 五、每条结果的三个动作

| 按钮 | 做什么 |
| --- | --- |
| 打开知网页 | 新标签打开这条的知网详情页，你自己登录去下 PDF |
| 复制题录 | 把这一条按标准格式复制到剪贴板，粘到笔记、Zotero、Word 里都行 |
| 勾选 | 攒够了几条一起存成文献集 |

复制出来的格式是这样：

```
- 《20世纪以来中国的大型滑坡及其发生机制》. 黄润秋. 岩石力学与工程学报, 2007年03期. 被引 3019, 下载 27027.
  https://www.cnki.com.cn/Article/CJFDTOTAL-YSLX200703000.htm
```

字段缺了就不写那一段，不会出现空括号、`undefined`、`null`。

## 六、为什么不自动登录、不自动下载

`carsi-bridge` 那套做法（Playwright 驱动本机 Chrome、自动填表、自动下 PDF、launchd 每天跑）是个**个人脚本**：跑在自己的机器上、用自己的账号、自己承担风险。

插件要装到别人机器上，三条过不去：

1. **零依赖。** 插件现在 `dependencies: {}`。塞个浏览器进去要几百 MB，每个装插件的人跟着下。
2. **密码必须真实浏览器填。** 学校登录页（金智 authserver）的密码是页面自己的 `encrypt.js` 用动态盐加密后写进隐藏字段再提交的。程序拼个 POST 一定失败，这不是努力就能解决的事。
3. **合规。** 知网的风控会封整所学校出口 IP、可能停用学号。自动化批量下载不是插件该替所有人干的事。

还有一条现实约束：插件的设置文件会随每次修改留历史副本（`settings.json` 会被复制进 `history/` 目录）。**任何写进设置的东西都会有多份副本躺在磁盘上**——这就是「账号密码绝不进设置」的直接理由。

### 所以边界是这样

> 检索我来，登录和下载你自己来。

插件负责让你在几秒内看清「这个领域有哪些文献、哪几篇是被引最高的、哪些是新的」，并把挑中的整理成能读的东西。**下载那一步在你自己的浏览器里完成**，插件不碰你的账号。

---

## 七、明确不做的

- 不自动登录任何学校入口
- 不存密码、不存 cookie、不存登录态
- 不下载 PDF 全文
- 不绕验证码（遇到就停）
- 不做学校直登入口那一层
- 不承诺按文献类型/学科/研究层次筛选
- 不承诺完整摘要
- 不发 npm、不推 GitHub（对外动作由用户自己发起）

## 八、怎么验

### 自动测试

```bash
node test/cnki_test.mjs          # 解析器：三份真实 fixture，不联网
node test/papercollect_test.mjs  # 造书：字节稳定、能被 parseEpub 读、摘要免责句必在
node test/run.mjs                # 全套
node golden/run.mjs              # 金标向量不许变
node client/build.mjs --check    # client.js 与源模块一致
```

### 真机三步

1. 重启 DSH，打开书架，点「导入图书」，面板里应该出现「④ 知网检索」。
2. 选「经典文献（被引最高）」，搜「滑坡」，应该出来 20 条，每条带被引/下载数。
3. 勾 3 条，点「存成文献集」，书架上应该出现《文献集 · 3 篇》，打开能读、能划线、能问 AI。

### 失败时看哪里

| 现象 | 原因 |
| --- | --- |
| 显示「知网这会儿没回应」 | 网络不通，或知网临时不可用，过一会儿再试 |
| 显示「知网没搜到相关的文献」 | 词太窄，或这个词在知网确实没有文献 |
| 结果是 0 条但没报错 | 知网改版让解析抽不到内容了，`lib/cnki.js` 的 class 选择器需要跟着改 |

最后一种情况插件会返回空列表而不是抛错，所以你看到的是「没搜到」而不是崩溃。判断依据是实测：解析器对空串、乱 HTML、被截断的块都返回空列表不抛异常，有测试守着。

## 九、改哪里

| 想改什么 | 改哪个文件 |
| --- | --- |
| 解析规则（知网改版了） | `lib/cnki.js` 的 `parseCnkiResults` 系列 |
| 检索请求头、超时 | `lib/cnki.js` 的 `searchCnki` |
| 翻页上限、词长上限、片段上限 | `lib/cnki.js` 顶部常量 |
| 文献集章节长什么样 | `lib/papercollect.js` 的章节模板 |
| 四种找法的名字和顺序 | `client/src/shelf.js` 的第四个 `select` |
| 「已在本地」怎么判 | `client/src/cnki.js` 的 `normalizeTitle` |
| 错误文案 | `client/src/api.js` 的 `E_PAPER_*` 四条 |

新错误码只有四个：`E_PAPER_QUERY`（没输入词）、`E_PAPER_FETCH`（连不上）、`E_PAPER_EMPTY`（没搜到）、`E_PAPER_COLLECT`（文献集没做成）。

其中 `E_PAPER_EMPTY` 目前是**预留**：没搜到不是错误，宿主返回 200 + `empty: true`，界面自己渲染一句空结果提示。这条文案留着是为了文案表完整，但不会有请求真的返回它。
