# 调研：这些阅读 skill 到底怎么教模型读书

调研时间 2026-11-11。方法：GitHub API 搜仓库 → 逐个用 `github_file` 实读 `SKILL.md` 正文。
**只借方法论与措辞，不复制原文，不搬脚本。** 无 LICENSE 的仓库只作思路参照。

---

## 一、一句话结论

论文阅读这条线，GitHub 上已经有成熟套路，最值得抄的是三件事：

1. **先决定读多深，再开始读**（Keshav 三遍读法 + 停止规则）；
2. **先给判决，再给依据**（值不值得读，四档说清）；
3. **每条结论挂得住出处**（原文位置 / 证据强度 / 没覆盖的部分明说）。

名著解析这条线，GitHub 上的 skill 少而浅，多数是「总结成笔记」，没有真正的文学分析流程。
所以 `book-analysis` 这个 skill 的方法论**主要自己写**，只借它们的输出结构。

## 二、论文阅读类：15 个仓库实读后的取舍

### 2.1 值得借的四条

| 来源 | 借什么 | 为什么 |
| --- | --- | --- |
| **UAACC/how-to-read-paper-skill**（MIT） | **停止规则**：先按「外围 / 相关工作 / 核心」把文献分三档，分别停在第一遍 / 第二遍 / 第三遍，产出物跟着变 | 这是三遍读法在 Agent 场景最大的落地障碍：模型不知道何时该停，于是每篇都读三遍，又慢又空 |
| **sodalone/paper-reading-skill**（无 LICENSE） | **Claim 六列表**：作者主张 / 原文位置 / 实际证据 / 支撑强度 / 最大缺口 / 报告结论；以及不确定性固定措辞（论文未提及 / 原文证据不足 / 当前未检索到可靠文献 / 当前环境无法确认） | 强制走完六格，就不许从「作者说」直接跳到「所以成立」。四条固定措辞治的是模型爱用的「可能」「或许」 |
| **huangkiki/dailypaper-skills**（Apache-2.0） | **判决四档**：值得精读 / 值得借鉴但需补证 / 增量有限 / 暂不推荐；且判决放正文第一节，不是结尾附个优缺点 | 用户第一个问题其实是「这篇要不要读」，多数 skill 却先给一万字报告 |
| **MrGeDiao/paper-reading-zh**（MIT） | **批判四层**：①论文声明（作者自己说的）②证据支持（数据实际支撑到哪）③合理推断（我的领域推论）④不确定或未覆盖 | 每条批判必须标层，读者才知道这句话是谁说的。中文场景，最贴国内学生 |

### 2.2 另外三条也进正文

- **LuoHaomin/read-paper**（MIT）：**承重单元**——找出「一旦不成立整篇就塌」的那个结论/实验/证明，只精读承重单元，其余略读；缺证据处标 ⚠️ 待核，自己补的推理标【补推】。
- **Yuan1z0825/nature-skills**（Apache-2.0）：**出处三态**——能给页码 / 只能给章节结构 / 只有摘要元数据（此时禁止推断未见的证据）。治编造引用。
- **ProgramingGod-ykj/keshav-paper-reading-skill**（MIT）：**阅读契约三问**——目标（判断/学习/评审/复现）、预算（5 分钟 / 1 小时 / 深读）、产出（决策/笔记/批评/复现方案）；用户没说就「推断最轻的够用深度并声明」。

### 2.3 明确不要的

- 所有 `scripts/` 执行层（`run_pipeline.sh`、`fetch_sources.py`、`validate_report.py`）——依赖 shell + Python 环境，塞进插件是长期维护负担。**只借表单与措辞**。
- Zotero + Obsidian 落库、Git push、MinerU 解析、LaTeX 编译——都是某个人的知识库工作流，插件不该假定用户装了这些。
- `zsyggg/paper-craft-skills` 的 HTML 三风格 + 字数硬指标（3000/4000 字下限）——目标是公众号爆文，会把「判断值不值得读」推向注水。
- 官方 `anthropics/skills`（20 个 SKILL.md）**没有任何论文阅读 skill**，不作方法论来源。

### 2.4 我们要不一样的地方

1. **中文优先，面向大学生**：现有要么全英文正文，要么中文但面向研究者做组会汇报。大学生要的是「这篇要不要读 + 读完能讲出来」。
2. **单点决策优先**：第一问是「读不读」，一句话答完；深读是可选第二档，不是默认一万字报告。
3. **不绑定外部生态**：不假设 Zotero / Obsidian / MinerU / LaTeX / Git。
4. **不造脚本，只造纪律**：用状态机 + 措辞表 + 检查清单压幻觉，不写 Python 校验器。

## 三、名著 / 文学解析类：GitHub 上确实薄弱

搜过的关键词：`claude skills book`、`book-analysis skill`、`literature analysis skill`、`novel analysis skill`、`reading-coach filename:SKILL.md`。

命中情况：

- 525 个 `claude skills book` 结果，绝大多数是「把技术书 PDF 转成 skill」（`virgiliojr94/book-to-skill` 那类）、或电子书处理工具，**不是文学分析**。
- `reading-coach` 作为文件名有 26 个命中，多是个人 Obsidian 第二大脑模板里的陪读条目，方法深浅不一，没有形成可复用的流程。
- 没有任何仓库在做「结构 / 人物 / 叙述视角 / 语言 / 文学史位置」这套文学分析。

→ **结论**：`book-analysis` 的正文自己写。可借的只有两处形式：

1. `reading-coach` 已经在用的「一次一问、卡片落 Markdown」这个交互形态（本插件自带，保持一致的体感）；
2. 陪读卡片里的「五维」（一句话要点 / 因果链 / 解决方案 / 边界条件 / 原句）——文学解析可以改成「结构 / 人物 / 视角 / 语言 / 位置（在文学史里）」，但**必须挂原句**这一条照抄。

文学分析的方法论来源不是 GitHub，是我们自己已有的 skill 体系：

- `human-writing` 的立场部分（向下看、不美化权贵、情绪不当场结清）；
- `style-fiction-cn` / `style-essay-cn` 的作家文体库（判断「这一处用的是谁的笔法」时有据可依）；
- 用户级 `~/.dsh/AGENTS.md` 第 2 节的写作 Skill 路由。

## 四、落到两个新 skill 的骨架

### `paper-reading`（论文阅读）

```
0. 阅读契约：目标 / 预算 / 产出（用户没说就推断最轻的并声明）
1. 判决前置：四档判决 + 一句话理由（正文第一节，不许放结尾）
2. 类型分诊：理论证明 / 方法 / 系统·数据集 / 实证 / 综述 → 决定「证据载体」是什么
3. 按档读：
   - 外围：第一遍，只给定位句 + 5C
   - 相关工作：第一遍 + 第二遍，七问的 1·2·4 + 审图
   - 核心：三遍，七问全 + 复现记录
4. Claim 台账：六列表，每条 claim 走完六格
5. 缺口与边界：区分「证据不足以支持」与「已证明无效」
6. 出处纪律：能给页码给页码，不能就只给章节结构，只有摘要就明说
```

### `book-analysis`（名著解析）

```
0. 先问一句：要「这本书怎么写的」还是「这本书说了什么」（前者是分析，后者是摘要，摘要不做）
1. 结构：怎么分卷/分章，为什么这么分，哪一章是枢纽
2. 人物：谁在推动，谁的转变有代价，谁只是功能
3. 视角与叙述：谁在看，看得到什么，看不到什么
4. 语言：句长、用词、对话与叙述的比例——每一条都要挂原句
5. 位置：在文学史/作者自己的写作序列里处在哪
6. 落卡片：五维改成「结构 / 人物 / 视角 / 语言 / 位置」，每一维必须有一句原文
```
