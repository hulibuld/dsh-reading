# 12 · 找书与网络导入

> 状态：已实现（`0.5.1`）。和 [`docs/08`](08-格式支持-TXT与MOBI.md)、[`docs/11`](11-格式支持-PDF.md)
> 是同一个系列的第三篇：那两篇讲「拿到文件之后怎么读」，这篇讲「怎么拿到文件」——
> 一条直链，和一个你自己填的书源。**插件不内置任何站点。**

---

## 一、结论先说

| 入口 | 你要做什么 | 插件做什么 | 需要联网 |
|---|---|---|---|
| 从电脑选文件 | 点一下，选文件 | 读字节 → 判格式 → 入架 | 否 |
| 粘贴链接 | 粘一条 `http(s)://…` 的直链 | 下载 → 判格式 → 补扩展名 → 入架 | 是，只连那一个地址 |
| 找书（书源） | 自己填一个搜索地址模板，然后搜关键词 | 抓结果页 → 抽出候选链接 → 你点哪条就下载哪条 | 是，只连你填的那个站 |

三条边界先写在这里，免得误会：

1. **不内置任何书源。** 插件里没有任何站点地址，也不带「默认书源」。你填什么，
   它就抓什么；不填就搜不了，界面会直接告诉你「还没有配置书源」。
2. **只认直链。** 粘贴链接要求是**指向文件本身**的 `http(s)` 地址（下载会直接返回
   EPUB / PDF 等字节）。指向网页的地址能下载下来，但下来的是一个 HTML 页，
   会被当成 TXT 读进来——那不是一本能读的书。
3. **搜索结果是「抽链接」，不是「解析某站」。** 没有为任何站点写适配器，
   靠的是通用的页面 HTML 解析。站点改版、放反爬页、要求登录，都可能让结果变成空列表。

## 二、粘贴链接：从一条地址到一本书

操作就两步：书架右上角「导入图书」→ 面板里的「② 粘贴链接」→ 粘地址 → 「导入」。

宿主侧做的事，按顺序：

1. 检查是不是 `http://` / `https://`（其它协议一律拒绝，包括 `file://`）；
2. `fetch` 下载，超时 90 秒，跟随重定向；
3. 先看 `content-length`，超上限直接拒绝；读流时也边读边累计，**再超就当场停**；
4. 拿到字节后按**文件头魔数**判格式（和本地导入同一套 `lib/bookformat.js`）；
5. 文件名优先级：请求里带的 `filename` → `Content-Disposition`（含 `filename*=UTF-8''…`
   这种中文写法）→ URL 路径的最后一段 → `book`；
   没有扩展名就按嗅探结果补一个（`.epub` / `.mobi` / `.pdf` / `.txt`）；
6. 交给和本地导入**完全相同**的 `store.importBook()`：同一套解析、同一套去重、
   同一套书库布局。所以「网络导入的书」和「本地导入的书」在书架上一模一样。

返回值也和 `shelf.import` 一致（`{ bookHash, meta }`），客户端不需要分两套逻辑。

## 三、书源：为什么让你自己填

「书源」在这里的定义很窄：**一个搜索地址模板**。它只解决一件事——把关键词拼进
一个 URL，然后抓那个页面回来。它**不是**一个爬虫脚本，也没有「章节列表 / 正文 / 分页」
这类适配规则，所以它只能帮你找到「可以下载的文件直链」，不能替你读在线章节。

### 3.1 模板怎么写

模板就是一条普通网址，把关键词的位置写成 `{query}`：

```
https://某站/search?q={query}
```

规则只有三条：

| 要求 | 说明 |
|---|---|
| 必须以 `http://` 或 `https://` 开头 | 其它协议一律拒绝 |
| 必须含 `{query}` | 没有占位符的模板存不进去（严格模式直接报错） |
| 关键词会被整体编码 | 空格、`&`、`#` 都会转义，不会把地址拼歪 |

`{query}` 出现几次都行（有的站点在路径和参数里各要一次）；中文关键词交给
`encodeURIComponent` 处理，你按站点原本的写法填就行。

**请不要填需要登录才能看的站点**：插件不带任何 Cookie，抓到的只会是登录页。

### 3.2 抓回来之后，候选是怎么来的

抓到的页面只在内存里过一遍，**不落盘**。抽链接的判据很朴素：

- 只认 `<a href="…">文字</a>`；
- `javascript:` / `mailto:` / `tel:` / `data:` / 纯 `#` 锚点全部丢掉；
- 相对的 `href` 按**页面自己的地址**解析成绝对地址；
- 文字里的标签剥掉、HTML 实体解回来（`&amp;`、`&#39;`、`&#x4E2D;` 这类）、空白压成一个空格；
- 文字为空、或长于 120 字的丢掉（那多半是导航条和版权声明，不是书名）；
- 同一个地址只留第一条；
- 最多 60 条。

搜出来的是「候选」，不是「评分排序」：插件不知道哪条是你要的书，它只把页面上的
链接按出现顺序列出来，你点哪条的「下载并导入」，它就按「粘贴链接」那套流程下载那一条。

### 3.3 书源存在哪

存在书库根目录的 `settings.json` 里（字段 `bookSources`），和字号、主题这些阅读偏好
放在一起。最多 8 条，每条三个字段：`id`（内部标识，≤32 字）、`name`（显示名，≤40 字）、
`searchUrl`（就是上面那个模板）。

## 四、数据与隐私

- **请求从这台机器直接发出。** 没有中转服务器，插件作者那一侧什么也看不到：
  既没有账号，也没有遥测，也没有「书源市场」这类会替你上报地址的东西。
- **抓取的网页只在内存里过一遍**，不落盘、不建缓存；只有你点了「下载并导入」，
  文件才会进书库。
- **书库仍然只在你的磁盘上。** 网络导入只是一次性取字节，取完就和本地导入没有区别。
- **不内置、不推荐、不评价任何站点。** 你填的地址会原样出现在你的请求里，
  也会原样出现在你对那个站点的访问记录里——请只访问你有权访问的内容。

## 五、限制（都是刻意的）

| 限制 | 数值 | 为什么 |
|---|---|---|
| 单个文件上限 | 200 MB（`maxImportBytes`，可在配置里改） | 再大就不是「一本书」了，而且浏览器半要把它 base64 一趟 |
| 下载超时 | 90 秒 | 慢站会卡住整个导入；宁可失败得快 |
| 搜索页读取上限 | 2 MB | 结果页只需要 HTML 骨架；再往后读是在下载图片和广告 |
| 搜索超时 | 20 秒 | 搜索是交互动作，用户不会等 |
| 候选条数 | 60 条 | 再多也翻不完，而且全给前端只会更慢 |
| 书源条数 | 8 条 | 够用，又能挡住把 settings.json 写成通讯录 |
| 协议 | 只支持 `http` / `https` | 不让插件去读本机文件、也不走其它协议 |
| 页面编码 | 按 UTF-8 解 | 非 UTF-8 的老站，候选文字可能乱码（链接本身仍可用） |

搜索结果的解析**靠的是页面 HTML 的形态**，不是站点 API。所以：

- 站点改版把链接换成 JS 渲染 → 抽不到链接（结果为空）；
- 站点要求登录 / 有反爬页 → 抓回来的是登录页或验证页（结果为空）；
- 站点把下载链接放在 `onclick` 里而不是 `href` 里 → 抽不到。

这些都是「机制本身的边界」，不是 bug；报错文案会尽量说清是哪一步没成。

## 六、失败怎么排查

先看界面上的中文提示（它们对应固定错误码，见 `client/src/api.js` 与 `client/src/shelf.js`）：

| 提示 | 错误码 | 多半是什么 | 怎么办 |
|---|---|---|---|
| 这个链接打不开，请检查它是否以 http:// 或 https:// 开头 | `E_IMPORT_URL_BAD` | 少了协议头，或者复制到了 `file://` / `ftp://` | 补上 `https://`；确认是网页地址还是文件直链 |
| 下载失败了，可能是网络不通或对方站点拒绝了访问 | `E_IMPORT_DOWNLOAD` | 断网、DNS 不通、站点 403/404、需要 Referer | 浏览器里打开同一地址试一次；能下就重试，不能下就换个来源 |
| 下载回来的文件是空的 | `E_IMPORT_EMPTY` | 地址指向的是一个跳转页或空响应 | 换成真正的文件直链 |
| 这本书文件太大了，暂时导入不了 | `E_IMPORT_TOO_BIG` | 超过 `maxImportBytes` | 换小一点的版本；或调大配置里的上限再重启 DSH |
| 还没有配置书源：先在找书面板里填一个搜索地址模板 | `E_SOURCE_NONE` | 书源列表是空的，或 `sourceId` 对应不上 | 在面板底下填模板 + 名称保存 |
| 这个书源的搜索地址写得不对 | `E_SOURCE_BAD` | 模板缺 `{query}`、协议不对，或 `https://` 后面什么都没有 | 按第三节的三条规则改一遍 |
| 连不上这个书源，可能是网络问题或地址写错了 | `E_SOURCE_FETCH` | 站点不通、返回非 2xx、需要登录 | 浏览器里手动打开拼好的地址确认一次 |
| 先输入要搜的书名或作者 | `E_SOURCE_QUERY` | 关键词是空的 | 填个关键词 |

界面上的「搜索没有结果」还有一层可能：链接抽出来了但被过滤光了（文字太长、
`href` 是 `javascript:`）。这时在浏览器里打开同一个搜索页，随手「查看源代码」看看
书名是不是包在 `<a href>` 里——如果是 JS 渲染出来的，这个机制就抓不到。

## 七、想看代码的话

| 文件 | 管什么 |
|---|---|
| `lib/sources.js` | 纯函数：模板拼接、候选抽取、文件名猜测。不联网，可单测 |
| `lib/routes.js` | `shelf.importUrl`（下载入架）与 `source.search`（抓结果页），含超时与体积上限 |
| `lib/store.js` | `bookSources` 的默认值、校验（`normalizeBookSources`）与合并写入 |
| `client/src/api.js` | `importUrl()` / `searchSource()` 与错误码文案表 |
| `client/src/shelf.js` | 「导入」面板：三段并列 + 书源表单 |
| `test/source_test.mjs` | 纯函数层单测（模板 / 抽取 / 文件名） |
| `test/e2e_local_test.mjs` | 起一个本地 http 服务器跑完整链路：导入、搜索、体积超限、坏模板 |

零依赖、零内置地址；想扩展「多书源切换」，只需要在 `bookSources` 里多存几条，
`source.search` 已经支持按 `sourceId` 选其中一条。
