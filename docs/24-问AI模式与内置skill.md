# 问 AI 的五个模式，与随插件带的四个阅读 skill

## 结论先说

0.11.0 起，插件自带两样东西，装好就有，不用另配、不用另装：

- **问 AI 有五个模式**。圈住一段原文点「问 AI」，面板头部多一个下拉框，选「名著精读」「论文分析」这些，同样一段文字、同一个问题，回答的角度和篇幅就不一样。
- **多四个 skill**，加上原有的陪读教练一共五个。聊天里说「分析这本书」「读这篇论文」「做综述」「把读书笔记改成文章」，对应的流程就会被载入。

两样都随包走：`npm pack` 出来的 tarball、GitHub clone 下来的目录里，`skills/` 与 `lib/askpresets.js` 都在。

## 一、问 AI 的五个模式

模式是插件自己的概念，不是宿主的 agent preset。一个模式就是**一段人设 + 一组回答要求**，只在「圈一段原文问 AI」这条链路上生效，跟你主会话的模型、人设、skill 都无关。

| 下拉里的名字 | id | 给谁用 | 上限 |
| --- | --- | --- | --- |
| 一般问答 | `general` | 默认，什么书都行 | 200 字 |
| 名著精读 | `classic` | 读文学名著 | 300 字 |
| 论文分析 | `paper` | 读论文 | 400 字 |
| 概念溯源 | `concept` | 碰到术语、典故 | 300 字 |
| 外文原著 | `foreign` | 读英／日／法等原著 | 350 字 |

### 它们各管什么

**一般问答**是老的「问 AI」，一个字没改。不选模式、老书签老记录、更早版本发来的请求，全都落到它，拼出来的 prompt 与 0.10.3 逐字相同。这条是刻意留的锚点：升级不该让老行为变样。

**名著精读**把人设换成「读过很多文学名著的读者」，要求模型把这句话放回整本书里看位置、写法、语气、时代语境。允许引原文关键词、允许点笔法（叙述视角、语气、节奏、意象），但禁止**剧透**——不预告结局、不点破人物命运、不暗示后文转折。这一条比一般问答的「不要剧透」更硬，因为读名著时被剧透的代价更大。

**论文分析**把人设换成「这本期刊的审稿人」，要求把回答拆成四类：作者声称了什么、证据支持了什么、我的推断是什么、论文没有覆盖什么。还要求指出关键证据是哪一句、支撑强度是相关还是因果还是个例。最要紧的一条：**不许把摘要复述当成结论**——这是论文问答里最常见的偷懒。

**概念溯源**处理的是「这个词到底什么意思」。它要求先给通行含义与来路（学科、年代、谁先这么用），再给这本书里的具体用法，并且**严格区分两者**，不一致时明确指出来。不许编书名、编人名。

**外文原著**要求关键句先给原文、再给一种贴切的中文译法（一种就够，不列一堆），术语与专名给中英对照。译不准就说「不确定」，不硬译。

### 怎么用

1. 打开一本书，在正文里圈住一段话；
2. 弹出的小菜单里点「问 AI」；
3. 面板头部、「问 AI」标题右边，有一个下拉框，选你要的模式；
4. 写问题，回车。

选过的模式记在书库的 `settings.json` 里（键名 `aiAskPreset`），下次打开还是它。

模式只影响**这一次提问**。切换模式不会清掉你正在打的问题，也不会清掉这一轮已经问过的回答。

### 怎么知道这次用的是哪个模式

两处能看到：

- 问答记录（`books/<bookHash>/qa.jsonl`）里每条记录带 `mode` 字段；
- AI 调用账本（`~/.dsh-reading/dsh-reading/ai-calls.jsonl`）每行带 `mode` 字段。

排查「为什么这次回答怪怪的」时，先看账本里那一行的 `mode` 是不是你想要的。

### 加一个模式要改哪

`lib/askpresets.js` 一个文件。数组 `ASK_PRESETS` 里加一条，六个字段：`id`（请求里传的值，也是 settings 里记的值）、`name`（下拉里显示的字）、`description`（悬停提示）、`persona`（进子代理系统提示）、`requirements`（进用户消息末尾的「回答要求」，不带编号）、`maxChars`（篇幅上限，供后端与测试用；前端只读 `name` 与 `description`）。

**顺序即下拉顺序**，第一项是默认。加完不用改前端——前端是从宿主拉的列表（路由 `ask.presets`），不硬编中文名。改完记得 `node test/run.mjs` 与 `node client/build.mjs`。

### 为什么人设与回答要求分两处放

`persona` 进子代理的**系统提示**，管「你是谁、用什么眼光看这段话」；`requirements` 进**用户消息**末尾的「回答要求」，管「这次输出成什么样」。两处内容不重复——重复了模型会收到两遍同样的指令，反而更容易跑偏。

宿主这边用的是 `SubagentStartRequest.persona`，落点是子代理系统提示里的 `deployment:persona-prefix` 段。它只在这个子代理的作用域里可见，**不会污染你主会话的人设**。

## 二、随插件带的五个 skill

| skill | 干什么 | 触发话术 |
| --- | --- | --- |
| `reading-coach` | 陪读教练：一次问一个，问完给卡片（0.9.6 起就有） | 陪读 / 阅读教练 / 带我读这本书 / 别替我总结，问我 |
| `book-analysis` | 名著解析：先判读不读，再按五维逐条解析 | 分析这本书 / 拆一下这本名著 / 这本书好在哪 |
| `paper-reading` | 论文阅读：先判读不读，再定读多深，主张挂证据 | 读这篇论文 / 这篇值不值得读 / 帮我拆这篇 paper |
| `literature-review` | 文献综述：按概念分组、找缺口、出草稿 | 做综述 / 这几篇放一起比 / 这个领域到哪一步了 |
| `notes-to-article` | 读书笔记转文章 | 把读书笔记改成文章 / 这个能写成什么 |

### book-analysis：名著解析

先给一份**不超过四百字的判读报告**并停下来等确认，再往下走。判读报告里要说清：这本书归哪一类、一句话主旨、核心问题两三条、四维判断（密度／新颖性／可批判性／挑战度）、以及**明确建议读不读**（分四档：值得精读／读关键章节／不值得精读／有空再说）。

这一步是刻意的门禁。多数时候人只想要一个「值不值得花时间」的判断，模型却直接开始长篇分析——那个判断就淹没在两万字里了。

确认之后按五个维度解析：结构、人物、视角、语言、文学史位置。每一维的判断都要挂原句，找不到合适的句子就写「这一节没有可直接引用的原句」。**不做摘要，不写读后感**——摘要网上到处都有，读后感是另一回事。

### paper-reading：论文阅读

三个问题，有先后，顺序不能倒：

1. **这篇要不要读**——一句话给四档判决（值得精读／值得借鉴但需补证／增量有限／暂不推荐）。判决放在正文第一节，不是结尾。用户没耐心翻到最后找结论。
2. **要读的话读哪几段**——按「外围／相关工作／核心」三档分，不同档位停在不同深度。这一条解决的是「模型不知道何时该停，于是每篇都读三遍」。
3. **读出来的结论靠不靠得住**——每条主张挂出处（哪一节哪一句）、证据强度（相关／因果／个例），写成一张六列的 Claim 台账。

不确定时的措辞固定四选一：论文未提及／原文证据不足／当前未检索到可靠文献／当前环境无法确认。**不许用「可能」「或许」糊过去**。

### literature-review：文献综述

按**概念**分组，不按作者分组——按作者排出来的必然是流水账。然后找缺口，缺口要点名是「谁与谁之间」空着，不是笼统说「研究不足」。最后才写草稿，顺序不能倒。

真矛盾和口径差异要分开：两篇结论不同，可能是真打架，也可能只是变量定义、样本、时间窗口不一样。这个 skill 要求先分清，再说谁对。

### notes-to-article：读书笔记转文章

先从笔记里找出一处**能立住的判断**。找不到就直说立不住、并指出缺什么，不硬凑一篇文章。

找着了按五段成文：入口、判断、证据、反面、落点。接公众号、知乎、头条都能用。引文有纪律：只引你真抄下来的句子，转述就写转述。

### 它们在哪、怎么改

```
dsh-Reading/skills/
├── reading-coach/
│   ├── SKILL.md
│   └── references/{question-design,card-template}.md
├── book-analysis/
│   ├── SKILL.md
│   └── references/{verdict-report,five-dimensions}.md
├── paper-reading/
│   ├── SKILL.md
│   └── references/{claim-ledger,critical-layers}.md
├── literature-review/
│   ├── SKILL.md
│   └── references/{concept-matrix,comparison-rules}.md
└── notes-to-article/
    ├── SKILL.md
    └── references/{structure-template,quotation}.md
```

注册逻辑在 `lib/skillbundle.js`：扫 `skills/` 下所有含 `SKILL.md` 的子目录，按目录名排序，逐个注册进宿主的 skill 服务。**加一个 skill 就是加一个目录**，不用改代码。

### frontmatter 只认两行

`SKILL.md` 开头必须是：

```
---
name: book-analysis
description: 一句话说清什么时候用它。
---
```

`name` 要和目录同名，`description` **不能换行**。解析器只支持一行一个 `key: value` 这个子集，多写字段会被忽略，description 写成分行会直接注册失败。

description 是最要紧的一行——模型是靠它决定要不要载入这个 skill 的。写「是什么」没用，要写「用户说什么话的时候用它」。

## 三、为什么不做成宿主的 agent preset

宿主有 `agentPresets` 服务，插件完全可以注册一个真正的 agent preset 进去。不做的理由：

1. **agent preset 是给整段对话换装配的**，会换掉工具集、系统提示、compaction 策略。问 AI 要的只是「这一次回答换个眼光」，用不上整段装配。
2. **agent preset 是全局可见的**。装了这个插件，用户的预设列表里就多出几条，跟他的写作预设、代码预设混在一起——那是在别人的列表里塞东西。
3. **persona 够用且更轻**。`SubagentStartRequest.persona` 是个纯字符串，落在子代理系统提示的一段 prefix 里，作用域干净，不影响主会话。

一句话：问 AI 的模式是插件自己的功能，不是宿主的配置。

## 四、兼容性

- 不带 `mode` 的请求（老前端、老书签、直接打接口）一律落到 `general`，prompt 与 0.10.3 逐字相同。
- `settings.json` 里没有 `aiAskPreset` 键时读作空串，等同 `general`，不报错。
- 未知的 `mode` 值（手改、拼错）退回 `general`，**不让一次手滑的提问失败**。
- QA 记录的结构没动（`anchorCfiRange`/`cutoffCfi`/`question`/`answer` 仍是必填，`mode` 是附加字段），老的 `qa.jsonl` 照常能读。
- `lib/coachskill.js` 的导出没动，单个 skill 的加载函数还在，老测试照常过。
