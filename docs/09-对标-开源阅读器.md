## 2. 问题①：书内目录页链接怎么跳

### 2.1 我们现在的真实状态（重要，跟直觉不一样）

`lib/routes.js` 的 `rewriteChapterAssets()` 对**所有 `<a>`/`<area>` 的 `href`** 做了特殊处理（`lib/routes.js:217-224`）：

```js
// 书内链接（脚注、章间跳转）不能改成 /asset：点了会让 iframe 去加载一份
// 裸 XHTML/CSS 字节，阅读界面当场变成一堆标签。改成「不导航的锚」并把原地址
// 编进 fragment，既不丢信息也不许 iframe 跳出当前文档。
if (isAnchor && localName === 'href') {
  if (value === '' || value.startsWith('#')) return whole
  return `${space}${attrName}${eq}${quote}#dsh-reading:${encodeURIComponent(value)}${quote}`
}
```

于是：

- `chapter2.xhtml#sec1` → 属性变成 `#dsh-reading:chapter2.xhtml%23sec1`；
- `https://example.com` → 同样变成 `#dsh-reading:https%3A%2F%2Fexample.com`（**外链也被包了**）；
- `mailto:a@b.com` → 同样被包；
- 纯 `#fn1` → 不动，保持 `#fn1`。

而 `client/src/reader.js` 全文**没有任何 click / 链接监听**（已 grep 确认）。所以今天点书内链接的结果是：iframe 的 URL 多一个 `#dsh-reading:...`，页面纹丝不动。**不是"跳错章"，是"没反应"。**

这意味着改造面很干净：服务端已经把「原地址」完整保留在 fragment 里，客户端只需要解码 + 分流，不用重新解析 HTML、不用改路由。

### 2.2 四个项目分别怎么做

**foliate-js（MIT，可照抄骨架）** `view.js`：

```js
doc.addEventListener('click', e => {
  const a = e.target.closest('a[href]')
  if (!a) return
  e.preventDefault()
  const href_ = a.getAttribute('href')
  const href = section?.resolveHref?.(href_) ?? href_
  if (book?.isExternal?.(href))
    Promise.resolve(this.#emit('external-link', { a, href_ }, true))
      .then(x => x ? globalThis.open(href_, '_blank') : null)
  else Promise.resolve(this.#emit('link', { a, href }, true))
      .then(x => x ? this.goTo(href) : null)
})
```

四个关键决定：

1. **事件委托在 `document` 上**，不是给每个 `<a>` 挂 onclick —— 后插入的节点（脚注弹层、异步注释）也能接管；
2. **先 `preventDefault()` 再问任何人** —— 宿主不处理也绝不会让 iframe 自己导航；
3. **先 `section.resolveHref(href_)` 把相对路径按当前章解析成 OPF 内路径**，再判外链 —— 顺序反了，`#fn1` 会被当成"无 scheme"，`mailto:` 会被当成"章节"；
4. 内部统一 `goTo(href)`，`goTo` 里 `book.resolveHref` 拆成 `{index, anchor}` 交给渲染器 —— **换章和滚锚点是同一条代码路径**，同章锚点只是 `index` 相同。

**epub.js（BSD-3，可照抄算法）** `src/utils/replacements.js` 的 `replaceLinks` 跟 foliate 相反，有三个坑别学：

```js
const links = contents.querySelectorAll('a[href]')   // 一次性快照，后插入的链接不接管
if (href.indexOf("mailto:") === 0) return           // mailto 完全不动，交给浏览器
const absolute = href.indexOf("://") > -1
if (absolute) { link.setAttribute("target", "_blank"); return }  // 外链只加 target
const linkUrl = new Url(href, location)
link.onclick = () => { fn(linkUrl.Path.path + linkUrl.hash); return false }
```

- 快照法：我们的章节是整章注入后不再插链接，暂时没事；但以后加脚注浮层就会踩坑 → **用委托**；
- `mailto:` 放过：在 sandbox iframe 里点了会变成「帧内导航到 mailto」，Chrome 多数时候静默失败 → **我们要拦**；
- 外链只加 `target=_blank`：iframe 没开 `allow-popups`，点了也开不出来 → **必须父页面 `window.open`**。

但 epub.js 有两个细节值得抄：

```js
// 相对路径解析：假 base + 去掉假 origin，顺带丢掉 query（书里链接带 ?x=1 无意义）
resolveURL(url, relativeTo)  // new URL(url, 'https://invalid.invalid/' + relativeTo)

// 锚点查找：id 找不到就退回 <a name="...">（老 EPUB2 大量使用）
doc.getElementById(id) ?? doc.querySelector(`[name="${CSS.escape(id)}"]`)
```

**readest（AGPL）**：`apps/readest-app/package.json` 里是 `"foliate-js": "workspace:*"`，即直接复用上面那套 `#handleLinks`，自己只写业务回调。**它没有另写一套拦截逻辑**——这本身就是结论：这件事的标准答案只有一套，别自创。

**koodo-reader**：v2.4.7 `package.json` 依赖里没有 `epubjs`（有 jszip / mammoth / rangy / better-sqlite3）。所以网上"koodo 用 epub.js 的 linkClicked"的说法对当前版本不成立，**不作为照抄来源**。

### 2.3 可照抄的判定顺序（伪代码，直接照着写）

```
onClick(e):
  a = e.target.closest('a[href]'); if (!a) return
  e.preventDefault()                       // 永远先拦

  raw = a.getAttribute('href')             // 用 attribute，不用 a.href（a.href 已被浏览器绝对化）
  if raw startsWith '#dsh-reading:' :
      href = decodeURIComponent(raw.slice('#dsh-reading:'.length))   // 服务端编进去的原地址
  else if raw startsWith '#' :
      href = raw                           // 纯 fragment，服务端没动
  else :
      href = raw                           // 理论上不会走到（服务端全包了），兜底

  // ① 协议分流：有 scheme 的一律不是章节
  if /^[A-Za-z][A-Za-z0-9+.-]*:/ .test(href):
      if startsWith('mailto:') or startsWith('tel:'):
          host.copy(href.replace(/^mailto:/,''))   // 比 window.open(mailto) 稳，用户能粘贴
          return
      if startsWith('http:') or startsWith('https:'):
          opened = window.open(href, '_blank', 'noopener')
          if (!opened) host.toast('浏览器拦了新窗口，链接已复制')  // 兜底
          return
      return                                // data: / javascript: / file: 一律忽略

  // ② 拆 path / hash
  [pathPart, hash] = splitFirst(href, '#')
  hash = hash ? decodeURIComponent(hash) : ''

  // ③ 同文件纯 fragment：不换章
  if pathPart === '' :
      jumpToAnchor(hash); return

  // ④ 相对路径按「当前章」解析（不是按 iframe 的 document URL）
  resolved = resolveAgainst(chapterHref, pathPart)
      // new URL(pathPart, 'https://x.invalid/' + chapterHref).pathname.slice(1)
      // decodeURI(...)，丢掉 query
  if (resolved === null) return            // 越出 OPF 根

  // ⑤ 查 spine（href 是相对 OPF 根的路径）
  index = spine.findIndex(s => normalize(s.href) === normalize(resolved))
      // normalize: decodeURI + 去掉 './' + 折叠 '//'；找不到再试 basename 匹配
  if (index < 0) { warn('书里有个链接指向不存在的章节', resolved); return }

  // ⑥ 同章 + 锚点：只滚不换章
  if index === chapterIndex && hash : jumpToAnchor(hash); return

  // ⑦ 换章（+ 锚点）
  goChapter(index, hash ? { anchor: hash } : { page: 0 })
```

判定顺序一句话总结：**先拦 → 解包 → 协议分流 → 拆 hash → 同文件锚点 → 相对路径按当前章解析 → 查 spine → 同章只滚 / 跨章换章带锚点**。foliate 的 `isExternal` 正则 `/^(?!blob)\w+:/i` 就是第 ① 步的判据；epub.js 的 `getElementById ?? [name=]` 是锚点查找的兜底。

### 2.4 我们的分页模型：锚点要换算成页号（不能照抄 scrollToAnchor）

foliate 的渲染器是滚动/分栏文档，锚点直接 `scrollIntoView`。我们是「CSS 多栏 + `body.style.transform = translateX(-page*(列宽+gap))`」，`scrollIntoView` 会把 iframe 视口滚走，跟 `pageRef` 计数当场错位。

正确做法（`reader.js` 里 `paginate()` 之后执行）：

```js
function pageOfAnchor(doc, id) {
  const el = doc.getElementById(id) || doc.querySelector(`[name="${CSS.escape(id)}"]`)
  if (!el) return null
  const bodyBox = doc.body.getBoundingClientRect()
  const box = el.getBoundingClientRect()
  // body 被 translateX(-page*(w+gap))，所以 (box.left - bodyBox.left) 已经把当前页偏移抵消，
  // 得到的是元素在「整章内容坐标」里的 x。
  const x = box.left - bodyBox.left
  const stride = geometry.columnWidth + geometry.gap
  return Math.max(0, Math.min(pageCount - 1, Math.floor((x + 1) / stride)))
}
```

时序：

1. `goChapter(index, {anchor})` → 设置 `src` → iframe `load`；
2. `handleLoad` 里先 `paginate(...)`（列数、页数定了才有 `stride` / `pageCount`）；
3. `await doc.fonts?.ready`，再算 `pageOfAnchor` —— 字体没加载完时行高变化会让页号整体漂移；
4. `applyPage(page)`；
5. 锚点找不到（`id` 拼错、`epub:type` 目标被删）：**停在第 0 页 + console.warn，不弹窗**。书是别人做的，链接坏了不是用户的错。

补充两条只有做过才知道的坑：

- **图片没加载完时算出的页号会偏**。`load` 事件只保证 DOM+同步资源，懒加载图会继续撑高。稳妥做法是 `load` 后算一次、`requestAnimationFrame` 再算一次（或 `img.decode()` 全 settle 后重算）；
- **跨章锚点不要用 `history`**：iframe 的 hash 变化会污染 `src` 比较逻辑（我们靠 `currentHref` 判章），一律 `preventDefault` 后走内存状态。

### 2.5 目录（toc）也要吃 fragment

`client/src/toc.js:124` 已经把两个参数都传出来了（`props.onJump(item.spineIndex, item.href)`），但 `client/src/app.js:582-585` 的接线把第二个参数丢了：

```js
onJump: (index) => {
  const api = apiRef.current
  if (api) api.jumpToSpine(index)
},
```

而 `client/src/reader.js:547` 的 `jumpToSpine(index)` 也只接 index。既然 `goChapter` 要支持 `{anchor}`，三处一起改：

```js
// reader.js
const jumpToSpine = useCallback((index, anchor) => {
  if (!Number.isInteger(index) || index < 0 || index >= spineCount) return
  if (index === chapterRef.current) { jumpToAnchor(anchor); return }   // 同章：只滚不换
  goChapter(index, anchor ? { anchor } : { page: 0 })

// app.js
onJump: (index, href) => api.jumpToSpine(index, fragmentOf(href))
```

一份代码同时修好「目录条目指向章内小节」和「正文链接跳章」。注意 `goChapter(index, {page:0})` 是现有签名（`reader.js:548`），加 `anchor` 只是多一个可选键，不破坏旧调用。

## 3. 问题②：封面排版与长书名/长作者

### 3.1 现状（`client/src/style.js`）

```css
.dr-grid { display:grid; grid-template-columns:repeat(auto-fill,minmax(148px,1fr));
           align-items:start; gap:14px; }
.dr-cover { position:relative; width:100%; aspect-ratio:2/3; overflow:hidden; }
.dr-cover img { position:absolute; inset:0; width:100%; height:100%; object-fit:cover; display:block; }
.dr-book-title { -webkit-line-clamp:2; ... }             /* 无 min-width、无 overflow-wrap */
.dr-book-meta  { font-size:11px; ... }                   /* JSX 里配 .dr-ellipsis 单行省略 */
```

方向是对的（`aspect-ratio` 而不是固定高、`img` 绝对定位 + `object-fit:cover`、`align-items:start`），**缺的是「不许被内容撑宽」这一条**。

### 3.2 头号根因：grid 子项 `min-width:auto`

CSS Grid 的轨道 `minmax(148px, 1fr)` 里，`1fr` 的**最小值受子项自动最小尺寸约束**。`.dr-book` 是 `<button>`，默认 `min-width:auto`，它的 min-content 宽度由最长不可断词决定（长英文书名、带连字符的系列名、`letter-spacing`+`text-wrap:balance` 都会放大）。一旦某本书的 min-content > 均分宽度，**那一列就被撑宽，同排封面立刻不等宽**——这正是「封面尺寸错乱」最常见的形态，而且只在特定书名下复现，所以看起来像玄学。

一行修：

```css
.dr-book { min-width: 0; }
.dr-book-title, .dr-book-meta { min-width: 0; overflow-wrap: anywhere; }
```

`overflow-wrap:anywhere` 比 `word-break:break-word` 更合适：后者对 CJK 无影响、对长英文串的断点也更晚；`anywhere` 还会把 min-content 一起降下来（`break-word` 不会），所以它是「防撑宽」的正解。

### 3.3 次因：`1fr` 在宽屏把封面拉到过大

书架只有 3 本书、窗口 1600px 时，`auto-fill` 会生成 9 个空轨道，每本仍占 `1fr` ≈ 170px，不算离谱；但容器再宽就到 220px+，卡片高度随之暴涨，一排三本像海报。**注意：不要为了「填满」改成 `auto-fit`** —— `auto-fit` 会折叠空轨道，3 本书直接把封面拉到 500px 宽，那才是真的「尺寸错乱」。`auto-fill` 必须保留。

要限宽就限轨道上限，并让整行居中：

```css
.dr-grid {
  grid-template-columns: repeat(auto-fill, minmax(148px, 190px));
  justify-content: center;     /* 行内居中，右侧不再留一大条空白 */
}
```

### 3.4 长书名 / 长作者的收法（三处，别只收一处）

| 位置 | 现状 | 建议 |
|---|---|---|
| 卡片书名 `.dr-book-title` | 2 行 clamp | 保留 clamp；加 `overflow-wrap:anywhere`；再加 `min-height: calc(2 * 1.35em)`，这样 1 行书名的卡片和 2 行的**底边对齐**，不会出现「这排卡片高矮不齐」 |
| 卡片作者 `.dr-book-meta.dr-ellipsis` | 单行 ellipsis | 已够；补 `min-width:0`（flex/grid 子项不加就不生效） |
| 纸封面书名 `.dr-cover-text` | 4 行 clamp + 自适应字号 | 已够；`word-break:break-word` 建议换 `overflow-wrap:anywhere`，长英文单词不会顶破封面 |
| 纸封面作者 `.dr-cover-author` | 单行 ellipsis | 已够 |

另外：卡片 `<button title="书名 · 作者">` 已有原生 tooltip（`client/src/shelf.js:117`），省略号截断后仍可读全名，**不需要**再做「点一下展开」。

### 3.5 「封面堆叠」的排查顺序

如果用户说的是两张封面叠在一起 / 封面压住文字，按这个顺序查（不是 CSS 玄学）：

1. `img` 与 `.dr-cover-fallback` 是否可能**同时**存在？现在 JSX 是二选一，安全；但如果以后加「加载中骨架」，务必让三者共用 `position:absolute; inset:0` 的一层，别各自 `relative`；
2. `.dr-cover` 是否被同时设了 `height` 和 `aspect-ratio`？两者冲突时 `height` 赢，`img` 的 `height:100%` 就会溢出到下方文字上——目前没有 `height`，保持住；
3. 同排卡片高度差是否来自 `min-width:auto` 撑宽（3.2）而不是高度？先修宽度，再看高度。

`client/src/shelf.js:325` 的 `key: book.bookHash` 是对的（不是 index），不会因为重排导致同一本书渲染两份——这条排除掉。

## 4. 问题③：元数据编辑（改名 / 改作者 / 换封面）

### 4.1 同类项目的交互形态

- **readest**：书卡右键菜单只有 `Show Book Details`（只读详情），**没有**改书名/作者/换封面（`BookshelfItem.tsx` 的 `itemOptions` 全部条目已核对）。也就是说 25k star 的项目也没做这件事——不是它做不到，是「改元数据」不属于高频路径。
- **Calibre 式**：独立「编辑元数据」对话框，左表单右封面拖放区，保存后写回 `metadata.opf` 并重建封面缩略图。它是桌面书库管理器，交互重量级。
- **KOReader 式**：书内菜单 → 书籍信息 → 可编辑，写 sidecar（`.sdr/metadata.epub.lua`），不动原书。

**结论：交互放「详情弹窗里的编辑态」，不要放书架卡片上。** 卡片单击是「打开书」，编辑是低频破坏性操作，必须两步（长按/右键/详情 → 编辑），否则误触改名的投诉会比功能本身多。

### 4.2 落盘：改 `meta.json`，不要碰原书

我们已经有现成的书目录结构（`lib/store.js:11-16`）：

```
<bookHash>/
  ├── meta.json          ← 书名/作者/coverHref 都在这
  ├── book.epub          ← 原书，一个字节都别动
  ├── cover.jpg          ← 抽出来的封面（可覆盖）
  ├── progress.json
  └── qa.jsonl
```

改原书（重写 EPUB 的 OPF）是**负收益**：要重新解析、可能破坏签名、用户换设备后不一致、出错就毁书。改 `meta.json` 是正解，Calibre/KOReader 也是「元数据与书分离」的思路。

新增一个 POST 方法即可（`lib/routes.js` 的方法表是 `POST /api/dsh-reading/<method>`，加一行就注册）：

```js
'book.update': async (body) => store.updateMeta(requireBook(body?.bookHash), {
  title: body?.title, author: body?.author,
  coverBase64: body?.coverBase64, coverMediaType: body?.coverMediaType,
}),
```

`store.updateMeta` 的要点：

- `title`/`author` 做 `trim()` + 长度上限（书名 200、作者 120），空书名**拒绝**（书架靠 title 判有效性，`lib/store.js:237` 空 title 会被跳过）；
- 只允许白名单字段，别把整个 body 合并进 meta（`bookHash`、`sourceFormat` 被改会出诡异 bug）；
- 写 `meta.json` 用现成的 `writeFileAtomic`（已有，`lib/store.js:195`）；
- 更新 `meta.updatedAt = new Date().toISOString()` —— 书架排序靠它（`listShelf` 末尾按 `updatedAt` 倒序），不更新的话改完名字书还沉在下面，用户以为没保存；
- 封面：`coverBase64` 解码后写 `cover.<ext>`（按 mediaType 选 jpg/png/webp），并 `meta.coverHref = 'cover.jpg'`。**覆盖同名文件**，不要留 `cover-1.jpg` 这种垃圾；
- 返回 `{ meta }`，让前端用返回值刷新，不要自己拼。

### 4.3 缓存失效（这里有个真 bug）

`serveCover()`（`lib/routes.js:524-538`）返回 `cache-control: private, max-age=3600`，而 `client/src/api.js:167` 的 `coverUrl()` 只有 `?book=<hash>`。**换完封面，浏览器最长 1 小时还显示旧图**，用户会反复点保存。

两种修法，选一种：

```js
// A. 版本参数（推荐：不动缓存语义，一行）
export function coverUrl(bookHash, version) {
  const q = `${API_BASE}/cover?book=${encodeURIComponent(bookHash)}`
  return version ? `${q}&v=${encodeURIComponent(version)}` : q
}
// 调用处：coverUrl(book.bookHash, book.updatedAt)
```

```js
// B. 封面响应改 no-cache（简单粗暴，每本书每次进书架都回源）
'cache-control': 'private, no-cache'
```

推荐 A：`shelf.list` 已经返回 `updatedAt`（`lib/store.js:262`），前端不用改数据流。注意**本地 state 也要换 key**：`img` 的 `src` 变了 React 才会重新请求；如果 `src` 没变只是文件变了，浏览器命中 304/内存缓存，照样旧图。

### 4.4 前端表单的最小可用形态

- 入口：卡片长按 500ms（移动）/ 右键（桌面）/ 详情弹窗里的「编辑」按钮；
- 字段：书名（input，必填）、作者（input，可空）、封面（file input，`accept="image/*"`）；
- 封面先在 canvas 压到宽 600、`image/jpeg` 0.85，再 base64 上传——手机拍的 4MB 图直接塞进 JSON 会把请求撑爆；限制 2MB；
- 保存中禁用按钮 + 「保存中…」；成功后关弹窗、就地替换列表里那条记录（乐观更新，失败回滚 + 中文 toast）；
- 表单里显示 `coverUrl(hash, updatedAt)` 的预览，改完立刻能看到新图（这也是缓存参数的第一次验证）。

## 5. 问题④：划词问答的「历史 + 点回原文」

### 5.1 好消息：后端已经完整了

- `lib/routes.js:409`：`'qa.list': async (body) => store.listQa(requireBook(body?.bookHash))`
- `lib/store.js:502`：`listQa` 合并读 `qa.jsonl`
- 每条记录字段（`client/src/contract.js` + `lib/ask.js`）：`anchorCfiRange`（必填）、`anchorAnnotationId`、`question`、`answer`、`cutoffCfi`、`contextExcerpt`、`contextCfiRange`、`model`、`threadId`、`parentId`

而 `client/src/` 里**没有任何地方调用 `qa.list`**（grep 确认）。所以这不是「要设计一个功能」，是「后端好了，UI 没接」。

### 5.2 同类项目的范式

- **foliate-js / KOReader 的批注侧栏**是通用范式：按书聚合、按位置排序、每条显示「摘录 + 备注 + 时间」，点一条 `view.goTo(cfi)` 跳回去并高亮。
- **readest** 的 AI 面板走的是对话线程（`@assistant-ui/react` + `ai` SDK，见 `package.json`），消息按 thread 存，选中文本作为上下文；**它有会话历史，但没有「问答记录列表点回原文」这种按锚点索引的 UI**（`【推断】`：从依赖与组件结构看是 thread 模型，未逐行核实）。
- **我们自己的批注侧栏已经是这个范式了**，这是最该抄的一份：`client/src/annotate.js:669` 的 `AnnotationSidebar`（列表 + 空态 + 错误态 + 隔离计数），`client/src/app.js:555` 的 `onJump(record)` 就一句 `api.jumpToCfi(record.cfi)`，而 `client/src/reader.js:528` 的 `jumpToCfi` 已经处理了「同章重分页 / 跨章 `goChapter(index,{cfi})`」两条路。

**所以问答历史不是「设计一个新范式」，而是「把 AnnotationSidebar 复制一份，records 换成 `qa.list` 的结果，跳转字段从 `record.cfi` 换成 `record.anchorCfiRange`」。** readest 的聊天线程范式不抄：我们的 `qa.jsonl` 是「一条问答 = 一个锚点」，天然适合列表；做线程会引入「同一段话多次提问怎么折叠」的复杂度，0.4.0 不值得。

### 5.3 交互设计（可直接实现）

侧栏加一个「问答」tab（和批注列表并排），数据 `call('qa.list', { bookHash })`：

```
[问答 12]                         [只看本章]
┌────────────────────────────────┐
│ "他为什么没有回头"              │  ← question，2 行 clamp
│ 选区：他站在门口，没有回头……    │  ← contextExcerpt，1 行 ellipsis，灰
│ 6 月 3 日 · deepseek-v3         │  ← createdAt + model 徽标
└────────────────────────────────┘
   ↓ 点击整条
jumpToCfi(anchorCfiRange) + flash 高亮 800ms
```

要点：

1. **点击整条 = 跳回原文**，展开答案用右侧小箭头（`▸`），别让「跳转」和「展开」抢同一个点击区域；
2. 跳转用现成的 `jumpToCfi`（`reader.js` 已有），失败（旧 CFI、书被重导入）降级用 `contextCfiRange` 的起点，再失败就 toast「原文位置已变化」——**不要静默什么都不发生**；
3. 「只看本章」按 `chapterHref` 过滤，比按 CFI 前缀稳；
4. 空态文案：「还没有问过 AI。选中一段文字，点『问 AI』」；
5. AskPanel 里加一个「历史」按钮 → 打开侧栏并滚到当前锚点那条（`scrollIntoView({block:'nearest'})`）；
6. 排序 `createdAt` 倒序；同一 `threadId` 的追问在列表里缩进一级（有 `threadId`/`parentId` 字段，做不做都行）。

**成本**：一个列表组件 + 一个 tab 切换 ≈ 80 行，不动存储、不动协议。

## 6. 值不值得照搬：三分类清单

### 照搬（高性价比，本轮就该做）

| 项 | 来源 | 改法 | 为什么值 |
|---|---|---|---|
| 链接拦截骨架（委托 + 一律 preventDefault + 先 resolve 再判外链） | foliate-js `view.js`（MIT） | `reader.js` 新增 `installLinkHandler(doc, index)`，`handleLoad` 里调用 | 今天点链接**完全没反应**，是「产品不完整」级别的缺陷；骨架只有 30 行，剩下是分流 |
| 锚点查找双保险 `getElementById ?? [name=]` | epub.js（BSD-3） | `pageOfAnchor()` 里 | 老 EPUB2 的 `<a name="fn1">` 很常见，不做就有一半脚注跳不过去 |
| `.dr-book { min-width:0 }` + 标题 `overflow-wrap:anywhere` | 通用 CSS 实践（非某项目专有） | `style.js` 三行 | 一行修掉「同排封面不等宽」，且不引入回归 |
| 保留 `auto-fill`，不加 `auto-fit` | 反例来自「书少时封面被拉宽」的常见实现 | 现状已对，写进注释防后人改 | 改错一次就是封面 500px 宽 |
| 封面 URL 加 `&v=updatedAt` | 通用缓存实践 | `api.js` + `shelf.js` 调用处 | 换封面立刻生效，否则用户以为保存失败 |
| 问答历史列表 + `jumpToCfi` 点回原文 | foliate 批注侧栏范式 | `annotate.js` 加 tab | 后端 `qa.list` 已就绪，纯 UI 增量 |

### 差异化（必须自己写，抄不到）

| 项 | 为什么抄不到 | 我们的做法 |
|---|---|---|
| 锚点 → 页号换算 | foliate/readest 是滚动或滚动分栏，`scrollIntoView` 一行搞定；我们是 transform 分页 | `pageOfAnchor()` 用 `getBoundingClientRect` 差值 / `(列宽+gap)`，字体 ready 后重算 |
| 外链打开方式 | 它们在自己的窗口里，`globalThis.open` 就行；我们在 DSH Web GUI 的 iframe 里 | 父页面 `window.open(..., 'noopener')`，被拦时复制链接 + toast |
| 元数据编辑 | readest 根本没做；Calibre/KOReader 是桌面应用，写 `metadata.opf`/sidecar | 写 `meta.json` + 覆盖 `cover.<ext>`，加 `book.update` 方法 |
| 脚注浮层（popover） | foliate 有完整实现（`epub:type="noteref"` + 内容注入），但依赖它的渲染层 | 0.4.0 **不做**，先保证「跳过去能看」；浮层放 0.5.0 |

### 跳过（明确不做，别被 star 数带跑）

| 项 | 项目 | 不做的理由 |
|---|---|---|
| `replaceLinks` 一次性快照法 | epub.js | 后插入链接不接管；我们以后要加脚注浮层/注释卡片，委托才对 |
| `mailto:` 直接放过 | epub.js | sandbox iframe 里点了静默失败，用户以为链接坏了 |
| Tauri 原生右键菜单 | readest | 我们是 Web 插件，原生菜单 API 不存在；DOM 菜单 30 行就够 |
| sqlite 书库 / IndexedDB 存储 | koodo / readest | 我们已有 `meta.json` + `qa.jsonl` 的目录结构，迁移是净负债 |
| 引 foliate-js 重写渲染层 | readest | 它是完整阅读器内核；我们只需要它的 30 行链接逻辑，引进来是 500KB 的债 |
| `coverFit` 用户设置 | readest | 我们的封面是统一 `cover` 裁切 + 纸封面兜底，加设置项是给 1% 场景加 100% 的测试面 |
| 直接复制 AGPL 代码文本 | readest / koodo | License 不兼容风险；学思路即可 |

## 8. 给设计师的三条落地建议（按顺序做）

1. **链接**（`reader.js`）：新增 `installLinkHandler` + `pageOfAnchor`，`goChapter(index, {anchor})`，`toc.onJump` 透传 fragment。验收按 §2.6 的 7 条手动过一遍。
