# 手机与桌面包：怎么打，先打哪个

这一份只做规划，没有动代码。结论先摆出来，后面是理由和代价。

---

## 一、结论

| 目标 | 能不能做 | 怎么做 | 成本 | 建议 |
| --- | --- | --- | --- | --- |
| Windows EXE | **不需要单独做** | 装 DeepSeek Harness 官方 exe，再装本插件 | 0 | 直接走官方 |
| macOS DMG | **不需要单独做** | 装官方 dmg，再装本插件 | 0 | 直接走官方 |
| Android APK | 能做，但只是「套壳」 | Bubblewrap 做 TWA，指向你的 DSH 地址 | 1–2 天 | 想要就做 |
| 独立 App（自带引擎、离线阅读） | 理论上能做 | Electron/Tauri 把 DSH 宿主连同插件一起打包 | 2–4 周 | 不建议现在做 |

一句话：**这是一个插件，不是一个软件。** 它能运行，靠的是 DSH 那个宿主进程 —— 宿主负责起服务、装插件、管账号。打 EXE/DMG 等于重打包整个 DSH，那件事官方已经在做，而且做得比我们好。

---

## 二、为什么 EXE 和 DMG 不用自己做

DeepSeek Harness 官方每夜发包，平台上都有现成的安装包（实测可下载）：

- Windows x64：`deepseek-harness-0.2.1-rc.3-win-x64.exe`
- macOS arm64：`deepseek-harness-0.2.1-rc.3-mac-arm64.zip`

装完宿主，再装插件（插件市场里就有，或 `npm i dsh-reading` 后挂进 profile），阅读器的界面就出现在侧栏。这跟「我们自己打一个 exe」对用户来说没有区别，却少维护一条发布线。

真要说缺点：安装包是官方的，用户得先装 DSH。但阅读器本来就是 DSH 的一部分，这一点躲不掉 —— 除非走下一节的独立 App。

## 三、Android APK 的三种做法

### A. PWA（已经具备，0 成本）

插件已经提供 `manifest.webmanifest` 与图标，手机上用浏览器打开 DSH 地址，菜单里选「添加到主屏幕」，就有一个全屏图标。iOS 用 Safari 的「分享 → 添加到主屏幕」。

- 优点：零打包、零签名、随插件更新自动更新。
- 缺点：本质还是浏览器；需要 DSH 在跑，手机要能访问到那台机器（同一局域网，或者你已经配好的公网穿透）。
- 适合：自己用、只需要一个图标入口。

### B. TWA 套壳 APK（1–2 天，推荐给「要一个 APK 文件」的场合）

用 Google 的 Bubblewrap 把上面那个网址包成一个 Android App：

1. `npm i -g @bubblewrap/cli`，`bubblewrap init --manifest <你的 manifest 地址>`；
2. 生成 `applicationId`（例如 `com.hulibuld.dshreading`）、签名密钥（keystore 自己保管）；
3. 站点根目录放 `/.well-known/assetlinks.json`（校验 App 与站点的归属，否则地址栏会露出来）；
4. `bubblewrap build` 出 `app-release-signed.apk`，直接发给手机装。

前提有两个，都是硬的：

- 地址必须是 **HTTPS**；
- 那台跑 DSH 的机器在手机上要能连上（局域网 IP 或公网域名）。

不上 Play 商店就不用开发者账号；上架要 25 美元一次性费用，还要过审（阅读器类应用会被看版权来源，这一点对我们不利）。

### C. 独立阅读器 App（2–4 周，不建议）

把 DSH 宿主 + 这个插件打成一个自带服务的壳（Electron / Tauri + 内置 Node）。要额外处理：内置 Node 运行时、profile 与插件目录、书库位置、自动更新、崩溃上报。等于是重做一个产品，而不是发一个插件。

只有在一种需求下值得做：**完全离线、不装 DSH、手机本地读书**。那时候数据结构也要改（现在书库在 `~/.dsh-reading`，得改成 App 私有目录）。

## 四、真正的坑不在打包，在数据

手机端和电脑端是**两个独立书库**。现在没有同步（WebDAV 一直挂在「没做」里）。如果先发 APK，用户装完打开会看到一个空书架，以为书丢了。

所以顺序应该是：

1. 先把 WebDAV 同步做掉（进度、划线、笔记、书源列表），手机和电脑才是同一套书；
2. 再做 PWA / TWA；
3. 桌面端写一段安装说明就够。

如果等不及同步，也可以先发 APK，但界面里必须写明「这是你自己的书库，和电脑上那台不是一回事」，并且提供「导出 / 导入书库」的手动搬运。

## 六、这一版没做的事

- 没有生成任何安装包；
- 没有引入 Electron / Tauri / Bubblewrap 依赖；
- 没有改 `package.json` 的 `engines` / `os` 字段（插件仍然只在宿主里跑）。
