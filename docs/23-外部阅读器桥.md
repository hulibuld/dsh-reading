# 外部阅读器桥（0.11.0 设计）

目标：让 dsh-reading 能和外面已经在用的阅读器/文献工具连起来，把书、论文、标注、笔记互相搬。
**不做的事**：不模拟点击别人的界面，不抄任何插件或应用的代码，不碰没有开放接口的软件。

四个适配器，按落地顺序：**Zotero → KOReader → Calibre → Obsidian**。
（Readwise 是云端服务、要 token，架构里留了位置，第五个再做。）

## 一、先说清「连」是什么意思

三种连法，成本从低到高：

| 连法 | 做法 | 能读 | 能写 | 稳不稳 |
|---|---|---|---|---|
| 读文件 | 直接读它存在硬盘上的文件（.sdr、Markdown、metadata） | 能 | 一般不能 | 最稳，但字段随版本变 |
| 调本地接口 | 它开一个本机地址或给命令行工具（Zotero 本地 API、calibredb） | 能 | 看它给不给写 | 稳，官方支持 |
| 驱动界面 | 模拟点击、截图、读屏 | 能 | 能 | 最脆，改版就坏，**不做** |

Agentero 那种「AI 在软件里跑」的本质是第一、二种的组合：软件把数据放在可读的位置，AI 通过 CLI 读写。
我们照这个模式做，但代码全部自己写。

## 二、总体架构

```
lib/bridges/
  index.js        —— 适配器注册表：list()、get(id)、detect()、import()
  zotero.js       —— 读 Zotero 本地 API
  koreader.js     —— 读 KOReader .sdr（Lua 表）
  calibre.js      —— 调 calibredb 命令行（JSON 输出）
  obsidian.js     —— 写 Markdown 到 vault
lib/bridges/http.js —— 极简本机 HTTP 客户端（只用 node:http，不引依赖）
```

每个适配器导出同一组函数，形状固定：

```js
export const id = 'zotero'
export const label = 'Zotero'
export async function detect(ctx)          // 能不能连上，返回 { ok, detail, hint }
export async function list(ctx, query)     // 能导入的东西（分类 / 书 / 笔记）
export async function fetch(ctx, itemId)   // 单条详情 + 附件路径或字节
export async function annotations(ctx, itemId) // 已有标注（没有就返回 []）
export async function write(ctx, payload)  // 可选；不支持就不要导出这个函数
```

`ctx` 由宿主传进来：`{ settings, http, logger, paths }`。适配器不直接读 settings，也不自己拼路由。

### 路由

沿用现有 `POST /api/dsh-reading/<method>` 的形状，新增四个：

- `bridge.list` —— `{ id }` → 返回该适配器能导入的东西
- `bridge.detect` —— `{ id }` → `{ ok, detail, hint }`
- `bridge.import` —— `{ id, itemId }` → 走现有导入通道落成一本（或一组）书，返回 `{ bookHash }`
- `bridge.write` —— `{ id, payload }` → 写回（部分适配器没有）

### 为什么放在宿主

外部软件都在本机，宿主的 Node 进程能读文件、能起 HTTP 请求；客户端在浏览器里读不了 `~/Zotero`。
这也和「书库归宿主管」的既有边界一致：客户端只发指令、只显示结果。

### 安全

- 只连 `127.0.0.1` / `localhost`，适配器里把非本机地址直接拒掉。
- 不自动启动别人的软件；只探测端口/文件是否存在。
- token（以后 Readwise）存在 `settings.json`，界面上只说「已保存」，不回显。
- 导入的附件按普通书落盘，路径不写进 meta（避免把 `~/Zotero` 的绝对路径带进书库）。

## 三、四个适配器怎么做

### 1. Zotero（论文，最先做）

**连法**：Zotero 7 自带本地 API：`http://127.0.0.1:23119/api/`。前提是用户在
「设置 → 高级 → 允许其他应用与这台电脑上的 Zotero 通信」里勾上。不联网、不限速、离线可用。

**能读**：

- `GET /api/users/0/collections` —— 分类树（做「选一个分类导入」）
- `GET /api/users/0/collections/<key>/items` —— 分类下的条目
- `GET /api/users/0/items/<key>/children` —— 子条目（含 `annotation` 类型）
- `annotation` 条目里带 `annotationText`、`annotationComment`、`annotationColor`、`annotationPageLabel`

**附件**：本地 API 的附件路径要拼 `~/Zotero/storage/<attachmentKey>/<filename>`；
拿不到就直接读这个目录（Zotero 的存储布局是稳定的）。

**写回**：**本地 API 是只读的**。写回 Zotero 需要用户自己的 Web API key（云），或者做 Zotero 插件。
第一期只读，写回列在第三期，且要用户明确同意再用他的 key。

**导入后长什么样**：PDF 走现有 PDF 解析（`parsePdf` 自动判论文版式），题录（作者、年份、期刊）
写进 `meta.description` 与标签，Zotero 的高亮变成我们的批注——**能做的前提是文本能对上**：
Zotero 的标注锚在 PDF 页面上，我们的锚在重排后的 XHTML 上，两边没有共同坐标。
第一期先「带过来放在批注列表里，标上『来自 Zotero 第 N 页』」，不做位置精确对齐（那要 CFI 与页面坐标的映射表）。

### 2. KOReader（墨水屏/安卓）

**连法**：读文件。每本书旁边有一个 `<书名>.sdr/metadata.<格式>.lua`，里面是 Lua 表：

```lua
["annotations"] = {
  [1] = { ["chapter"] = "第一章", ["text"] = "划线原文", ["note"] = "我的批注",
          ["page"] = 42, ["pos0"] = "/body/DocFragment[3]/...", ["pos1"] = "...",
          ["datetime"] = "2026-10-01 21:30:00" },
},
["percent_finished"] = 0.37,
```

**做法**：

- 用户选一个目录（通常是挂载上来的 KOReader 设备或它同步到电脑的文件夹）。
- 扫 `*.sdr/metadata.*.lua`，找同目录同名的书；把书导入书库，把标注变成批注。
- Lua 表不用完整解释器：写一个「表字面量解析器」，只认 `{ }`、`[key] =`、字符串、数字、布尔、逗号和分号。
  二百行以内，且能被单测钉住。

**写回**：KOReader 只能通过它自己的同步服务（koreader-sync-server）收进度，协议是自建的、字段很少，
不支持写批注。所以**只读**，写回不做。

**进度**：`percent_finished` 可以映射成我们的 `bookProgression`，用户看到「在墨水屏上读到 37%」。

### 3. Calibre（电子书库）

**连法**：调它自带的命令行 `calibredb`（Calibre 安装目录里，macOS 在
`/Applications/calibre.app/Contents/MacOS/calibredb`）。用户先告诉我们 Calibre 书库路径，或者我们用
`calibredb list --library-path` 试一下。

**列表**：`calibredb list --for-machine --fields=title,authors,formats,tags,series,identifiers,pubdate`
返回 JSON 数组，解析即得。比直接读 `metadata.db`（SQLite）稳：不用 SQLite 驱动，也不怕它升级表结构。

**导入**：条目里的 `formats` 是绝对路径（如 `.../Title (1)/book.epub`），直接读文件走导入通道。

**写回**：可选的第三期——把我们的蒸馏稿生成 EPUB/HTML，用 `calibredb add` 塞回书库。
先不做，等前三个稳定。

**为什么不读 metadata.db**：Node 的 SQLite 支持还在变（`node:sqlite` 版本间行为不同），
而 `calibredb` 是官方入口、输出稳定。宁可多一条子进程，少一个原生依赖。

### 4. Obsidian（笔记库）

**连法**：vault 就是一个文件夹，全是 `.md`。写文件即可。

**做什么（单向写）**：

- 把陪读教练的知识卡片（`books/<hash>/coach/*.md`）复制进 vault 的 `dsh-reading/读书卡/`
- 把蒸馏稿（`distill.json` 的 markdown 导出）写到 `dsh-reading/蒸馏/`
- 文件名：`《书名》- 卡片 - 2026-11-09.md`；frontmatter 带 `bookHash`、`title`、`source: dsh-reading`
- 已有同名文件就更新那一个（幂等），不产生 `-1`、`-2`

**读（第二期）**：如果 vault 里已经有 `dsh-reading/` 以外的读书笔记，可以按书名匹配，把摘要塞进
AI 问答的上下文。这一期先不做——读别人的笔记容易把别人的观点当成书里的原文。

**为什么不用 Local REST API 插件**：让用户装插件、开端口、配 token，比「告诉我 vault 路径」麻烦得多。
写文件不需要它。

## 四、界面

书架右上角「书源」旁边加一个「外部」按钮，打开一个面板，四行：

```
Zotero       ● 已连接     [从 Zotero 导入]
KOReader     ○ 选目录…    [从 KOReader 导入]
Calibre      ● 已连接     [从 Calibre 导入]
Obsidian     ● 已连接     [导出读书卡 / 蒸馏稿]
```

- 未连接的行只有一个动作：告诉用户怎么连（Zotero 勾哪个开关、KOReader 选哪个目录）。
- 连接状态是**打开面板时探测一次**，不后台轮询：别人的软件不归我们管，不能一直去敲它的端口。
- 导入过程复用现有的进度提示（「正在导入…」），不新造一套。

## 五、分期与工作量

| 期 | 内容 | 工作量 | 交付判据 |
|---|---|---|---|
| P0 | 桥框架（注册表、http 客户端、四个路由）+ Zotero 检测与列表 | 1 天 | Zotero 开着时能列出分类与条目 |
| P1 | Zotero 导入（含附件与标注） | 1 天 | 选一篇论文，落到书架，带批注 |
| P2 | KOReader .sdr 扫描与导入 | 0.5 天 | 选目录，导入一本，标注与进度都在 |
| P3 | Calibre 列表与导入 | 0.5 天 | 导入一本 EPUB |
| P4 | Obsidian 写入（卡片 + 蒸馏稿） | 0.5 天 | vault 里出现卡片，重复导出不重复 |
| P5 | Readwise（云 API，token） | 1 天 | 拉一次高亮，落成批注 |

## 六、测试

- **Zotero**：起一个假的本地 HTTP 服务（`node:http`），按 Web API 形状返回两三个条目 + 一个分类 +
  一条标注；断言适配器能列出、能取到附件路径、能解析标注。不起真实 Zotero。
- **KOReader**：临时目录里造一个 `.sdr/metadata.epub.lua`（含划线、注、进度），断言解析出的条数与字段。
- **Calibre**：不调真 CLI——把 `calibredb list --for-machine` 的输出存成 fixture，注入一个假执行器。
- **Obsidian**：临时目录当 vault，写两次，断言只有一个文件、内容被更新。
- 端到端：`test/e2e_local_test.mjs` 加一条——假 Zotero 服务 → `bridge.list` → `bridge.import` → 书架里有书。

## 七、风险与边界

- **Zotero 本地 API 只读**：想写回必须用云端 key，这个决定要用户点头，不能默认做。
- **标注对不上位置**：Zotero/KOReader 的锚是页面坐标，我们的是 XHTML 里的 CFI。第一期只做「内容搬过来 + 标页码」，不做精确跳转。做成精确跳转要维护 PDF 页 → 章节 → 字符偏移的映射表，是另一个工程量。
- **Calibre 路径**：CLI 路径因安装方式而异（App Store 版不同），检测要给出「没找到 calibredb，请告诉我它的位置」的人话。
- **Obsidian 写坏笔记**：只在 `dsh-reading/` 子目录写，不碰 vault 根目录与别人的文件；同名更新前先备份到 `dsh-reading/.history/`。
- **端口冲突**：Zotero 23119 被占时，只报「连不上」，不重试轰炸。
- **不连**：微信读书、得到、多看、掌阅、MarginNote、Apple Books、Kindle。没有开放接口，模拟界面不稳也不合规。

## 八、不做的事

- 不模拟点击任何外部软件。
- 不读别人的数据库文件（Zotero 的 `zotero.sqlite`、Calibre 的 `metadata.db`）——走官方入口。
- 不自动启动 Zotero/Calibre/KOReader。
- 不把外部路径写进书库 meta。
- 不做 Readwise 之外的云端服务（微信读书等）。
