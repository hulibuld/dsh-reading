# 审计修复记录

这份文档记录一次**外部审计**提出的全部缺陷、每条的修复方式，以及对应的回归测试。

审计者是一位不共享本项目任何上下文的审查代理：只交给它仓库路径、四条验证命令，
以及「找出缺陷，不要客气」。它的报告在 [`06-独立审计报告.md`](./06-独立审计报告.md)。

---

## 为什么值得留这份记录

自己写的测试会不自觉地绕开自己没想到的地方。这次的 11 条缺陷里，有 2 条是**高危、
静默、且现有测试全绿**的那种：

- 翻页之后高亮整体错位一页 —— 不报错，只是错位；
- 声明 `size=0` 的 deflate 条目会把压缩炸弹展开进内存 —— 只有真炸弹才炸。

它们能活到审计阶段，恰恰说明「测试全绿」不等于「没有 bug」。所以每条修复都补了一个
**会红的回归测试**：把老代码改回去，测试必须失败。下面逐条列。

## 高危

### H1. 翻页后高亮整体错位一页

**位置**：`client/src/annotate.js` 的 `computeRects`（原 `left: frameBox.left + rect.left - shift - layerBox.left`）

**问题**：`range.getClientRects()` 返回的是**视觉**矩形，祖先元素的 CSS `transform`
已经算进去了（CSSOM View 规定：`getClientRects` 与 `getBoundingClientRect` 一样返回
变换后的盒子）。而翻页正是靠 `doc.body.style.transform = translateX(-offset)` 实现的，
所以 `rect.left` 里已经含了 `-offset`。再减一次 `shift` 就是双重扣减。

**现象**：第 1 页正常，第 2 页起所有色块整体左移一个页面宽度。不抛异常、不写日志。

**修复**：删掉 `- shift`，坐标改为 `frameBox.left + rect.left - layerBox.left`。
`pageOffsetPx` 参数保留（页码变了要重算，它是上层的 repaint 依赖），但不再参与换算，
并在 JSDoc 与调用处写明原因。

**回归测试**：`test/dom_immutability_test.mjs` — 用同一批 50 条锚点算两次矩形
（`pageOffsetPx` 分别 0 与 548），逐矩形断言 `left`/`top` 完全一致。
把老代码改回去，第一条就报：`第 0 个矩形在翻页后横向位置变了（32 → -516）`。

### H2. 声明 `size=0` 的 deflate 条目绕过解压上限

**位置**：`lib/zip.js` 的 `extract`

**问题**：防压缩炸弹的第一道闸在中央目录阶段，判的是**声明**尺寸；第二道闸是
`inflateRawSync(raw, { maxOutputLength })`。原实现写的是
`entry.size > 0 ? { maxOutputLength: entry.size } : undefined` —— 当条目声明
`size=0` 时，选项整个变成 `undefined`，等于不设上限。中央目录看到 0 字节就放行，
inflate 于是把整颗炸弹展开到内存里。

**修复**：无条件传选项，声明 0 时给 `maxOutputLength: 1`（空表达式的合法输出是
0 字节，上限 1 足够；任何真解出内容的都会撞上限），并把 `ERR_BUFFER_TOO_LARGE`
翻译成 `E_ZIP_TOO_BIG`。

**回归测试**：`test/zip_test.mjs` — 手搓一个「中央目录与本地头都谎报 `size=0`、
实际展开 20 MB」的包。断言中央目录阶段放行（这是前提）、`get()` 抛 `E_ZIP_TOO_BIG`；
同时断言真正的 0 字节条目仍能正常读（上限不能误伤空文件）。

## 中危

### M1. 结构预检没有过 filter

**位置**：`client/src/cfi.js` 的 `checkStructure` / `childSlots`

**问题**：`checkStructure` 是交给 vendor 之前「自己先走一遍」的规范模型，负责把
索引越界、偏移越界、在文本块上继续下降分成三个确定的失败码。它算的是「索引 → 节点」
的映射，而 vendor 算的时候是**带 filter** 的。`childSlots` 漏传 filter，于是阅读器
注入的 `<style data-dsh-reading-injected>`（每个章节都注入）在父节点的槽位表里
占掉一格，索引整体错位。

**现象**：对一份**刚由自己算出来、完全合法**的 CFI 报 `cfi_resolve_failed`。
用户看到的是「刚划的标注，一点开就报错」。

**修复**：`childSlots(element, filter)` 过同一份 filter，`checkStructure` 把 filter
一路传下去；新增 `SKIP_NODE` 常量（`NodeFilter.FILTER_SKIP = 3`）避免每个调用点
再去取 `win.NodeFilter`。

**回归测试**：`test/cfi_test.mjs` 的 `structureCheckAlsoUsesFilter` — 往 body 插一个
注入标记元素，`fromRange` 算出的 CFI 必须仍能通过 `validate`。老代码在这里报
`cfi_resolve_failed / 路径 /4/2/2/1 在索引 2 处越界`。

### M2. 隔离舱不幂等

**位置**：`lib/store.js` 的 `quarantineBadLine`

**问题**：坏行的 id 用 `bad-${Date.now().toString(36)}-${lineNumber}` 生成。于是同一行
坏数据每被读一次就换一个 id、又追加一条记录。`quarantine.jsonl` 随刷新次数线性膨胀，
隔离舱从「证据」变成「垃圾场」。

**修复**：id 改为内容派生 —— `bad-<sha256(文件名:行号:原文) 前 16 位>`。写之前先把
已有 id 读进内存（每个书目录一次），重复的直接跳过；写盘失败时把内存标记撤回，
下次读还会重试（不是永久放弃）。

**回归测试**：`test/store_test.mjs` — 连续三次读同一份含坏行的文件，断言
`quarantine.jsonl` **逐字节不变**、条目数不增长；再追加一条**不同**的坏行，
断言仍会入舱（幂等不能变成「一律忽略」）。

### M3. 一致性向量的「独立性」有边界

**位置**：`golden/spec-cfi.mjs`、`golden/dom-walk.mjs`

**问题**：`golden/` 的真值由一份不 import vendor、也不 import `client/src` 的独立 spec
算出，这确实能抓实现偏离（它已经抓出三个真 bug）。但那份 spec 复用了同一套
「before / after / first / last 虚拟槽位」本体论 —— 它能证明「两套实现一致」，
不能单独证明「符合 EPUB CFI 规范」。

**处理**：不假装这是外部验证。README 与 CHANGELOG 的「已知限制」里写清楚这条边界；
外部基准（Readium、Calibre）的交叉验证留作后续工作。

## 审计认为做对的（也记下来）

审一次不只为了挑错，确认哪些防线是真的在守也有价值：

- **filter 完整性**：所有 CFI 调用点都经 wrapper，`cfi.js` 的两个内核函数签名里根本没有
  filter 参数 —— 「漏传」这种事故在类型层面就不可能发生。
- **`dom_immutability_test` 是真测试**：指纹包含文本节点切分、属性值、源码黑名单三层，
  不是「数一下节点个数」那种假验证。
- **解压门禁顺序正确**：先看声明尺寸、再决定解不解，解完再核长度。
- **XML 不展开 DTD / 外部实体**：没有 XXE 面。
- **墓碑合并方向正确**：`compareVersion(...) >= 0`（这条本身是更早一轮 e2e 测试抓出来的：
  `>` 会让同毫秒的墓碑被待删记录顶掉，表现是「删掉的标注刷新又回来」）。

## 第二轮代码质量复审（第三位审查员，只读）

前面那一轮是**文档与契约**审；这一轮换了一位只看代码的审查员，对着同一份冻结字节
又跑了一遍全量验证，再逐行读关键路径。它修不动代码（只读），只交结论。
它找到的问题分两类：一类是前面那轮修过、它确认修对了；另一类是**上一轮没看见的**。

确认修对的：H1（翻页双重扣减）、H2（`size=0` 绕过解压上限）、M2（隔离舱幂等）、
以及上一轮的 6 条低危。它同时在报告里明确说：解压炸弹防护、墓碑合并方向、
CFI 中间段 id 限制这三处**判得对**。

新发现的，按危害排序：

### F1. 高亮几何没有缓存，翻页卡半秒（high）

`computeRects` 每画一条记录都要 `CFI.toRange`：重新 parse、跑一遍结构预检、再让
vendor 从 `documentElement` 逐层下降。审查员实测 1000 次 3634ms；翻页会整层重绘，
等于再算一遍（200 条 ≈ 730ms）。`docs/03` §七本来就写着「单章 >100 条标注必须缓存」，
但实现里没有。

**修法**：annotate 里加模块级 `WeakMap<Document, Map<cfi, Range>>`。只缓存 Range、
不缓存矩形 —— 矩形依赖当前排版与翻页位移，必须每次重量；Range 只依赖 DOM 结构，
而**换章就是一个新 Document 对象**，WeakMap 的键随之失效，天生不用手工清缓存。
上限 4000 条只是保险（正常一章几十条）。

回归：`test/dom_immutability_test.mjs` 里对比冷启动与暖缓存两轮耗时（暖 ≤ 冷 × 0.6 才算过）。

### F2. 恶意 EPUB 能把阅读界面导去外站（medium）

`<meta http-equiv="refresh">` 与 `<base>` 原样透传。CSP 管不到导航，iframe 的
sandbox 也没开 `allow-top-navigation`，但**帧内自身导航是允许的** ——
所以一条 meta refresh 就能把整章换成远程页面。这是安全边界，不是显示问题。

**修法**：改写阶段整条丢弃 `base` 与 `http-equiv=refresh` 的 `meta`。这成了
「原样输出」的一个**记录在案的安全例外**（另一个见 F3），`lib/routes.js` 文件头写明了。

回归：`test/routes_test.mjs` 断言 `evil.test` 不出现在响应体里，其它 meta 与正文原样保留。

### F3. 书里的链接一点就把阅读界面点散（medium）

`<a href>` 被改写成 `/api/dsh-reading/asset?...`，点下去 iframe 就导航到一份裸
XHTML/CSS 字节（served 给图片用的头），阅读界面整片白。

**修法**：`<a>` 一律降级成**不导航的锚** —— `href="#dsh-reading:<原文>"`，原文
percent-encode 塞进 fragment。点它什么也不会发生，也不会触发任何跳转；将来做
「点链接跳转到目标章节」时，可以从 fragment 里把原文读回来。纯 `#frag` 站内锚
保持原样（那种跳转还在同一份文档内，无害）。

回归：`test/routes_test.mjs` 断言跨章链接变成 `#dsh-reading:...`、站内 `#top` 不动、
外部 `https://` 同样降级、没有 href 的 `<a>` 不长出属性。

### F4. 属性值里的 `>` 让整条 `src` 漏改（low）

旧的标签扫描用 `/<[A-Za-z][^>]*>/g`。`>` 在属性值里是合法字符（`alt="a > b"`），
于是这种标签被截成两半，里面的 `src` 不再被改写 —— 图片加载失败，且**只有这一张**。

**修法**：`findTagEnd` 按 `'` / `"` 跟踪引号，引号内的 `>` 不算标签结束；
`<!--` / `<!DOCTYPE` / 裸 `<` 仍按正文原样带走。

回归：断言 `alt="a > b"` 原样保留、同一标签里的 `src` 仍被改写成 asset URL。

### F5. 转义逗号让区间判断出错（low）

`fromRange` 原来用 `inner.includes(',')` 判「这是区间还是点」。CFI 里 `^,` 是字面逗号，
`[p^,1]` 是转义后的断言值，两者都会被误判成区间分隔符。

**修法**：`hasUnescapedComma` 扫 `^` 转义，并跳过 `[...]` 断言段（断言里的逗号是分隔
`text` 断言参数的，不是区间分隔符）。

### F6. 书签被画在页面左上角（low）

没有矩形的书签（书签本来就是零宽的点）会被补一个假矩形 `{0,0,10,14}`，于是每次翻页
都在左上角画一个小方块 —— 看着像坏了。现在**什么都不画**：书签的存在感由侧栏列表负责。

### F7. 注入节点让生成与解析各用一套下标（medium，原 docs/01 的写法是错的）

这是本轮最值得记的一条，因为它**推翻了设计稿的一部分**。

`docs/01`/`docs/04` 要求 filter 对注入节点返回 `FILTER_SKIP`，理由是「SKIP 跳过自身、
保留子节点；REJECT 会把真文本一起丢掉」。这句话本身没错，但 vendor 的实现是
**不对称**的（`client/vendor/epubcfi.foliate.js:201-211` 与 `:244-260`）：

- `getChildNodes` 遇到 SKIP 是 `return getChildNodes(node, filter)` —— 子节点**拼进父列表**；
- `nodeToParts` 却把 SKIP 节点自身那一段的 `index` 记为 `-1` 后**整段丢弃**。

两者拼不到一起：生成时用的是「注入节点内部的下标」，解析时用的是「父级的下标」。
实测 `<p>A</p><div data-dsh-reading-injected><p>B</p></div>` 里给 B 生成 CFI 得到
`!/4/2`，解回来指向 **A** —— 不报错，只是划错地方。

**修法**：filter 改为 `FILTER_REJECT`（整棵子树不算）。这样生成与解析都只看同一份
兄弟列表，自洽。代价是注入节点里的文本不参与 chunk 计数，也**不可被锚定** ——
这正是我们想要的：注入的是 `<style>`，它的 CSS 文本本来就不该进书签偏移。

配套的模型侧（`checkStructure` 的槽位表）也随之按 REJECT 语义重写：
`collectIndexedNodes` 递归展开，REJECT 整棵丢、SKIP 摊平（保留对 SKIP 的通用支持，
万一将来 vendor 改了行为也只是换个返回值）。

回归：`test/cfi_test.mjs` 的 `injectedNodesDoNotShiftExistingCfi()` ——
先在干净文档上取两条 CFI，再往 `<head>` 插带 CSS 文本的 `<style>`、往两个段落之间
插含元素的注入包裹，断言同一个 CFI 仍**精确**落在原来那几个字上，且仍通过结构校验。
这条用例在 SKIP 实现下是红的（第二段会解到第一段上）。

### 一并收掉的工程债

- `client/src/app.js` 的主面板注册多带了官方插槽清单没登记的 `priority: 50`。
  官方 `registerOptions` 只登记 `key`；严格校验的宿主会因此抛错，而 `apply` 抛错 =
  这个 slot **静默退役**（用户看到的是「面板没了」）。已删。
- `lib/routes.js` 里 `writeFailure` 的两个分支完全相同（死分支），收成一处。
- `test/run.mjs` 在缺 `jsdom`/`ajv` 时把 import 错误当失败（陌生人 clone 后不装
  devDependencies 会看到三条红）。现在识别 `ERR_MODULE_NOT_FOUND` 且包名命中时记 SKIP。
- `golden/run.mjs` 缺 jsdom 时直接抛原始栈。现在先给出中文提示再抛，退出码非零。
