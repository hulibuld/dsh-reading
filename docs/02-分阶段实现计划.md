# dsh-Reading 分阶段实现计划 v1.0

> 每一阶段的定义标准：**能独立验收**。不能验收的阶段不是阶段，是待办事项。
> 阶段可以砍，顺序不能乱。Phase 0 不通过就开工 UI，等于把钱押在未验证的假设上。

---

|---|---|---|---|---|

## Phase 0：契约与锚点地基

### 为什么这个阶段必须存在

整个项目只有一个真正的技术风险：**两端对同一本书算出同一个 CFI**。这一件事若在 P5 才发现做不到，前面 10 周的工作全部要改锚点模型。所以先花 1.5 周把它钉死。

### 交付物

1. `schema/contract.schema.json`（已产出 v1，本阶段做用例验证）
2. `core/cfi.ts` —— TS 参考实现，基于 foliate-js `epubcfi.js`，包一层本项目接口
3. `golden/fixtures/*.epub` —— 8 本构造书（嵌套内联、相邻文本节点、空元素、CDATA、ruby、RTL、脚注引用、emoji+CJK扩展B）
4. `golden/vectors.json` —— 至少 200 条向量，覆盖正常与畸形两类
5. `golden/run.mjs` —— TS 侧 runner
6. `spike/flutter_readium_probe/` —— 手机端 CFI 可行性验证工程
7. `docs/02-CFI-规范.md` —— 把方案 §3 提炼成两端都要照着写的实现手册

### 验收标准

| # | 标准 | 判定方法 |
|---|---|---|
| A0-1 | TS 实现跑过全部 200 条向量，0 差异 | `node golden/run.mjs` 退出码 0，输出 `PASS 200/200` |
| A0-2 | 畸形 CFI 全部被正确分类到 quarantine | 向量中含 30 条畸形样本，逐条断言 `reason` 字段正确 |
| A0-3 | 同一文档重复生成 100 次 CFI 完全一致 | 幂等性测试 |
| A0-4 | 空元素、相邻文本节点、注释混排下偏移正确 | 专项向量组 |
| A0-5 | **Flutter spike 给出明确结论**：能否稳定拿到 (元素选择器, 文本节点序号, 字符偏移) | spike 输出一份 `RESULT.md`，含 4 个问题的实测答案 |
| A0-6 | 若 A0-5 为「否」，Plan B 的字段语义变更已写进契约文档 | 文档更新 |

A0-5 是这个阶段的**唯一不可妥协项**。它没有「差不多」的结论，只有能或不能。

### 依赖与风险

- 依赖：无（本阶段不需要 dsh 环境）
- 风险 R1：Flutter spike 需要一套能动起来的 Flutter 环境。若本机没有，先装，别跳。
- 风险 R2：10 万字的书做 CFI 批量生成可能很慢。若单章 > 100 ms，需要在 P1 前设计缓存策略（按 chapterHref 缓存规范化树）。
- 风险 R3：foliate-js 是 0.0.0，行为可能变。缓解：vendor 到 `core/vendor/foliate-epubcfi.js`，锁 commit，并在文件头记录 commit hash。

### 出口判据

`golden/run.mjs` 通过 + `spike/RESULT.md` 结论明确。二者缺一，不进 P1。

## Phase 1：电脑端阅读器（能读）

### 交付物

1. dsh 插件骨架（host `index.js` + client React 入口），能被 dsh 加载
2. EPUB 导入：本地文件选择 → 算 bookHash → 落本地书库 → 生成 meta.json
3. 书架视图：列表、封面、进度环、最近阅读
4. 阅读视图：分页、翻页（键盘/点击/滚轮）、双栏可选
5. 目录：章节树、当前高亮、点击跳转
6. 进度：自动保存到 progress.json（本地），关书重开恢复到原位
7. `spike/iframe-decision.md` —— iframe 方案是否可用的结论

### 验收标准

| # | 标准 |
|---|---|
| A1-1 | 导入 3 本真实 EPUB（含中文竖排、含图、含脚注），全部能打开 |
| A1-2 | 翻页无白屏、无跳动；连续翻 100 页无内存增长异常 |
| A1-3 | 关闭重开，回到上次位置，误差 = 0 字符 |
| A1-4 | 目录跳转后 CFI 与点击章节的首个文本节点一致 |
| A1-5 | 主题跟随 dsh 明暗切换（书籍正文可独立设置，但插件 UI 必须跟随） |
| A1-6 | 不含脚本的 EPUB 与含脚本的 EPUB 都能打开，且后者脚本**未执行** |
| A1-7 | 打开一本 5 MB / 50 万字的书，首次渲染 < 2 秒 |

### 依赖与风险

- 依赖：P0 的 `core/cfi.ts`
- 风险 R4（高）：iframe 约束。方案 §10.4 已备 Plan B（Shadow DOM），但那是 1–2 周额外工作。**这个风险必须在 P1 第一周内确认**，不能拖到最后。
- 风险 R5：foliate `paginator.js` 的分页依赖 iframe 内的布局计算，Shadow DOM 化需要改 `view.js`/`paginator.js`/`overlayer.js` 三处。若走 Plan B，P1 估时要重估。
- 风险 R6：大书解析阻塞主线程。缓解：host 侧预解析 + 分章惰性加载。

### 出口判据

能连续读一小时不崩、不丢进度。这条只能靠真读，不能靠测试用例。

## Phase 2：标注与笔记

### 交付物

1. 选区菜单：五色高亮、写笔记、加书签
2. 覆盖层渲染（`overlayer.js` 封装），正文 DOM 零改动
3. 侧栏：本书全部标注，按章节/颜色/类型筛选
4. 标注编辑、改色、删除（软删）
5. 点击标注 → 跳回原文
6. 标注写入 annotations.jsonl（本地）
7. `test/dom-immutability.test.ts` —— 断言「加标注前后正文 DOM 结构指纹不变」

### 验收标准

| # | 标准 |
|---|---|
| A2-1 | 跨段落、跨内联元素（`<em>`/`<strong>`/`<a>`）划线，边界字符精确 |
| A2-2 | **加 50 条标注后，所有标注位置仍精确**（DOM 不可变性的直接检验） |
| A2-3 | 改字号 / 改栏宽 / 切主题后，标注位置不漂 |
| A2-4 | 删除一条标注，其余标注不受影响 |
| A2-5 | 同一条划线可先高亮后加笔记，笔记挂到同一条记录上（不产生两条） |
| A2-6 | 标注列表中每条都能跳回，跳回后目标在可视区内 |
| A2-7 | 关闭重开，标注全部还在，位置完整 |

A2-2 是这个阶段的灵魂。它若过不了，说明某处偷偷改了 DOM，后面所有同步都会带着错位的锚点跑。

### 依赖与风险

- 依赖：P0、P1
- 风险 R7：跨分页的选区（从第 1 页末尾选到第 2 页开头）在 CSS multi-column 下 DOM Range 是连续的，但视觉跨页。渲染要拆成多段矩形。foliate 的 overlayer 已处理，但要测。
- 风险 R8：竖排 / RTL 文本的矩形计算。v1 允许降级为「整段高亮」并记入已知限制。

## Phase 3：WebDAV 同步与 BYOC 引导

### 交付物

1. `host/routes/webdav.js`：连接测试四步探测、PROPFIND/GET/PUT/DELETE/HEAD、ETag 读取
2. 能力探测：自动判定后端支持 `If-Match` / `LOCK` / 两者都不支持
3. 同步引擎：pull → merge → push，含 `.sync-state.json`
4. 逐记录合并算法（`host/sync/merge.js`）+ 性质测试
5. `history/` 写入与轮转（保留 20 份）
6. 设置向导：分步表单、四步测试实时反馈、错误码映射到中文文案
7. 坚果云图文指引（含「必须用应用密码」的显著提示）
8. 同步状态面板：上次同步时间、待同步条数、失败原因、手动重试
9. 频率预算与退避

### 验收标准

| # | 标准 |
|---|---|
| A3-1 | 用错误密码 → 显示 `E_AUTH`，文案明确指出「可能是主密码而非应用密码」 |
| A3-2 | 用只读路径 → 显示 `E_NO_WRITE`，指出「能读不能写」 |
| A3-3 | 用错域名 → 显示 `E_DNS` 或 `E_TLS`，不显示笼统「连接失败」 |
| A3-4 | 坚果云实测：完整配置流程 ≤ 4 步，无需查外部文档 |
| A3-5 | 两台设备各加 10 条标注，同步后两边都是 20 条，**无丢失** |
| A3-6 | 同一 id 在两端修改，合并后取 `updatedAt` 较新者，旧值进 history |
| A3-7 | 删除一条标注，同步后两端都看不到（墓碑生效），但文件里仍有该行 |
| A3-8 | 注入 30 条畸形 CFI，全部进 quarantine，阅读器不崩、不渲染它们 |
| A3-9 | 断网 → 改动 5 条 → 恢复网络 → 自动补齐，无重复、无覆盖 |
| A3-10 | 连续同步 100 次，请求数不超过预算（用 mock 后端计数） |

A3-5 是**这个阶段唯一不能打折的项**。它是「逐记录合并而不是整文件后写胜」这个设计存在的理由；如果做不到，说明又回到了会丢数据的方案。

### 依赖与风险

- 依赖：P2（需要有标注可同步）
- 风险 R9：坚果云频率限制。缓解：PROPFIND 快照 + 批量 PUT + 退避。要在 A3-10 里量化。
- 风险 R10：时钟漂移导致合并顺序错乱。缓解：§10.8，服务器 Date 头校准 + `clockSkew` 标记。
- 风险 R11：用户把同步根路径填成网盘根 → 我们的文件散落在用户其他文件之间。缓解：配置完强制建 `dsh-reading/` 子目录，路径框只让填到父级。

## Phase 4：AI 问答（电脑端）

### 交付物

1. `host/ai/scoped-context.js`：唯一取文入口，按 `cutoffCfi` 硬截断
2. 子会话派生：每问一个短生命周期子会话，主会话只收摘要
3. 选区 → 提问 UI；标注 → 提问 UI；追问（`parentId` 链）
4. 问答面板：按时间/按标注聚合两种视图
5. 每条回答下方「回原文」按钮
6. `qa.jsonl` 写入（含 `anchorCfiRange` 强制性校验）
7. 「存入记忆」功能，带 `sourceBook` + `sourceCfiRange`

### 验收标准

| # | 标准 |
|---|---|
| A4-1 | 读到第 3 章时问「后面主角会怎样」，模型明确表示不知道后续 → 截断生效 |
| A4-2 | 手动构造一个「问 cutoff 之后段落」的请求，`scoped-context` 抛错，不返回任何后文 |
| A4-3 | 主会话上下文中不含整章原文（检查会话记录） |
| A4-4 | 每条 qa 记录都有 `anchorCfiRange` 与 `cutoffCfi`，无例外 |
| A4-5 | 强行写入一条无锚定的回答 → 被写入函数拒绝 |
| A4-6 | 点「回原文」精确落在触发提问的那段文字上 |
| A4-7 | 追问能带上之前的问答上下文，且 `parentId` 链正确 |
| A4-8 | 换一本书提问，上下文与新书无关（无串书） |

A4-2 是防剧透的机械证明。不靠「模型乖不乖」，靠它拿不到。

### 依赖与风险

- 依赖：P2（需要锚点）、P3（qa.jsonl 走同一套同步）
- 风险 R12：模型可能把「用户当前在第 X 章」误读为「可以推测后续」。缓解：prompt 里明确「你不知道后续内容，也不要推测」+ 结构上确实没有。
- 风险 R13：长追问链导致子会话上下文膨胀。缓解：只带最近 3 轮 + 始终带的锚定原文。

## 关键路径与并行机会

```
P0 ──┬─→ P1 ─→ P2 ─┬─→ P3 ──┬─→ P4 ─┐
     │              │        │       ├─→ P7
     └──────────────┼────────┴─→ P5 ─→ P6 ─┘
                    │
                    └──────────────→ (P5 可与 P2/P3 并行，若人手够)
```

- P5 只依赖 P0，理论上可以和 P1/P2 并行。单人做不了，两人可以。
- P4 依赖 P3（qa 走同一套同步），但 UI 可以提前设计。
- P7 不可压缩，它是「能不能给别人用」和「做完了」之间的差别。

## 里程碑定义（对外可讲的那种）

| 里程碑 | 达成条件 | 意义 |
|---|---|---|
| M1 可读 | P1 完成 | 能在 dsh 里读完一本书 |
| M2 可记 | P2 完成 | 划线笔记可用，但只在本机 |
| M3 可同步 | P3 完成 | 数据不怕丢，可以开始自用 |
| M4 可问 | P4 完成 | 差异化功能出现 |
| M5 可跨端 | P6 完成 | 项目目标达成 |
| M6 可发布 | P7 完成 | 能交到陌生人手里 |

**M3 是心理分水岭。** 到这一步用户可以放心真实使用，之后的功能都是在有价值的基础上加。

## 不做什么（防止范围蔓延）

按优先级从高到低砍：

1. PDF 支持 —— v2 议题，需要另一套定位模型
2. 手机端 mobi/txt 导入 —— 让用户用电脑转一次
3. 自动冲突合并 —— 第一版只做逐记录取新
4. 全本 AI 摘要 —— 明确不做
5. 多用户共享书库 —— 明确不做
6. 云端书城 / 推荐 —— 明确不做
7. 手机端 AI —— 硬约束，不做
8. TTS 朗读 —— 除非 flutter_readium 白送
9. 手写批注 / 画线 —— 诱惑很大，但会拖垮时间表
10. 数据统计（阅读时长、词频）—— 好玩但无用

前三条是「做了会推迟发布」的量级，后七条是「做了也不影响闭环」的量级。
