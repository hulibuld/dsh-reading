# 书源：按 Legado 的格式搜书、加书

这一版加的是「书源」——不是又一个下载器，而是把 Legado 那套书源 JSON 接过来用：
你手上已经有的源，不用改，直接导进来就能搜书、看目录、加入书架。

插件**不内置任何书源**，也不带默认站点的地址。列表里空着的那个框，就是你自己的责任边界。

---

## 一、能做什么

| 动作 | 结果 |
| --- | --- |
| 导入书源 JSON | 一个文件里几十上百个源，一次导完；同 URL 的源覆盖更新，不产生重复 |
| 搜书 | 已启用的源并发搜索，结果带来源与最新章节，失败的原因单独列出来 |
| 加入书架 | 抓目录、落盘成一本书，书架里显示「网络书源」标记 |
| 读正文 | 翻到哪一章抓哪章，缓存到那本书的目录里；断网后已读过的章还能看 |
| 停用 / 删除 | 某个源坏了不影响别的源 |

## 二、规则支持到什么程度

Legado 的书源规则有四层退化：CSS（Jsoup）→ 正则 → XPath → JS。
这一版实现了**前三层加一个很窄的 JS 子集**，够跑常见的 css 源，跑不了的会明确报错，不会静默返回空。

| 语法 | 状态 | 说明 |
| --- | --- | --- |
| `@css:选择器`、裸选择器 | ✅ | 标签 / `.class` / `#id` / `[attr=值]` / `[attr*=值]` / `[attr^=值]` / `[attr$=值]` / `>` 子选择 / `,` 并列 |
| 默认规则（多段 `.` 连接） | ✅ | `class.item.0`：逐段求值，纯数字当下标 |
| `@json:路径`、裸 `$` 路径 | ✅ | `$.list[*]` / `$..name` / `['key']` / 数字下标 |
| `## 正则` / `##$1` | ✅ | 提取与分组；支持忽略大小写、`.` 不匹配换行 |
| `@xpath:` | ⚠️ | 支持 `/`、`//`、`@attr`、索引、`text()` 的常用子集，复杂轴不支持 |
| `@js:` / `<js>` | ⚠️ | 只支持取字段与拼字符串的极小模板（`{{key}}`）；含循环/正则/校验的脚本直接报错说明原因 |
| 目录分页 `nextTocUrl` | ✅ | 最多翻 10 页，防死循环 |
| 正文分页 `nextContentUrl` | ✅ | 同上 |
| `{{baseUrl}}` `{{page}}` 等模板变量 | ✅ | 搜索地址、目录地址、正文地址都支持 |

**不支持就要说清楚**：含 JS 逻辑的源（大量网站用 `@js` 算签名）会带着源名报一条「这个源的规则用了脚本，暂时跑不了」，而不是让用户对着空列表猜。

## 三、字段怎么用

导入时读这几个字段（Legado 自己的命名）：

- 身份：`bookSourceName`、`bookSourceUrl`、`bookSourceGroup`、`enabled`
- 搜索：`searchUrl`（`{{key}}` 换成关键词）、`ruleSearch` 的 `bookList` / `name` / `author` / `bookUrl` / `intro` / `lastChapter`
- 详情与目录：`ruleBookInfo.tocUrl`、`ruleToc.chapterList` / `chapterName` / `chapterUrl`
- 正文：`ruleContent.content`

缺 `bookSourceUrl` 或 `searchUrl` 的源会被拒，并告诉你是哪一条、缺哪个字段——导入一批 200 个源时，这条信息比「导入失败」有用得多。

## 四、一次搜索会发生什么

1. 取已启用的源，最多 8 个并发；
2. 每个源套 `searchUrl` 模板、发 GET、按规则抽列表；
3. 单个源失败不影响别的，失败原因记在「N 个源没搜成」里；
4. 结果按源分组显示，最多 60 条；
5. 点「加入书架」才抓目录（几秒），正文等你翻到那一章才抓。

## 五、书怎么存

网络书和本地书走同一个书架、同一套 CFI 锚点、同一套标注：
书目录下是 `meta.json` + 生成的 XHTML 章节，`sourceFormat` 记 `legado`。
已经抓过的章节落盘，所以断网、关掉重开都还能读；没抓过的章节需要联网。

## 六、隐私与边界

- 搜索请求从**你的机器**直接发到书源站点，插件不经过任何中转；
- 插件不内置、不推荐、不分发任何书源；
- 书源内容与可用性由书源作者决定，抓不到的章节就是抓不到，插件不会去猜别的地址。
