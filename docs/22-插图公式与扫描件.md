# 插图、公式、扫描件：统一走「截成图片」

方案（0.11.0），针对论文 PDF 里三类内容：**插图**、**公式**、**扫描页**。

核心策略是一句话：**正文只保留「确定是字、且认得对」的内容；其余一律变成图片块，按原始坐标插回正文原位置。** 不做「猜不出来就用占位符糊过去」这种事，也不把乱码当正文塞给读者。

## 一、三类内容其实是同一个问题

| 内容 | PDF 里是什么 | 一期能做吗 | 为什么 |
|---|---|---|---|
| 论文插图 | 多数是内嵌位图（JPEG / Flate 位图） | 能 | 位图本来就存在文件里，抽出来即可，不需要渲染 |
| 扫描页 | 通常整页就是一张大位图 | 能 | 同上，抽出来就是整页图 |
| 公式 | 字体里画的符号（少部分是位图） | 部分 | 字体画的抽不出像素，要光栅化；位图公式能抽 |
| 矢量图、表格框线 | 路径绘制 | 不能 | 路径要在画布上重画，必须有渲染器 |

所以一期能覆盖一大半真实文件，且**不需要引入渲染器**；剩下那部分（矢量、字体公式）交给二期的浏览器渲染。

## 二、数据怎么走

现在的解析链是：`lib/pdf.js` 的 `PdfDocument` → `lib/pdftext.js` 的 `extractPageText`（内容流状态机，已经维护了变换矩阵 `matrixAt(matrix)` 和 CTM）→ `linesToParagraphs` → `chaptersFromPages` / `parsePaper` → `lib/textbook.js` 的 `buildReflowedBook` → 章节 XHTML。

插入图片要动三个地方：

1. **抽取层**（`lib/pdftext.js`）。现在是 `case 'Do'`（`lib/pdftext.js:770`）只处理 `Subtype = Form` 的表单对象，遇到 `Subtype = Image` 直接跳过；`BI ... ID ... EI` 的内联图走 `skipInlineImage`（`lib/pdftext.js:541`）整段丢掉。改成：遇到图像对象时记一条 `{page, x, y, width, height, ref}` 到页面结果里，同时**在该位置的文本流里插一个占位标记**（例如 `\u0001{index}\u0001`），让图片在段落序列里占住它原来的位置。占位标记在后续清洗步骤里被替换成图块。
2. **资源层**（`lib/pdf.js`）。新增 `pageImages(pageIndex)`：取图像的原始流字节。`DCTDecode` 直接就是 JPEG 文件字节，原样落地；`FlateDecode` 是裸像素，要自己编码成 PNG（`node:zlib` 的 `deflateSync` 已经有，PNG 编码器约 150 行）。`JPXDecode`（JPEG2000）、`CCITTFaxDecode` 暂不支持，记一条 `unsupported`。
3. **排版层**（`lib/paper.js` / `lib/textbook.js`）。`buildReflowedBook` 已经支持 `chapter.html` 直通（0.10.0 加的），所以论文版式直接把图块拼进 HTML；普通书版式则在 `buildChapterXhtml` 里加一条：段落文本等于占位标记时输出 `<figure>`。

资源地址沿用现有约定：书目录下的 `assets/`，通过 `assetBytes(bookHash, href)` 读。路由已经有 `GET /asset`，不用新增接口。

## 三、什么情况自动降级成图片

判定分三层，从粗到细：

**页级（整页变成一张图）**

- 抽出的字符数 / 页数 < 20
- 未知字形（`unmapped`）占该页字符数的 30% 以上
- 双栏检出（同一水平线上出现两组相距超过页宽 40% 的文字块）
- 页里只有图像对象、没有任何文字对象

页级降级后，这一页整页当图显示，页内不再尝试排版。

**块级（一个区域内做图）**

- 图像对象水平覆盖 ≥ 页宽 30%，或高 ≥ 60pt
- 图像紧挨一行以「图 N」「表 N」「Figure N」「Table N」开头的文字 → 图注跟随，图片放在图注上方

**行级（二期，需要渲染器）**

- 该行来自缺 `ToUnicode` 的字体，或私有区字符占比 > 30%
- 公式特征：无汉字、运算符与希腊字母密集、字号上下跳变（上下标）、行宽明显短于正文且居中

行级命中就把这一行的矩形交给渲染器截图。这条是「识别明显错误」的主要出口：与其猜，不如截。

## 四、渲染器：放在浏览器，不放在宿主

**不引到 Node 端**，原因是依赖：pdf.js 在 Node 里跑 canvas 需要 `node-canvas` 或 `@napi-rs/canvas` 这种原生二进制，三个平台各一套预编译包，插件「零运行时依赖」这条底线就破了，而且 Windows 上装原生模块的失败率很高。

改成**浏览器端按需渲染**：

1. 宿主在导入时输出「区域清单」：`meta.layoutAssets[]`，每条 `{page, kind: 'figure'|'formula'|'page', x, y, width, height}`，坐标是页面归一化值（0–1）。
2. 前端拿到区域清单后，用 pdf.js（Apache-2.0）把对应页渲染进离屏 canvas，按归一化矩形裁切，`toDataURL('image/png')`，塞进 `<img>`。
3. 渲染结果存 IndexedDB，键是 `bookHash + page + rect`，下次打开直接命中。
4. 前端要能拿到原始 PDF：新增 `GET /pdf?book=<hash>`，只对本机应用自己发，读 `book.pdf`，带 `Cache-Control: private, max-age=3600`。

代价：前端多约 400KB（pdf.js 主包 + worker，gzip 后），首屏只在一本书有区域清单时才懒加载。

## 五、数据结构

```jsonc
// meta.json 新增
"pageMode": "text" | "image",          // 扫描件整本 → "image"
"layoutAssets": [
  { "page": 7, "kind": "figure", "href": "assets/p0007-i01.jpg", "width": 812, "height": 540 },
  { "page": 9, "kind": "formula", "test": "render", "x": 0.31, "y": 0.42, "w": 0.38, "h": 0.06 }
]
```

- `href` 存在的走硬链接图片（一期，宿主已经抽出字节）
- `kind: 'formula'` 且带 `test: 'render'` 的走前端渲染（二期）
- `pageMode: 'image'` 时，spine 每页一章，`href` 指向该页原图；阅读器切「图片页」：可缩放、翻页、加书签，不能选题划线、不能全文搜索

正文标记：

```html
<figure class="pp-fig">
  <img src="assets/p0007-i01.jpg" alt="论文插图，第 7 页"/>
  <figcaption>图 3 叙述时间的两种结构</figcaption>
</figure>

<span class="pp-formula" data-asset="f-p0009-01">
  <img src="data:…" alt="公式"/>
</span>
```

## 六、分期与工作量

**一期（不需要渲染器，约 1.5–2 天）**

- 图像对象抽取 + JPEG 直通 + Flate 位图转 PNG
- 占位标记 → 图块，按原位插入，图注跟随
- 扫描页整页图片模式
- 不支持格式（JPX/CCITT）留一句「这一页的图暂时显示不了」
- 测试夹具：内嵌 JPEG 的论文页、Flate RGB 图、整页扫描图、双栏页

**二期（浏览器渲染，约 2–3 天）**

- `GET /pdf`、前端 pdf.js、区域裁剪、IndexedDB 缓存
- 行级降级（乱码行、公式行）
- 「看这一页原样」按钮：任何页面都能整页渲染出来对照

**三期（可选）**

- 导入时后台把扫描件整本渲染成图缓存（要把前端渲染结果回传宿主，加一个上传接口）
- 公式识别（把图转 LaTeX）——这条最贵，且当前模型能力不稳定，建议不做

## 七、风险

- **CMYK JPEG**：浏览器基本能显示，个别的偏色。可接受。
- **索引色 / 带 SMask 的位图**：PNG 编码器要处理调色板与 alpha，不然透明区变黑块。一期先按「不透明、白底」处理，二期再补。
- **大图内存**：3000×4000 的一页解码成 RGBA 是 48MB。抽取时**不解码**，JPEG 直接字节透传；必须解码的（Flate）按行编码，不整体展开。
- **双栏检测误判**：中文论文单栏居多，阈值放宽到「两组文字中心距 > 页宽 40%」，宁可漏判也别把正常单栏切成图。
- **图片版权**：抽出来的图跟着书走，只在本地书库，不上传任何地方。

## 八、不做的事

- 不做 OCR。扫描件就是图，不假装能搜。
- 不做公式转 LaTeX。
- 不在宿主端装原生渲染依赖。
- 不为图片做「智能裁边」这种锦上添花的事。
