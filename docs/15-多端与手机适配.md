# 15 · 多端：安卓、Windows 与「为什么没有 APK / EXE」

> 状态：已实现（`0.7.0`）。和 [`docs/12`](12-找书与网络导入.md)、[`docs/14`](14-搜索与标注交互.md)
> 同一个系列：前面几篇讲书怎么进来、怎么读，这一篇讲**在别的设备上怎么读**。

## 1. 先说结论

`dsh-reading` **不是一个独立 App，所以没有 APK 和 EXE 可打包**。

它是一块跑在 DeepSeek Harness（下称 DSH）界面里的面板：宿主提供窗口、路由、文件访问、
模型调用，插件只负责「书架 + 阅读器」这一层。打包成 APK 的前提是能打包 DSH 本身，那属于
宿主的发行版，不在这份源码里。

所以「安卓版」「Windows 版」实际是三条不同的路：

| 你想在什么设备上用 | 实际做法 | 今晚做完的部分 |
| --- | --- | --- |
| 安卓手机 / iPad | 手机浏览器打开你那台电脑的 DSH 网页地址（你就是这么连远程的），再「添加到主屏幕」 | 全套窄屏适配 + PWA manifest + 图标 |
| Windows 电脑 | 在 Windows 上装 DSH，再 `dsh plugin add` 这个目录 | 跨平台兼容审计 + 修掉 Windows 上的写入隐患 |
| 想要真正独立的阅读 App | 需要另写一个外壳（Electron / Capacitor）+ 把 `lib/` 当纯 Node 库用 | 没做，见第 5 节 |

## 2. 手机：怎么用，做了什么

### 2.1 用法（三步）

1. 电脑上按你已有的方式起远程实例（cloudflared 隧道 + 扫码页），拿到公网地址。
2. 手机浏览器打开这个地址，进「Reading」面板。
3. 浏览器菜单里选**「添加到主屏幕」**（Chrome/Edge）或「分享 → 添加到主屏幕」（Safari）。

之后主屏幕上会出现一个叫**深读**的图标，点开是全屏（没有浏览器地址栏），直接进 DSH。

### 2.2 窄屏改了什么

窄屏不是「把字缩小」那么简单，真实的三个问题是：窄边占地、手指没有 hover、刘海与小白条。

| 问题 | 改法 |
| --- | --- |
| 两侧 26px 翻页窄边在 390px 屏上占 13%，正文被挤成细条 | `≤720px` 时整条隐藏；改用它处已有的「左右滑动」「底部热区」「左右方向键」翻页 |
| 鼠标「划过才出现」的箭头，在手机上永远不出现 | `@media (hover:none)` 下箭头常显（透明度 0.35），不靠 hover |
| 底部热区太小，拇指够不着 | 窄屏热区放大到 45% 宽 × 42% 高 |
| 顶部工具栏按钮多，换行会挤成两行 | 窄屏改成横向滚动（隐藏滚动条，按钮不换行），高度压到 44px、可点区域 ≥38px |
| 刘海屏顶部 / 底部小白条盖住侧栏与页码 | 侧栏补 `padding-top: env(safe-area-inset-top)`，页码行补 `padding-bottom: env(safe-area-inset-bottom)` |
| 正文左右留白 44px 在手机上太奢侈 | 窄屏 `padding: 16px 18px` |
| 手机横屏高度只有 300 多像素 | `@media (max-height:460px)` 把热区从 42% 收回 22% |

### 2.3 PWA：图标是怎么来的

插件拿不到页面 `<head>`，只拿到自己前缀路由（`/api/dsh-reading/*`）的控制权，所以：

- 宿主侧新增两个只读路由：`GET /api/dsh-reading/manifest.webmanifest`、`GET /api/dsh-reading/icon.svg`；
- 客户端 `apply()` 里幂等地往 `document.head` 塞 `<link rel="manifest">` 和几个 meta
  （`theme-color`、`mobile-web-app-capable`、iOS 的 `apple-mobile-web-app-*`）。

**听懂一句话就够**：manifest 是「应用说明书」，浏览器读到它才知道图标、名字、全屏方式；
我们把说明书放在自己能控制的路由上，再让页面去引用。

限制（写在这里免得以后误会）：`start_url` 只能是站点根 `/`，因为插件无权改宿主的启动页；
所以点图标打开的是整个 DSH，而不是直接跳进某本书。

## 3. Windows：审计了什么

代码本身没有写死平台的地方，逐项核对过：

| 检查项 | 结论 |
| --- | --- |
| 路径拼接 | 全部走 `path.join` / `path.sep`，没有硬编码 `/` |
| 用户目录 | `os.homedir()`，不是 `process.env.HOME` |
| 平台分支 | `lib/device.js` 已经把 `win32` 映射成 `win`（设备 id 用） |
| 文件名 | 书目录是 16 位 hash / 64 位 hex，不含 `:` `*` `?` 等 Windows 非法字符 |
| **覆盖写入** | **修过**：见下 |

**修掉的那个隐患**：`writeFileAtomic` 原来的做法是「写临时文件 → `rename` 覆盖」。
POSIX 上 rename 覆盖是原子的；Windows 上只要目标文件被杀毒软件、索引器或资源管理器
短暂持有句柄，就会抛 `EPERM` / `EBUSY` / `EACCES`，用户看到的是「保存进度失败」。
现在 `renameWithRetry` 会退避重试 3 次（20/40/60ms），仍失败就先删目标再改名。

没验证的部分要说清楚：**我没有 Windows 机器，没在真机上跑过**。上面是静态审计 +
按 Windows 已知行为改的，`test/layout_css_test.mjs` 里有源码级断言防止回退。

## 4. 手机上还做不到的事

- **没有离线阅读**：manifest 只做「图标 + 全屏」，没写 Service Worker，断网打不开。
- **不能后台播放 / 锁屏朗读**：没有语音朗读功能。
- **iOS 的「添加到主屏幕」不读 manifest 的图标**，用的是 `apple-touch-icon`；
  本插件没发这个路由，所以 iOS 上图标会是网页截图。要修就是再加一条 PNG 路由，但
  生成 PNG 要么引入依赖要么手写字节，暂时不值。
- 手机上侧栏是覆盖式抽屉（92% 宽），盖住正文时不能「边看目录边看正文」。

## 5. 如果以后真要独立 App

最小代价的路线不是重写，而是**换壳**：

1. 把 `lib/`（store / bookformat / txt / mobi / pdf / pdftext / routes）当纯 Node 库，
   它不依赖 DSH，只依赖 `node:fs`；
2. 外壳用 Electron（Windows/macOS）或 Capacitor（安卓）起一个本地 HTTP 服务，
   直接把 `client.js` 的面板挂进自己的页面；
3. 补一个 `ctx.slots` / `ctx.webServer` 的最小适配层，或者干脆让路由自己起 `http.createServer`。

这部分没有开工：它属于「另做一个产品」，不是这轮修 bug 的范围。

## 6. 测试

- `test/routes_test.mjs`：manifest 与图标的响应（content-type、字段、非空图标）；
- `test/layout_css_test.mjs`：窄屏规则（隐藏窄边、45% 热区、两处 safe-area、工具栏横滚）
  与 `renameWithRetry` 的存在性；
- 手机视口实测：Chrome headless `390×844` 渲染阅读器外壳，确认正文不被裁、工具栏不换行。

## 7. 一句话总结

手机上用「浏览器 + 添加到主屏幕」，Windows 上装 DSH 再装插件；APK/EXE 不是这个项目的
形态，硬要的话得另做外壳，那是另一个工程。
