# AI 状态中心与读书蒸馏（0.8.0）

这一版回答两个问题：**AI 到底为什么用不了**，以及**读完一本书能带走什么**。

---

## 一、AI 状态中心：把「莫名其妙不能用」变成一句人话

### 问题

插件里的 AI 调用（问 AI、蒸一章）失败时，界面只有一句「问不了 AI」。用户不知道是
本机断网、宿主没开会话、模型供应商挂了，还是额度用完了。唯一的办法是一次次重试——
这既慢又浪费，而且重试前还得把问题、选区重新找一遍。

### 做法

失败原因拆成四道**可独立成立**的检查，每道都带「怎么修」：

| 检查 | 判什么 | 不给过时说什么 |
| --- | --- | --- |
| `service` | 宿主有没有 `subagents` 服务 | 这个 DSH 版本没提供子代理服务，升级 DSH |
| `startActivation` | 服务有没有 `startActivation` | 宿主接口变了，升级 DSH 或等插件更新 |
| `session` | 有没有活着的会话能当 parent | 先开个对话发一句话，再回来用 AI |
| `route` | 能不能解析出 provider/model | 去设置里检查模型供应商与额度 |

再加一次**真实探测**（`ai.probe`）：发一句「只回复两个字：可用」，测的是网络与供应商，
25 秒超时。配置检查与真实探测分开，是因为「配置对了但网断了」和「配置根本不对」
需要用户做完全不同的事。

### 账本

每次调用写一行 JSONL 到 `<书库>/dsh-reading/ai-calls.jsonl`：

```json
{"id":"…","at":"2026-10-26T05:12:44.120Z","kind":"distill","label":"蒸馏：第三章",
 "bookHash":"…","bookTitle":"深度工作","chapterLabel":"第三章","promptChars":8421,
 "answerChars":612,"model":"p/m","latencyMs":18422,"ok":false,
 "code":"E_AI_TIMEOUT","status":504,"message":"模型 90 秒没回话",
 "preview":"你是一位耐心的读书助手…"}
```

- 成功也记：否则界面只能显示「上次失败」，看不出「最近恢复了」。
- 只留最近 300 条；文件超过 4 倍上限才裁剪（约 400 字节/条，不会无限长）。
- 坏行跳过不报错：一行坏了不能让整本账本作废。

### 界面

- 工具栏多一个 **AI 状态点**：绿 = 可用、黄 = 最近失败过、红 = 配置不通。
- 侧栏「AI 状态」面板：四道检查 + 最近 10 分钟失败统计 + 最近 50 次调用（时间 / 用途 /
  耗时 / 结果 / 错误码）+ 「测一次连通」+「清空记录」+ 账本文件路径。
- 问 AI 面板顶部常驻状态芯片，点它直接跳诊断。

### 每次调用都带着「当前在干什么」

用户抱怨的另一半是「失败之后还得重来一遍」。所以：

1. **请求里带上工作内容**：书名、作者、章节、选区，外加**选区所在整段**（上限 1500 字，
   转成纯文本）。问「这句什么意思」时，只给一句模型只能猜，给整段答案立刻准。
2. **失败不丢输入**：提交前把整份请求写进本机 `localStorage`（按书分键），失败后
   下次打开面板自动把问题填回来，重试就是「同一份再发一次」。成功即清除。
3. **蒸馏按章落盘**：一章一次调用，失败只记这一章（`status: failed` + 原因），
   其它章的成果不受影响。

## 二、读书蒸馏：把一本书蒸成能带走的笔记

### 它做什么

一册书按章处理，每章产出四类东西：

| 产出 | 形态 | 硬要求 |
| --- | --- | --- |
| 核心论点 | 一句话 + 若干条带原文引用的论点 | 引文必须能在本章原文里找到，找不到标「原文里没找到这句」 |
| 关键概念 | 术语 + 一句定义 | 术语必须是本章真正用到的 |
| 可执行方法 | 做什么 / 什么时候用 / 步骤 / 怎么算做完 | 四件缺一不算方法（避免「一句话空方法」） |
| 金句 | 逐字引用 | 同样回源核对 |

再合成一张**全书骨架**（一句话主旨 / 主论点 / 结构 / 适合谁），最后一键导出 Markdown。

导出的 Markdown 里有一节「可以直接照着做的」，把全书方法按章排开——这是这一版真正想
交付的东西：读完能动手，而不只是「读过」。

### 它故意不做什么

蒸馏主管（`dsh-distillation-director`）那套手册是**工作区级**的工程：多阶段流程、
Python 门禁脚本、技能包产出。阅读器里搬不动也不需要。这里只取它的三条内核：

1. **引文必须回源**——找不到就标出来，绝不假装；
2. **方法必须可执行**——做什么/何时用/怎么算完，凑不齐不算；
3. **只判过不过，不打分**——不给"这章值 8.2 分"这种假精确。

### 接口

| 方法 | 作用 |
| --- | --- |
| `distill.get` | 章节清单 + 已有蒸馏稿 + 进度 |
| `distill.chapter` | 蒸一章（一次 AI 调用，超时 240 秒） |
| `distill.skeleton` | 用已蒸的章合成全书骨架（需 ≥1 章） |
| `distill.export` | 返回 Markdown 全文 |
| `distill.clear` | 清空这本书的蒸馏稿（走 history 备份） |

数据落在 `<书库>/dsh-reading/books/<hash>/distill.json`，写入走 `writeFileAtomic`，
覆盖前把旧文件挪进 `history/`。

### 失败长什么样

- 模型不可用 → `E_AI_UNAVAILABLE`（503），面板顶部直接劝你去修 AI，并给跳转按钮；
- 调用超时 / 报错 → `E_DISTILL_FAILED`（502），这一章标失败并保留原因；
- 回复不是合法 JSON → `E_DISTILL_FORMAT`（502），同样只影响这一章；
- 还没蒸过就点骨架 → `E_DISTILL_EMPTY`（400），文案是「先蒸几章」。

## 三、换模型与思考强度（0.8.1）

插件里的 AI 调用默认跟随当前会话的模型。想自己挑时，在「AI 状态」面板最上面：

| 控件 | 选项 | 说明 |
| --- | --- | --- |
| 模型 | 「跟随当前会话」+ 宿主名单里的所有模型（按供应商分组） | 名单来自宿主的 `sessionController.modelCatalog()`，和主界面输入框那个选择器是同一份 |
| 思考强度 | 「跟随模型默认」+ 该模型声明的档位（off / low / medium / high / xhigh / max） | **默认 high**（不是 max：max 很慢也很贵，留给具体的某一章自己开） |

下面一行永远写着「实际使用：provider/model · 思考 高（你选的）」——手选和实际不一致时
（比如选过的模型已经下架），这一行会退回并说明原因，而不是继续用一个不存在的模型。

三条实现上的取舍：

1. **强度不硬塞**。每个模型自己声明支持哪几档；用户选的档它没有，就退到该模型的默认档，
   并在下面写一句「这个模型没有『很高』档，已退到『中』」。静默塞一个不支持的档，
   用户看到的是「AI 报错」，而不是「设置没生效」。
2. **名单不内置**。读不到宿主名单时只留「跟随当前会话」，并说明原因，不 hardcode 一份
   迟早过期的模型列表。
3. **改完就生效**。没有「保存」按钮——多一个按钮就多一次「我改完忘了点」。

接口：`ai.models` 返回 `{available, groups, failures, default, current, effective, efforts, defaultEffort}`；
设置项是 `aiProvider` / `aiModel` / `aiEffort`（空串 = 跟随，`aiEffort` 默认 `high`）。
