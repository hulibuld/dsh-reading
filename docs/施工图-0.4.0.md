## 1. 起点事实盘点（改之前必须对上的现状）

### 1.1 一条请求怎么走

```
client: api.call(method, body)          client/src/api.js:118
  → POST /api/dsh-reading                headers: content-type json + x-dsh-device-id
  → routes: buildMethods(store)          lib/routes.js:340 起
  → store: 方法之间互斥（mutex）         lib/store.js
  ← { ok:true, data } | { ok:false, error:{ code, message } }
```

- 错误码面：`E_ARGS / E_METHOD / E_NOT_FOUND / E_COVER_NOT_FOUND / E_EPUB_TOO_BIG / E_FILE_TOO_BIG / E_INTERNAL` 等；客户端的 `ERROR_TEXT` 在 `client/src/shelf.js`。
- `call` 之外的专用入口只有三个：`getDeviceId`、`coverUrl`、`chapterUrl`/`assetUrl`（`client/src/api.js:143-200`）。

### 1.2 章节链接被改写成了什么样（改 §2 前必读）

`lib/routes.js:199-240` 的 `rewriteChapterAssets(html, { book, chapterHref, resolve })`（`#dsh-reading:` 前缀在 222 行）：

| 原始 `href` 值 | 输出 | 谁负责处理 |
|---|---|---|
| `''` 或 `#frag` | **原样不动** | 浏览器原生（同文档锚点），但被我们的 click 拦截接管 |
| `mailto:` / `tel:` / `javascript:` / `https://…` / `//host/…` | `#dsh-reading:<encodeURIComponent(原值)>` | 客户端拦截器（§2） |
| 相对路径 `ch3.xhtml#sec-3-2` / `../text/a.xhtml` | `#dsh-reading:<encodeURIComponent(原值)>` | 客户端拦截器（§2） |

补充事实：

- 同一函数还删掉整条 `<base>` 和 `<meta http-equiv="refresh">`（唯一例外，见文件头注释）。
- `src` / `xlink:href` 里的相对路径改成 `/api/dsh-reading/asset?...`，**不是** `#dsh-reading:` 形态。
- 因此界面上「点了没反应」的真相是：**href 已经是一个同文档 fragment，浏览器只是改了 `location.hash`，没有任何人监听。** `client/src/reader.js` 里对 `click` 的监听数为 0。
- 解码一次拿到的 `原值` 是**相对章节文件**的地址（不是 OPF 根，不是绝对 URL），跨章解析必须用书的 `spine` href 目录做基准。

### 1.3 分页模型与几何（§2 锚点定位、§3 命中判定的地基）

`client/src/reader.js`：

- `COLUMN_GAP = 48`、`SIDE_PADDING = 28`（文件头常量）。
- 分栏：`column-width = (frameWidth - 2*SIDE_PADDING) / columns`，`columns` 由字号/宽度算；正文容器 `transform: translateX(-(page * (width + gap)))`。
- **页号公式（全仓唯一口径）**：对书内任意元素的 `getBoundingClientRect().left`，`page = floor((left - bodyBox.left + 1) / (width + gap))`，再 clamp 到 `[0, totalPages-1]`。`annotate.js` 的定位走同一口径。
- `paginate(restore)` 目前按优先级吃三种 restore：`{ cfi, page, percent }`（cfi 优先，其次显式 page，最后 percent）。**锚点定位要插在 cfi 之后、page 之前**（见 §2.6）。
- `applyPage(offset)` 负责写 transform 并回调 `props.onPageChange({ pageOffsetPx, frameEl, page })`。
- iframe 由 `ReaderView` 渲染，`sandbox="allow-same-origin"`，`src` 每次章节变化都重新设，`onLoad` 里 `injectFrameStyle` 注入主题 CSS。

### 1.4 覆盖层（侧栏/抽屉/面板）的宿主

### 2.3 拦截器要识别的三种 href

监听挂在**书页文档**上，所以 `event.target` 一定是书里的元素。取 `event.target.closest('a, area')`，再读 `getAttribute('href')`（**不要读 `.href`**：`HTMLAnchorElement.href` 会把 `#dsh-reading:…` 解析成绝对 URL，尾巴对不上）。三种形态：

| 形态 | 例 | 处理 |
|---|---|---|
| 同文档 fragment | `#fn-1` | 原地定位（§2.6） |
| 改写壳 | `#dsh-reading:ch3.xhtml%23sec-3-2` | 剥前缀 → `decodeURIComponent` → 得到**原值**，再按原值分流 |
| 其它 | 空、`javascript:` | 已 preventDefault 后忽略 + `console.debug` |

> 注意：`getAttribute('href')` 对 `#dsh-reading:…` 返回的是**未解码**串；`decodeURIComponent` 必须包在 `try/catch` 里（用户书里可能有畸形百分号）。

### 2.4 判定顺序（照抄，顺序不可换）

```
click(a, ev)
 1. ev 不是主键点击（button !== 0）→ 交回浏览器（中键/右键）
 2. ev.preventDefault()          ← 无条件，先做。防 iframe 内导航与 hash 变动
 3. ev.stopPropagation()
 4. raw = a.getAttribute('href') ?? ''；raw === '' → 返回
 5. raw 以 '#dsh-reading:' 开头 → target = decode(raw.slice(12))；否则 target = raw   （decode 失败 → console.debug 并返回）
 6. 协议分流：
      scheme = /^[a-zA-Z][\w+.-]*:/.exec(target)?.[0].toLowerCase()
      http:/https:        → 外部打开（§2.10）
      mailto:/tel:        → 复制/提示（§2.10）
      javascript:/data:   → console.debug + 返回
      其它 scheme         → console.debug + 返回
 7. target 以 '#' 开头 → fragment = target.slice(1) → 原地定位（同章，§2.6）
 8. 拆 hash：hashAt = target.indexOf('#')；path = hash 前，fragment = hash 后（无 hash 则 fragment=''）
 9. path === '' → 原地定位（等价第 7 步）
10. 解析成 spine 项：spineIndex = resolveSpineTarget(spine, currentHref, path)
       null → console.debug('书内链接无法解析', {path, currentHref}) + 返回（停在原地，不报错）
11. 同章（spineIndex === 当前章）→ 原地定位（fragment）
12. 跨章 → props.onJumpSpine(spineIndex, { fragment })
```

「原地定位」= 调 `reader.js` 内部的 `paginate({ fragment })`（不换章、不重载 iframe），完事后 `emitProgress()`。

#### 2.5.1 三条规则（实现时逐条照做）

1. **路径归一**：按 `currentHref` 的目录拼接 `target`，再折叠 `.`/`..`/重复斜杠；结果必须**不以 `/` 开头**。以 `/` 开头或折叠后越界（`..` 多于层数）→ 返回 `null`。

### 2.6 分页模型下的锚点定位（**不许 scrollIntoView**）

为什么不许：分页模式下正文靠 `translateX` 平移、`overflow` 裁切，`scrollIntoView` 会去滚**外层容器**甚至父窗口，结果是把父页面滚走、正文一页不挪。

正确做法：把锚点元素换算成页号，再走现成的 `paginate`。

```js
/** 在书页文档里找锚点：id 优先，其次 name（`<a name>` 的老书）。找不到返回 null。 */
function findAnchor(doc, fragment) {
  const ids = [fragment]
  try { const d = decodeURIComponent(fragment); if (d !== fragment) ids.push(d) } catch { /* 畸形百分号：按原串试 */ }
  for (const id of ids) {
    if (id === '') continue
    const byId = typeof doc.getElementById === 'function' ? doc.getElementById(id) : null
    if (byId) return byId
    const byName = typeof doc.getElementsByName === 'function' ? doc.getElementsByName(id) : null
    if (byName && byName.length > 0) return byName[0]
  }
  return null
}
```

`paginate(restore)` 里插入分支（**位置固定在 cfi 分支之后、`page` 分支之前**）：

```js
} else if (typeof restore.fragment === 'string' && restore.fragment !== '') {
  // 锚点换算成页号：此时 transform 已归零，rect 就是书籍文档坐标。
  const el = findAnchor(doc, restore.fragment)
  const bodyBox = doc.body.getBoundingClientRect()
  const left = el ? el.getBoundingClientRect().left - bodyBox.left : null
  // 找不到锚点 → 停章首（0 页），不报错：书里指向已删锚点的链接很常见。
  target = left === null ? 0 : Math.floor((left + 1) / (width + gap))
}
```

收尾（两处都要）：

1. `const pages = Math.max(1, Number(frameEl.scrollWidth) ... )` 算完总页数后 clamp：`if (target > pages - 1) target = 0; if (target < 0) target = 0`。
2. `restore` 里的 `fragment` **用完即弃**：`paginate` 不接受 `fragment` 进入 `pendingRef`/URL 状态（`pendingRef.current` 存的是 `{cfi,page,percent}` 那套，别把 fragment 塞进去，否则重排时会重复跳）。

### 2.8 事件绑定位置与生命周期（iframe 事件的铁律）

- iframe 里的 `pointerdown`/`click` **不会冒泡到父文档**。任何「点书页」相关的判定都必须 `doc.addEventListener`，`doc = frameEl.contentDocument`。
- 绑定时机：`onLoad` 触发后、`injectFrameStyle` 之后立刻绑（同一个 effect）。此时 `contentDocument` 已可读（`allow-same-origin`）。
- 解绑：effect cleanup 里 `removeEventListener`；章节切换时 iframe 会换文档，旧监听随文档一起消失，但 src 相同的重载不会——所以 cleanup 必须显式解绑。
- `click` 用**冒泡阶段**（不要 `capture`）：书里没有脚本（CSP `script-src 'none'`），没有别的手会抢。
- 监听函数里**只读不改 DOM**：`closest` / `getAttribute` / `getBoundingClientRect` 是允许的；任何 `insert`/`wrap` 都是违规（铁律 1）。

### 2.9 键盘 Enter 激活

`<a href>` 用 Tab 聚焦后按 Enter，浏览器会在**帧内**触发一次 click（`defaultPrevented=false`）。因为我们的监听挂在文档上、冒泡能到，所以 §2.4 的流程自动覆盖。**不要**再单独绑 `keydown` 处理链接——那会双触发（一次跳到章、一次原地定位）。

唯一要补的：Enter 触发的 click 事件 `button` 属性为 `0`，第 1 步的过滤不会误杀。

### 2.10 外部链接与 mailto（含提示 UI）

`http(s)`：优先宿主能力。`ReaderView` 新增 `onExternalLink` prop（app.js 传下来），实现按顺序降级：

1. `props.onExternalLink(url)` 若返回 truthy → 结束；
2. `window.open(url, '_blank', 'noopener,noreferrer')` 得到非 null → 结束；
3. 都被拦 → `navigator.clipboard.writeText(url)`，`props.onNotice('链接已复制，请在浏览器里打开')`。

> 为什么用父窗口 `window.open`：iframe 是 `sandbox="allow-same-origin"` **没有** `allow-popups`，帧内打开一定被拦。

`mailto:` → 复制地址 + `onNotice('邮箱地址已复制：' + addr)`；`tel:` → `onNotice('电话：' + num)`；复制失败 → `onNotice('这个链接打不开')`。

提示 UI（包 A 新增，CSS 由 B 写进 style.js，见 §8.4）：

`ReaderView` 的 `onNotice={showNotice}`、`onExternalLink={undefined}`（宿主暂无 openExternal，先走 window.open 降级）。

## 3. 【包 A / 需求 C】点击外部收起

### 3.1 根因

`sideKind`、`settingsOpen`、`helpOpen`、`askOpen` 四个 state 只在各自 toolbar 按钮里 toggle；点击正文/空白没有任何监听（iframe 事件还不冒泡）。所以用户「点菜单栏 → 点书页」什么都不会关。

### 3.2 统一收口 API：`closeOverlays(options)`

在 `ReaderScreen`（`client/src/app.js`）里定义，**所有关闭路径的唯一出口**：

```js

 * 统一收起所有覆盖层。为什么要一个函数：四种覆盖层各有自己的 state，
 * 任何一处漏关都会让用户觉得「点了没反应」；收敛到一个出口才好逐条测。
 *
 * @param {{ except?: 'side' | 'settings' | 'help' | 'ask' }} [options]
 *   除某一类之外都收起（「点另一栏」时用来避免把自己也关掉）
 */
const closeOverlays = (options = {}) => {
  // TODO 逐 state 置空；返回 boolean 表示「是否有东西被关掉」
}
```

**必须支持「点另一栏」语义**：点目录 toolbar 按钮时 → `closeOverlays({ except: 'side' })` 之后再 `setSideKind(...)`；点「字号」→ `closeOverlays({ except: 'settings' })`；点「问 AI」→ `closeOverlays({ except: 'ask' })`。这样用户点第二个栏，第一个栏自动关，且第二个栏不会自我闪一下。

### 3.3 绑在哪儿（三个入口，缺一不可）

| 事件源 | 绑在哪 | 触发条件 | 动作 |
|---|---|---|---|
| 书页点击（正文空白、链接、任意处） | 每个章节 `contentDocument` 的 `pointerdown` | 目标是正文空白或任意非白名单元素 | `closeOverlays()` |
| 书页空白（不留缝） | 同上的 `pointerup`（`pointerdown` 后位移 < 6px 且 `selection.isCollapsed`） | 同上 | 同上（幂等） |
| 键盘 `Esc` | 父窗口 `keydown`（已有处理链） | 任意 | `closeOverlays()`，返回是否关过（关了才 `preventDefault`） |
| 主区域外的宿主区域 | **不做**（宿主外点击本插件收不到事件，README 里注明边界） | — | — |

> 为什么 `pointerdown` 和 `pointerup` 都绑：`pointerdown` 会在划词开始时触发（要挡住，见 §3.5），而有些用户是按下后才发现自己想关面板。两个都幂等，无副作用。
> 为什么不绑父窗口的 `click` 捕获取代：`side` 侧栏与 toolbar 在父文档里，父文档 click 抓不到 iframe 内的点击，必须两处都绑。

### 3.4 白名单（这些点击**不收起**）

判定顺序（自上而下，命中即返回）：

```js
/** 白名单：命中任一就不要收起覆盖层。 */
const KEEP_SELECTOR = [
  '[data-dr-keep-open]',   // 覆盖层内部提供这个属性的容器（侧栏/抽屉/弹窗根节点）
  '.dr-side',              // 右侧栏（目录/笔记/问答）
  '.dr-drawer',            // 字号抽屉
  '.dr-modal',             // 帮助、编辑书名、预览等弹窗
  '.dr-toolbar',           // 顶部工具栏（含书架按钮、目录按钮、字号、问 AI）
  '.dr-ask',               // 问 AI 面板
].join(',')
```

- **书页内**：`ev.target.closest('.dr-link-hit')` 不需要——链接不该挡住收起（点链接时面板该关，然后再跳章，体验更顺）。但**拖选**必须挡（§3.5）。
- **两侧 26px 翻页条**：`reader.js` 的翻页条是父窗口里的绝对定位元素（宽 26px），在 `pointerdown` 的父窗口监听里用 `closest('.dr-rail')` 排除；它对 `closeOverlays()` 返回 `false`，即不收起。
- **关闭按钮**：所有关闭按钮自己调 `closeOverlays()`，**不许**依赖事件冒泡（`stopPropagation` 会在按钮里调，避免重复触发）。

### 3.5 划词拖选的判据（不许把选中的词弄没）

```js
// pointerdown 时记：downX/downY、selection 已折叠
// pointerup/pointerdown 判定时：
const sel = frameWin.getSelection()
const dragging = Math.abs(ev.clientX - downX) > 6 || Math.abs(ev.clientY - downY) > 6
const hasSelection = sel !== null && sel.toString().trim() !== ''
if (dragging || hasSelection) return   // 不让收起，也不挡后续 SelectionMenu
```

> 为什么用 6px 而不是 0：触控板点击常有 1-2px 抖动，0 会让「单击」被误判成拖选、面板关不掉。

### 3.6 与其它交互的互斥

| 场景 | 期望 | 机制 |
|---|---|---|
| 面板开着，点目录按钮 | 目录关掉 | toolbar 按钮 = toggle，内部走 `closeOverlays({except:'side'})` 语义 |
| 目录开着，点「字号」 | 目录关、抽屉开 | 同上 |
| 抽屉开着，点侧栏里的目录项 | 抽屉关、跳章 | 目录项 click 先 `closeOverlays()` 再跳 |
| 问 AI 面板开着，点书页正文 | 面板关（不丢草稿？见下） | `AskPanel` 卸载前把已输入内容存进 `askDraftRef`，下次同 `recordId` 打开时回填——**可选加分项，本轮允许不做**；不做就写明「关闭会丢弃草稿」 |
| Esc 连按两次 | 第一次关最上层、第二次关剩下的 | `closeOverlays()` 全关即可，不需要分层 |

## 4. 【包 B / 需求 D】元数据编辑契约

### 4.1 磁盘上的形状（`~/.dsh-reading/books/<id>/meta.json`）

现状（`schema/contract.schema.json` 的 `meta` 定义，`additionalProperties:false`，必填 `id/title/author/format/size/spineCount/toc/createdAt/updatedAt`，可选：`coverHref/coverMediaType/progress/lastChapter/lastPage/lastPercent/reflow`）：

- `title` 无 `maxLength`，`author` 无 `maxLength`（允许空串）——**这是刻意的：EPUB 元数据里作者名经常几十上百字，schema 拦住会让导入失败。长度限制只放在 `book.update` 的校验里（§4.3）。**
- `coverHref` 是**书目录内的文件名**（`cover.jpg`），不是 URL。
- `updatedAt` 由 `store.writeMeta` 路径统一刷新（新增/改元数据时必须经它）。

0.4.0 **只加一个可选字段**：`tocSource`（见 §6.1）。其余一个字不动 → 旧 `meta.json` 天然合法，无需迁移。

### 4.2 routes 三个新方法（`lib/routes.js` 的 `buildMethods`）

#### `book.update`

```
请求  { book: string, title?: string, author?: string }
响应  { book: { id, title, author, updatedAt } }        ← 只要这三个字段 + updatedAt，别回整本 meta
错误  E_ARGS  缺失/类型错/超长/空标题
      E_NOT_FOUND  书不存在
```

校验（顺序固定，错误文案见 §8.5）：

| 字段 | 规则 | 违反 |
|---|---|---|
| `book` | 非空字符串 | `E_ARGS` |
| `title` | `typeof === 'string'`；`trim()` 后**不能为空**；长度 ≤ **120**（按 `Array.from(title).length` 算，避免 emoji 算两个） | `E_ARGS`「书名不能为空」/「书名最多 120 个字」 |
| `author` | `typeof === 'string'`；`trim()` 后**允许为空**（清空作者 → 书架显示「作者未知」）；长度 ≤ **80** | `E_ARGS`「作者名最多 80 个字」 |
| 其它字段 | **忽略**（不许客户端改 id/coverHref/progress） | — |
| 都没传 | `E_ARGS`「没有要改的内容」 | — |

实现约束：`title`/`author` 先 `trim()` 再写盘（避免首尾空格撑宽书架卡片，跟 §7 是同一个根因家族）；写盘走 `store.updateMeta(book, patch)`（互斥 + 原子写 + 刷新 `updatedAt`）。

#### `book.cover.put`

```
请求  { book: string, dataUrl: string }        // 前端 FileReader 的 data URL，形如 data:image/png;base64,....
响应  { book: { id, coverHref, coverMediaType, updatedAt } }
错误  E_ARGS「封面文件太大」/「只支持 PNG、JPEG、WebP 图片」/「封面数据无法解析」
      E_NOT_FOUND
```

| 项 | 规则 |
|---|---|
| 大小上限 | **data URL 解码后 ≤ 3 MiB（3_145_728 字节）**；请求体整体上限沿用 routes 现有的 body 限制（若现有 < 4 MiB 则把该路由的 body 上限提到 4 MiB，并在文件头注释说明） |
| 魔数 | PNG `89 50 4E 47 0D 0A 1A 0A`；JPEG `FF D8 FF`；WebP `52 49 46 46 ?? ?? ?? ?? 57 45 42 50`（RIFF 长度后必须 `WEBP`） |
| 扩展名与 mediaType | PNG → `.png` / `image/png`；JPEG → `.jpg` / `image/jpeg`；WebP → `.webp` / `image/webp` |
| 落盘 | 写 `<bookDir>/cover.<ext>`；若已有别的扩展名的 `cover.*`，先删掉（否则两个文件同时存在，`coverBytes` 靠目录扫描会不确定） |
| meta 更新 | `coverHref = 'cover.' + ext`、`coverMediaType = mediaType`、`updatedAt` 刷新 |
| 安全 | **不校验尺寸/不重编码**（零依赖、零图像库）；只信魔数 + 大小。注释写明「这是本地单用户场景，不是公网上传口」 |

#### `book.cover.reset`

```
请求  { book: string }
响应  { book: { id, coverHref: null, updatedAt } }
行为  删除 bookDir 下所有 cover.*，meta 里 coverHref=null、coverMediaType=null
```

书架回落：`coverUrl(null)` → 书架显示 `.dr-cover-fallback` 的「无封面」占位（现有 UI 已有）。

### 4.4 封面缓存（换图必须立刻生效）

现状两个坑（§1.6）：`coverBytes` 只读解析产物；URL 无版本号 + `max-age=3600`。

**改法（三处一起改才生效）**

1. `store.coverBytes(bookHash)`（**签名不变**，内部自己 `readMeta`）：读盘优先，解析产物兜底。
   ```
   ① meta.coverHref 存在 → 读 bookDir/coverHref，读到就返回 { bytes, mediaType: inferFromExt(name) }
   ② 否则退回 `parsed.assetBytes(parsed.coverHref)`（导入时从归档里抽的）
   ③ 都没有 → null（route 转 404 E_COVER_NOT_FOUND）
   ```
   `inferFromExt`：`.png→image/png`、`.jpg/.jpeg→image/jpeg`、`.webp→image/webp`、其它 → meta.coverMediaType 或 `image/jpeg`。
2. `routes: cover` 的响应头：`cache-control: private, max-age=0, must-revalidate` + **`etag: "v<updatedAt 毫秒数或 hash>"`**；请求带 `if-none-match` 且相等 → `304`。理由：`max-age=0` 让浏览器每次带 etag 回源，换图立刻生效，且没换图时也只有一个 304 的流量。
3. 版本参数（**两处都要带**，缺一处就有一半路径拿旧图）：
   - 服务端 `lib/store.js:258` 的 `mapShelfItem`：
     ``coverUrl: meta.coverHref ? `/api/dsh-reading/cover?book=${dirName}&v=${encodeURIComponent(meta.updatedAt)}` : null``
   - 客户端 `client/src/api.js:167` **改签名**（下游只有 `shelf.js:125` 一处调）：
     ```js
     export function coverUrl(bookHash, version)  // version 传 book.updatedAt
     ```
     `version` 缺失/空 → **不带** `v` 参数（向后兼容）。
   - `client/src/shelf.js:123-125` 的 `src: coverUrl(book.bookHash)` 改成 `coverUrl(book.bookHash, book.updatedAt)`（shelf item 的 JSDoc 已保证有 `updatedAt`，`lib/store.js:229`）。

> 只做 2 不做 1：换图后磁盘有文件但 `coverBytes` 读不到 → 404 或旧图（这就是 0.3.1 的坑）。
> 只做 1 不做 2：换图 1 小时内还是旧图（用户会以为「没换成」）。

## 6. 【包 C / 需求 F】目录三形态

### 6.1 用什么字段表达来源

**`meta.json` 加可选字段 `tocSource`**（已登记进 schema，§4.5）：

| 值 | 含义 | 例子 |
|---|---|---|
| `'nav'` | EPUB3 `nav.xhtml` 里的目录 | 正规 EPUB3 |
| `'ncx'` | EPUB2 `toc.ncx` | 老 EPUB |
| `'auto'` | **程序识别出来的标题**（TXT 的「第X章」正则命中；转换格式的 `第 N 章`） | 用户最关心的「自动识别」 |
| `'none'` | 没有目录（含 TXT 硬切） | 必须显示「这本书没有目录」 |

旧的 `meta.json` 没有这个字段 → `?? 'none'`（§6.4）。

`book.toc` 的响应结构**加一个字段，不改任何已有字段**：

```json
{ "toc": [ { "label": "第一章", "href": "text/ch1.xhtml", "spineIndex": 0, "depth": 0 } ], "source": "nav" }
```

> 为什么把 `source` 放在响应而不是让客户端读 meta：客户端只有 `book` 摘要，让它自己判断「这是真目录还是硬切」等于把同样的判定写两遍。服务端一次说清。

### 6.2 三个来源怎么判定（各文件改什么）

**`lib/epub.js`**（真目录判定，**顺序不能动**：nav → ncx → spine 假目录）

```js
// 返回值里已有 toc 与 opfDir；新增：
tocSource: navEbookToc.length > 0 ? 'nav' : (ncxToc.length > 0 ? 'ncx' : 'none')
```
- `nav` 解析失败（缺文件/空 nav）→ 继续试 ncx，**不抛错**（现有行为）。
- **都要没有时，现在会按 spine 生成一层假目录**（`第 N 章`）。0.4.0 把它标成 `'none'`：假目录里的 label 不是书里的标题，属于「冒充目录」，§6.3 要求不显示。**保留生成逻辑**（`spineCount`、跳章、进度计算都依赖 spine），只是 `source='none'` 时客户端不渲染成目录。

**`lib/txt.js`**

- 「真识别」判据：`splitChapters` 命中的标题数 **≥ 2** 且**至少一个标题匹配** `^第[一二三四五六七八九十百千0-9]+[章回节卷部篇].*` → `'auto'`。
- 只命中 1 个（通常是首章标题或误匹配）→ 视为**没有**真目录：退回硬切，`'none'`。理由：1 条目录对用户毫无用处，还会把硬切的 `第 N 部分` 混进去。
- 硬切路径（`hardSplit` + `chunkByLength`）→ `'none'`，且**章节 label 保持 `第 N 部分`/`（续 n）` 不动**（它们是翻页导航，不是目录；改它们会破坏已有进度与测试断言）。

**`lib/textbook.js`**（MOBI/AZW3/DOCX 转出来的：chapter 按 spine 切，标题取自身 HTML 的 `h1`/`title`）→ `'auto'`。

**`lib/bookformat.js`** 的 parse 返回值汇总处，把上面三个源的 `tocSource` 透传成 `meta.tocSource`。

**`lib/routes.js`** 的 `book.toc`：`const source = meta.tocSource ?? 'none'`；**当 `source === 'none'` 时返回 `toc: []`**（服务端就把假目录删掉，客户端拿不到就不会误渲染）。

**`lib/store.js`** 的 `toc()`（B 包的 1 行，见 §8.2）：`source: meta.tocSource ?? 'none'`。

## 7. 【包 B / 需求 A】封面尺寸错乱 / 堆叠

### 7.1 根因（已定位，直接写进结论）

三个事实叠加，缺一不成：

1. `style.js:194` 书架网格是 `repeat(auto-fill, minmax(148px, 1fr))` —— **列宽由网格决定，但每个 grid item 的 `min-width` 默认是 `auto`**。
2. `.dr-book` 里的 `.dr-cover-author`（`style.js:297`）是 `white-space: nowrap; overflow: hidden`。**`nowrap` 让内容宽度不收缩**，`overflow:hidden` 只裁显示、不减最小内容宽度。所以「艾伦·莱特曼、布莱恩·R·利特尔…」这种超长作者串把 grid item 的 `min-width:auto` 撑到约 **2 倍列宽**。
3. `1fr` 列可以容纳溢出的 item，于是**卡片向右溢出覆盖邻卡**；`align-items:start` 让高度也不齐。用户看到的「封面大小错乱、堆叠」就是这个。

**不是**图片本身的问题，**不是** `auto-fill` 的问题，也**不是** `object-fit` 的问题。

### 7.2 修法（三处一起改，少一处就复发）

**① grid item 加类并放宽**

`shelf.js` 里包 `BookCard` 的那层容器（现为内联 `style={{position:'relative'}}` 的 `div`）：

```js

// 之后：
h('div', { className: 'dr-book-cell', key: book.id }, h(BookCard, …))
```

```css
/* 0.4.0 封面修复：grid 子项的 min-width 默认是 auto，长书名/长作者会把单元格撑到
   比列宽还宽，于是卡片互相压住。min-width:0 让单元格服从列宽。 */
.dr-book-cell {
  position: relative;
  min-width: 0;          /* ← 头号修复，删了它就回到「封面堆叠」 */
  max-width: 200px;      /* 宽栏时别让单卡无限大 */
  width: 100%;
  margin: 0 auto;        /* 列比 200px 宽时卡片居中，不留半格空白 */
}
```

**② `.dr-book` 自己也加 `min-width:0`（belt & braces）**

```css
.dr-book { min-width: 0; width: 100%; }
```

> 为什么两处都要：`.dr-book` 是 `<button>` 改成 `display:flex` 的，它自己的 `min-width:auto` 同样会按内容顶出去；父格修好、子元素照样能溢出。两处都写，删任一处都能在某个主题/字号下复现。

**③ 作者行与标题行必须可收缩**

```css
.dr-cover-author {
  /* 原来只有 nowrap + overflow:hidden；少了 min-width:0 与 text-overflow，
     它在 flex 里既不被压缩，也不显示省略号。 */
  min-width: 0;
  max-width: 100%;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
.dr-book-title { min-width: 0; }   /* 标题行同样处理，多行截断已有 line-clamp 就不动 */
```

**④ 封面容器与图片（顺手把「尺寸错乱」的另一半钉死）**

```css
.dr-cover {
  position: relative;
  width: 100%;
  aspect-ratio: 2 / 3;       /* 统一 2:3，全部同高 */
  overflow: hidden;
  border-radius: 8px;
  background: rgba(0, 0, 0, .05);
}
.dr-cover > img {
  position: absolute; inset: 0;
  width: 100%; height: 100%;
  object-fit: cover;         /* 不拉伸、不留白边 */
  display: block;
}
```

> `aspect-ratio` 与 `object-fit` 若现有代码已经这么做（`.dr-cover` 已有固定高度或 padding-top 比例），就**只补缺的那条**，不要写两套互相打架的规则——改之前先 `read` 一遍 `style.js:232-300`。

### 7.3 窄栏/宽栏两档断点

```css
/* 窄栏（手机/窄侧栏）：列更小，作者行只留 1 行 */
/* 复用 style.js:1034 已有的 @media (max-width: 720px) 断点，不要新建 520px 断点：
   同一件事有两套断点，改一处忘一处就会出现「窄窗口又堆叠」。*/
@media (max-width: 720px) {
  .dr-grid { grid-template-columns: repeat(auto-fill, minmax(120px, 1fr)); gap: 10px; }  /* 原样，别改成 118 */
  .dr-book-cell { max-width: none; }        /* ← 新增这一行 */
}
/* 宽栏（桌面大屏）：卡片有上限，整行居中，不出现「一列特别宽」 */
@media (min-width: 1100px) {
  .dr-grid { grid-template-columns: repeat(auto-fill, minmax(160px, 1fr)); gap: 16px; }
  .dr-book-cell { max-width: 184px; }
}
```

**不许把 `auto-fill` 改成 `auto-fit`**：`auto-fit` 会把空列折叠，列表不满一行时卡片被拉成超宽——正是用户抱怨的「大小错乱」的另一个版本。

## 10. 风险与「本轮不做」

| 风险 | 缓解 |
|---|---|
| `auto-fill` 列宽随窗口变化，极端窄宽下卡片 < 120px | 沿用现有 `minmax(120px,1fr)`；再窄就一列（`auto-fill` 自然退化为单列） |
| 书里 `<a>` 包着整段图片（图链接） | 拦截器不区分内容，点击照样跳；这是对的（图链接也是链接） |
| 某些 EPUB 的 nav 里链到 `href="#"` | 走 §2.4 第 7 步：原地定位，`findAnchor('')` 返回 null → 停章首，无副作用 |
| 封面 3 MiB 上限对超清封面偏紧 | 前端选图前就提示，用户可先压图；上限写在 §4.2 表，改一个常量即可 |
| `coverBytes` 改读盘后，与导入时归档里的封面条目可能不一致 | 读盘优先即可：磁盘才是用户编辑后的真源 |
| iframe 内 `pointerdown` 被 `<a>` 默认手势吃掉 | 我们在 `click` 上 `preventDefault`，`pointerdown` 只做判定；两者不冲突 |
| 老 TXT 书的目录「消失」（§6.4） | 这是需求本身；README 写明 |

**本轮不做**：`qa.delete`（契约已留）、问 AI 草稿持久化、WebDAV/手机端、封面裁剪/重编码、目录搜索、多级目录折叠记住展开态。
