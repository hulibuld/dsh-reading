## 以后怎么记

想让它变准，就从下一个版本起在提交信息里分开写：修 bug 的用「fix:」开头，加功能的用「feat:」。现在这张表只能靠人读，分不出哪条是修。

1. 修复版本：改了 `package.json` 的 version 就算一个新行。
2. 修复日期：提交日期。
3. 现象：用户看到的是什么。
4. 原因：能说清才写，说不清写「未记录」。
5. 提交：短 SHA。
