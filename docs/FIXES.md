# 已知问题与修复记录

本表只收**能追溯到提交的修复**。三点先说清：

- **日期是修复提交的日期**，不是 bug 首次出现的时间。这个仓库没有开过 issue，提交信息里也很少写「从哪个版本开始坏」，所以「出现时间」多数还原不出来，不填。
- **原因只写提交里写明的**。写不出的标「未记录」，不猜、不补。
- **版本按最近一次改 `package.json` 的提交归属**，也就是这个修复第一次随哪个版本发出去。

## 以后怎么加一行

修完一次就加一行，别攒着——攒三个月再回忆，原因那一列就只能写「未记录」了。

1. 修复版本：改了 `package.json` 的 version 就算一个新行。
2. 修复日期：提交日期。
3. 现象：用户看到的是什么，不写技术描述。
4. 原因：能说清才写，说不清写「未记录」。
5. 修复方式：一句话说清动了什么。
6. 提交：短 SHA。
