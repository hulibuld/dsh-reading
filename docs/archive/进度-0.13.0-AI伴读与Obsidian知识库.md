## 这一版要解决什么

起因是抖音「清华姜学长」那条「workbuddy + obsidian 搭 AI 伴读助手」的视频
（419 秒，字幕全文已整理在 `docs/调研-姜学长AI伴读助手视频字幕.md`）。他的玩法一句话：
**一本电子书 + 一段提示词，在当前文件夹里长出四类 Markdown**，而且每次讨论完自动写回。

dsh-reading 缺的正是这最后一步：蒸馏稿只能「下载 .md」到浏览器的下载目录，落地就死。
这一版把它接上一个出口——写进用户自己的 Obsidian 库，并补上视频里没做的一半：
**读者的「问 AI」记录本身就是素材**，拿它决定笔记该写给谁。

三条不做的边界（`docs/26 §一`，已落进代码注释）：不双向同步、不装 Obsidian 插件、
不把 vault 里已有的读书笔记当原文喂给 AI。

## 已完成（按 P0–P6）

### P0 · 锚块协议与库写入（`lib/blocks.js` 356 行 + `lib/vault.js` 440 行）

`blocks.js` 是纯函数：把一份 Markdown 解析成「块外归用户、块内归插件」的区间表，
渲染同一个块一万次字节都一样（时间戳来自记录而非 `now()`），只在块的区间内替换。
不做 Markdown 语法解析，只认 HTML 注释标记；缺 `end` 的块一律视为「文件可能被手改过」，拒绝重写。

`vault.js` 是本插件唯一碰用户笔记目录的地方，四条铁规矩写死在文件头：
原子写（`.tmp` + rename）、覆盖前备份到 `.history/` 留 20 份、路径必须在库内
（用 `base + sep` 前缀比对，不用裸 `startsWith`）、UTF-8 无 BOM + `\n` + 结尾一个换行。

库的自动发现读 Obsidian 自己的 `obsidian.json`，只取路径与名字。
`vault.choose` 会真写一次 `dsh-reading/` 目录做可用性确认——只 `stat` 挡不住「目录在但只读」。

### P1 · 地图与笔记两类产物（`lib/notesync.js` 661 行）

`relPathsOf` 返回四个键 `{map, note, relations, threads}`，路径形如
`《书名》 <短哈希>/《书名》 00 全书地图.md`（短哈希 = `sha256(bookHash)` 前 10 位）。
块 id 来自来源记录（一条 qa 一个、一章蒸馏一个、一条标注一个），**不是序号**——
序号一插入就全体错位，后果是用户改过的那段被后面的新内容顶掉。

三条冲突处理：台账里 `deletedByUser` → 永不复活；`userEdited` → 跳过并 `conflicts+1`；
文件里块没了 → 记 `deletedByUser`。文件不存在时先写只有 header 的骨架
（注释写明：不先写标题的话用户打开看到的第一个字就是 HTML 注释）。

### P2 · 问完自动写回（`lib/routes.js` 的 `autoWriteQa`，:248）

挂在 `qa.ask` 返回之前跑完。三个刻意的取舍，注释里逐条写明：
**只写 01 不碰 00 地图**（重算整张地图会把你改过的段落推进 hash 冲突）、
**复用 `applyPlan` 不另开写文件通道**（锚块协议、手改保护、备份全在那一处）、
**没配库或关开关就静默跳过**（`{skipped:true, reason:'off'|'no-vault'|'no-file'}`，这不是失败）。

写失败只 warn，绝不把答案一起弄丢。

### P3 · 侧栏「笔记」页签 + 书架角标（`client/src/notes.js` 665 行 + `CSS_NOTES`）

阅读器工具栏「问答」右边多一个「笔记」（`sideKind='companion'`，
`client/src/reader.js:1692-1707`）；书架书卡上有「笔记 N」角标
（`client/src/shelf.js:282` 读 `book.notesCount`，>99 显示「99+」，
点开 `client/src/app.js:2270 onNotes` 先 `openBook` 再 `setSideKind('companion')`——
顺序不能反，先 openBook 才有 bookHash）。

面板六张卡：画像 / 我写过什么 / 文件清单 / 人物关系 / 思想脉络 / 库路径与三个按钮 + 预览。
`notes.js` 里 11 个导出全是可单测的纯函数（`fileStatusText` / `notesSummary` /
`profileText` / `relationsNotice` / `candidateText` …）。

### P4 · 读者画像（`lib/profile.js` 315 行）

从这本书的 `qa.jsonl` 算：问得最多的模式、反复出现的主题词、常问章节。三条硬约束：
只进结论不进原文、零 AI 也能算、数字必须是真的。

主题词只留「在 ≥2 个不同问题里出现过、长度 ≥2、不以虚字开头结尾」的（`MIN_DF=2`、
`EDGE_CHARS`），最多 8 个；只看最近 30 条（`RECENT_QA=30`），让新词能顶上来。

画像注进三处 prompt：`distill.chapter`（routes.js:1035）、`distill.skeleton`（:1129）、
`relations.build`（:1585）。每处都跟一句「宁可少一条，也不要为了贴合他而改动原文」。

### P5 · 人物关系 + 跨书主题（`lib/relations.js` 550 行 + `lib/threads.js` 417 行）

`relations` 四件事按重要性排：**每条边必须带原句**（`verifyEdges` 拿回章节正文 `indexOf`
核对，核不上就丢掉并报数）、**只在小说上做**（`fictionVerdict` 判不出来就不生成）、
**分批抽可续跑**（`MAX_SOURCE_CHAPTERS=24` / `MAX_BATCH_CHARS=8000` / `MAX_BATCHES=8` /
`MAX_PERSONS=40` / `MAX_EDGES=120`）、**同一个人只有一个节点**（按别名并进已有节点）。

整张图是一个块（`rel-body`），不拆成「一人一块」——关系是整体语义，拆开会出现
「你改过的张三那段留着、李四那段被重写」的割裂图。

`threads` 机械聚类不调 AI（理由不是省钱：模型判「是不是同一主题」每次答案都不一样，
用户第二次点开候选列表就换了，没法信任）。三道门槛 `MIN_BOOKS=2` / `MIN_BLOCKS=3` /
`MIN_HITS_IN_ONE_BOOK=2`。落盘在 `<vault>/dsh-reading/_主题/<主题>.md`（**全局一份**，
不是每本一个目录）+ `_索引/主题总览.md`。「我现在的判断」那一节永远留空。

### P6 · 反向读「我写过什么」（`lib/mynotes.js` 112 行）

只读文件名与一二级小标题，正文一个字都不往外送；`MINE_MAX_FILES=200` / `MINE_MAX_HEADINGS=40`。
不建索引、不存台账——用户随时可能在 Obsidian 里改名删页，再存一份索引两者一不一致界面就开始撒谎。
插件自己写的块（`dsh-reading:block` 之间）单独计数，那些 `## 第三章` 是程序加的，
不冒充成「你写过的」。

### P7 · 书源可以贴链接导入

原来只有「整包粘进文本框」和「选 .json 文件」两条路，而真实的整包书源有 1–21 MB——
粘贴这条路实际上走不通。现在 `source.legado.import` 收 `{url}` 这个形状：

| 常量 | 值 | 依据 |
|---|---|---|
| `SOURCE_IMPORT_TIMEOUT_MS` | 180 s | 实测一份 20.01 MB 的书源完整抓完要 109 s，原 60 s 会误判成失败 |
| `SOURCE_IMPORT_MAX_BYTES` | 32 MB | 真实整包 1–21 MB，24 MB 只剩 3 MB 余量 |
| `LEGADO_TIMEOUT_MS` | 20 s | 单次请求自己的超时，不变 |

抓取在 `lib/routes.js` 的 `fetchSourceText`（:1982），体积闸门先看 `content-length`，
超了直接拒、不把整包拉下来；没有这个头的站点走 `for await (const chunk of response.body)`
流式累加，超了当场断。三种失败各自说人话：`E_SOURCE_BAD_URL`（不是 http(s)）/
`E_LEGADO_NOT_JSON`（抓回来是网页）/ `E_SOURCE_TOO_BIG`（太大），错误文案里
**不许出现 `maxBytes` / `content-length` / 内部域名**，这条已写进 e2e 断言。

界面上「导入书源」折叠区顶部多一行输入框 + 「从链接导入」（`client/src/legado-ui.js:112 doImportUrl`），
回车也能提交；整包粘贴降级成「另一种给法」。

## 下一步（真机，需要重启 DSH）

1. 重启 DSH（插件是软链，宿主加载的是内存里的旧代码）
2. 打开任一本书 → 点工具栏「笔记」→ 面板应出现，此时「没选库」的引导态要能看明白
3. 点「选择库」→ 选中 `~/Documents/knowledge base` → 确认 `dsh-reading/` 目录真的被建出来
4. 点「同步全书地图 + 读书笔记」→ 打开 Obsidian 看两个文件是否出现、块标记是否完整
5. **在 Obsidian 里手改块外一行，再同步一次** —— 你改的那行必须还在（这是整份设计的地基）
6. **手改块内一行，再同步** —— 面板应报「有 1 段你改过，我没动」，且块内不被覆盖
7. 圈一段话问 AI → 回 Obsidian 看答案是否自动落进对应章节（默认开）
8. 连问 5 个以上问题 → 回面板看画像卡的数字是否与实际提问一致
9. 找一本小说 → 点「抽人物关系」，跑一批看 Mermaid 是否出图、有没有「原句核不上，丢掉 N 条」
10. 拿两本都问过同一个词的书 → 看「思想脉络」候选里是否出现它

**真机没验过的地方**：Obsidian 对 `<!-- -->` 注释的折叠表现、大库（几千页）下
`notes.mine` 的耗时、中文书名在 macOS 上的 NFC/NFD 目录名一致性。
