## 一、要交付什么

1. **问 AI 有五个模式可选**，圈一段原文问 AI 时能切换，人设与回答要求各不相同，问答记录与 AI 账本里能看出用的是哪个。
2. **五个阅读 skill 随包内置**（含原有 `reading-coach`），装好插件重启，聊天里就能用，不需要用户另装、另配目录。
3. **开箱即得**：`npm pack` 的 tarball 与 GitHub clone 里，`skills/` 与 `lib/askpresets.js` 都在。

## 三、五个问 AI 模式

| id | 面板显示 | 给谁用 | 人设内核 | 回答要求差异 |
| --- | --- | --- | --- | --- |
| `general` | 一般问答 | **默认** | 耐心的读书助手（**逐字等于现状**） | 现状四条不变 → 老行为零变化 |
| `classic` | 名著精读 | 读文学名著 | 懂文学的读者：这句话在整本书里的位置、写法、语气、时代语境 | 许引原文、许点笔法；≤300 字；**禁剧透**加强 |
| `paper` | 论文分析 | 读论文 | 审稿人视角：分清「作者声称 / 证据支持 / 我的推断 / 论文没覆盖」 | 要给 Claim、证据、缺口；≤400 字；**禁把摘要复述当结论** |
| `concept` | 概念溯源 | 碰到术语/典故 | 词典与思想史的路子：词从哪来、谁先这么说、在这本书里什么意思 | 区分「通行含义」与「本书用法」；≤300 字 |
| `foreign` | 外文原著 | 读英/日/法等原著 | 双语读者：先照原文读，再给中文落点 | 关键句给原文 + 一种译法；术语给中英对照；≤350 字 |

`general` 的 persona 与四条要求**逐字沿用现状**，这是向后兼容的锚点，也保证 `test/ai_test.mjs` 那三条断言自动继续过。

## 四、五个内置 skill

| skill 名 | 干什么 | 触发话术 | 来源 |
| --- | --- | --- | --- |
| `reading-coach` | 陪读教练（**已有，不动**） | 陪读 / 阅读教练 / 带我读这本书 | 原有 |
| `book-analysis` | 名著解析：结构 / 人物 / 视角 / 语言 / 文学史位置，每维挂原句。**不做读后感、不做摘要** | 分析这本书 / 拆一下这本名著 / 这本书好在哪 | 自写 + 借 GitHub 骨架 |

## 五、实现方案

### 5.1 预设数据：新建 `lib/askpresets.js`

纯数据 + 三个纯函数，不碰 IO：

```js
export const ASK_PRESETS = [ {id, name, description, persona, requirements:[…], maxChars}, … ]
export const DEFAULT_ASK_PRESET = 'general'
export function listAskPresets()   // 给前端/路由的精简列表（含 name/description，不含 persona 正文）
export function pickAskPreset(id)  // 未知 id 一律退回 general，不抛
export function buildAskPromptWith(preset) // 可选：把要求拼装抽出来
```

### 5.2 改 `lib/ask.js`

- `buildAskPrompt(input, preset = pickAskPreset(input?.mode))`：开场换 `preset.persona`；尾部「回答要求」换 `preset.requirements` 编号列表；**书名/位置/上下文/原文/问题几段一字不改**。
- `ask(input)`：读 `input.mode` → `pickAskPreset` → 传入 `buildAskPrompt`；record 带 `mode`。
- `complete(input)`：`request` 里加 `persona`（仅当非空）；其余不动。

分工：persona 进系统提示（管「你是谁、用什么眼光」），requirements 进用户消息（管「这次输出成什么样」），**两处内容不重复**。

### 5.3 改 `lib/routes.js`

- `qa.ask` 多一行 `mode: typeof body?.mode === 'string' ? body.mode : ''`。
- 新增 `ask.presets` 返回 `listAskPresets()`，前端不硬编模式表。

### 5.4 改 `lib/store.js`

- `mergeSettings` 加 `aiAskPreset`（≤32 字，空串合法 = 用默认）。记住上次选的模式。

### 5.5 改 `lib/aicall.js`

- `meta()` 加 `mode`，账本 `ai-calls.jsonl` 能看出每次用的模式。

### 5.6 前端

- `client/src/app.js`：`askMode` state（初值取 settings 的 `aiAskPreset`）；payload 加 `mode`；渲染 `AskPanel` 传 `mode`/`onModeChange`/`presets`。
- `client/src/annotate.js`：`AskPanel` 头部 `AiModelBar` 旁加原生 `<select>`，选项来自 `ask.presets`，选完写回 settings。
- 构建守卫：自定义 CSS 属性只许 `--dsw-alias-*`/`--dsw-radius-*`/`--dsh-reading-*`，每个 `var()` 必须带 fallback，禁 `prefers-color-scheme` 与 `oklch()`。

### 5.7 skill 批量注册：新建 `lib/skillbundle.js`

- `listSkillDirs(root)` 扫 `skills/` 下含 `SKILL.md` 的子目录，**按目录名排序**（顺序稳定 → 测试稳定）。
- `registerAllSkills(ctx, {logger})` 逐个 register，单个失败只 warn，不拖垮其他。
- 保留 `lib/coachskill.js` 现有导出不变（`test/coach_skill_test.mjs` 依赖）。
- `index.js:90` 换成 `registerAllSkills(...)`。

### 5.8 新 skill 目录

`skills/<name>/SKILL.md` + `skills/<name>/references/*.md`。
**frontmatter 只认 `name` 与 `description` 两行，一行一个 key: value，description 不能换行**——`splitFrontmatter` 只支持这个子集，违反就注册失败。
`package.json.files` 已含 `skills`，不用改。

### 5.9 文档

- `docs/24-问AI模式与内置skill.md`：有哪几个模式、哪几个 skill、怎么触发、加模式改哪个文件。
- `README.md:357` docs 索引表加一行。
- `CHANGELOG.md` 新开 `[0.11.0]`，分「新增 / 测试」。
