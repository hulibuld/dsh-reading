写于 2026-11-12。上一版计划书（问 AI 五模式与四个阅读 skill，0.11.0）已归档到

## 一、要交付什么

给 reading 插件加一条**知网文献检索**渠道。用户在「导入图书」面板里输入一个词，
直接看到知网上的论文列表，每条带标题、作者、期刊、年期、被引次数、下载次数、
摘要开头，并且能一眼看出**这篇本地书库里有没有**。勾选几条，一键存成一本
「文献集」进书架——打开就能划线、能问 AI。

不解决的事：不自动登录、不存密码、不下载全文。这三条在第四、五节讲清原因。

三条验收：

1. 在插件里搜「滑坡」，按被引排序，能出 20 条真实知网结果，字段齐全。
2. 把其中三条勾选存成文献集，书架上出现一本新书，打开有目录、有正文、能划线。
3. 在文献集里选中一段问 AI，选「论文分析」模式，能拿到四档判决格式的回答。

## 二、现状勘察（全部本机实测，行号为当前值）

### 2.1 知网哪些入口能用

| 入口 | 结果 | 说明 |
| --- | --- | --- |
| `POST search.cnki.com.cn/search/listresult` | **200 可用** | 老版免费检索站，返回 HTML 片段，每页 20 条 |
| `GET search.cnki.com.cn/Search/Result` | 200（壳） | 结果由 JS 异步填，壳里没数据 |
| `POST search.cnki.com.cn/api/search/listresult` | **504** | 页面 JS 用的是这个，挂了 |
| `kns.cnki.net/kns8s/defaultresult/index` | **302 → 极验滑块** | 现代检索，裸 HTTP 100% 挡死 |
| `pay.cnki.net/zscsdoc/download` | **302 → 登录页** | 全文下载要登录 |
| `www.cnki.com.cn/Article/CJFDTOTAL-<FN>.htm` | 200 | 免费详情页，摘要恒定截断 128 字 |
| 百度学术 / 维普 / 万方 | 403 / 412 / JS 渲染 | 都不可用 |

### 2.2 检索接口的准确行为（实测 100+ 次）

- 请求：`POST https://search.cnki.com.cn/search/listresult`，
  `content-type: application/x-www-form-urlencoded`，
  body 形如 `Title=滑坡&Order=4&page=1`。带 `x-requested-with: XMLHttpRequest` 更稳。
- 响应：`200`、约 20–113KB、`content-type: text/html;charset=UTF-8`（不用猜 GBK）、
  耗时 0.2–1.9s、**连发 10 次不触发限流**。
- 单页固定 20 条；`page=500` 仍有效（真实深度未知，要自设上限）。
- 空结果返回 449 字节 `<div class="no-result">`。

**四种找法与参数的对应**：

| 面板显示 | 参数 | 实测效果 |
| --- | --- | --- |
| 经典文献（被引最高） | `Title=词&Order=4` | 被引单调不增，翻 5 页零重复 |
| 最新发表 | `Title=词&Order=2` | 首条被引 0、当日文献 |
| 相关度 | `content=词&Order=1` | 标题词命中率高，会混出学位论文 |
| 高下载 | `Title=词&Order=3` | 下载数单调不增 |

**必须知道的坑**：`Order=4` 是**全局排序不是先筛后排**。`content=滑坡&Order=4`
20 条里只有 4 条标题真含「滑坡」，其余是「业绩滑坡」。所以「经典文献」这个
找法**必须用 `Title=`**，用 `content=` 会拿到跨学科意外结果。
实测 `Title=滑坡&Order=4` 是 39/40 命中，`content=滑坡&Order=4` 是 4/20。

**覆盖范围**：
- `Title=` / `Theme=` 只出期刊（host 恒 `www.cnki.com.cn`）。
- `content=` 才混出学位论文（`cdmd.cnki.com.cn`）与会议（`cpfd.cnki.com.cn`）。
- 类型由结果里 `p.source` 末尾那个裸 `<span>` 给出，实测四种：期刊 / 硕士论文 /
  博士论文 / 中国会议。
- `Year=2024` 单值生效；`Year=2024|2025` 只认第一个。
- `Type=` / `Subject=` / `Level=` 传任何值都无效，**不能承诺按类型/学科筛选**。

### 2.3 结果条目结构（解析器已跑通 3 种 query）

按 `<div class="list-item">` 切块，块内抓：

| 字段 | 取法 |
| --- | --- |
| 标题 + 链接 | `p.tit > a.left` 的 `title` 与 `href`（协议相对要补 `https:`；标题要剥高亮 `<span>` 与 `&nbsp;&nbsp;CNKI文献` 尾巴） |
| 作者 | `p.source` 内 `<a data-key="...">` 的**标签内文字**（`data-key=""` 的空 a 要滤） |
| 期刊 | `p.source` 内 `《...》` |
| 年期/日期 | `p.source` 内 `<span>` 包住的 `2007年03期` 或 `2021-03-13` |
| 类型 | `p.source` 内**最后一个** `<span>` |
| 关键词 | `p.info_left` 第一个 `data-key` 按 `/` split |
| 被引 / 下载 | `span.time2` / `span.time1` 里的数字 |
| 摘要开头 | `p.nr`（正文开头片段，不是摘要） |
| 文件名 | 块尾 `div.checkbox1[data-fn]` |

实测缺失统计：期刊 query 全字段 0 缺失；学位论文 query 的 `journal` 必然为空
（20/20），属正常，界面要能空着显示。

### 2.4 造书链路（已端到端跑通）

```
题录数组
  → writeZip(mimetype + container.xml + OPF + nav.xhtml + N 个 XHTML)
  → Buffer（字节稳定，mtime 固定 Date.UTC(2020,0,1)）
  → parseEpub → meta/toc/spine 全对，tocSource='nav'，目录标签是中文
  → store.importBook({filename, dataBase64}) → 书架出现，可读
```

实测：1907 字节的包能被完整解析；加 nav 后 2477 字节，目录是
`[{label:'1. 大型滑坡实例研究', href:'text/ch001.xhtml'}]` 而不是 `c1`。
同字节重复导入幂等（bookHash 相同）。

**注意**：`buildReflowedBook` 不出 ZIP 字节（它只做内存虚拟书），所以造书
必须走 `lib/zip.js writeZip` + `lib/epub.js parseEpub` 这条，不能用它。

## 三、方案

### 3.1 三件事

**第一件：检索。** 内置知网检索，零配置，不登录也能用。

**第二件：结果看得懂、用得上。**
- 每条显示：类型徽章 · 标题 · 作者 · 期刊年期 · **被引 N · 下载 N** · 摘要开头
- **书架里已经有这篇的，打一个「已在本地」角标**
- 三个动作：打开知网页 / 复制题录 / 勾选

**第三件（「再往前一步」）：把检索结果变成能读能问 AI 的书。**
勾选几条 → 一键存成「文献集」→ 书架上多一本可读的书 → 打开划线、问 AI。

这一件是这次真正往前迈的那一步。前面两件只是「检索」，第三件才让它接上
0.11.0 已经做好的五个问 AI 模式和四个阅读 skill——检索出来的论文，能直接用
「论文分析」模式拆，能直接跑 `paper-reading` skill 的四档判决。

### 3.2 四种找法为什么这么设计

用户找论文有两种真实处境：

- **「这行里的经典是哪几篇」** → 经典文献（被引最高，`Title=` 保证不跑偏）
- **「最近有什么新东西」** → 最新发表
- **「我知道要什么，但不知道怎么表述」** → 相关度
- **「大家都下什么」** → 高下载

四种覆盖四种提问方式，界面上用中文直说，不露参数。

### 3.3 文献集长什么样

一本 EPUB，目录是每篇论文，正文每章是：

```
<原告标题>
作者 · 期刊 2024年05期 · 被引 128 · 下载 3021
文献类型：期刊 / 硕士论文 / 博士论文 / 中国会议
关键词：滑坡 / 预警 / 位移
原文：https://www.cnki.com.cn/Article/CJFDTOTAL-XXXX.htm
摘要开头（知网免费给的前 128 字以内片段，如无则写「知网未提供摘要片段」）
```

**摘要这里必须诚实**：知网免费详情页的摘要恒定截断在 128 字，这不是我们能
绕过的。文献集里就写片段，并明确标注「片段，非全文摘要，完整摘要需登录知网」。

不给用户造成「这是完整摘要」的错觉。

### 3.4 「已在本地」怎么判

不需要新字段，用 `listShelf()` 拿到的 `title` 与 `author` 做归一比对：

```js
归一 = 转小写 → 去所有空白 → 去掉《》〈〉""''、，。：；！？（）()【】[]—-_/·
```

标题归一后相等就判「已有」。**只做提示，不做拦截**——用户可能确实想要一份
文献集版本。作者只作辅助参考，不强求相等（知网上的作者写法与 PDF 里的常不一致）。

### 3.5 三个动作

| 动作 | 做什么 | 为什么这样 |
| --- | --- | --- |
| 打开知网页 | `window.open(原文链接)` | 全文下载要登录，插件不碰登录态，交给用户自己的浏览器 |
| 复制题录 | 生成 Markdown 到剪贴板 | 用户要写文献综述时直接粘给 AI，不用手抄 |
| 勾选存成文献集 | 勾几条 → 起个名 → 生成 EPUB 入库 | 把一次性检索变成可反复读的资产 |

复制题录的 Markdown 格式：

```markdown
- 《20世纪以来中国的大型滑坡及其发生机制》. 黄润秋. 岩石力学与工程学报, 2007年03期. 被引 3019, 下载 27027.
  https://www.cnki.com.cn/Article/CJFDTOTAL-YSLX200703000.htm
```

### 3.6 接口设计

| 方法 | 入参 | 返回 |
| --- | --- | --- |
| `paper.search` | `{query, field, order, year, page}` | `{items:[...], page, query, empty}` |
| `paper.collect` | `{title, items:[题录数组]}` | `{bookHash, title}` |

`paper.search` 的 `field`：`title`（经典/最新/高下载用）或 `content`（相关度用）。
`empty`：没搜到时为 `true`——**空结果是 200 + `empty:true`，不是错误码**，界面自己渲染空态。
`order`：1–4。`year`：四位年份字符串，空则不筛。`page`：1 起，上限 20。

**不设 `paper.schools` / `paper.school`**——用户明确不做学校直登入口那一层。

错误码（都是 `AppError`，否则用户只看到 500）：

| 码 | 文案 |
| --- | --- |
| `E_PAPER_QUERY` | 先输入要搜的主题词。 |
| `E_PAPER_FETCH` | 知网这会儿没回应，过一会儿再试。 |
| `E_PAPER_EMPTY` | 知网没搜到相关的文献，换个词试试。 |
| `E_PAPER_COLLECT` | 文献集没做成，可能是这几条题录不完整。 |

### 3.7 拆分：网络与解析分开

`lib/cnki.js` 两个导出，**解析是纯函数，网络是可注入的**：

```js
export function parseCnkiResults(html)          // 纯函数，单测只测它
export async function searchCnki(params, deps)  // deps.fetch 可注入，测试给假 fetch
```

这样单元测试不联网、不依赖知网还活着。fixture 用本机实测存下的真实响应。

## 四、为什么不自动登录

用户给过 `~/carsi-bridge/` 做参考，那是他自己的个人脚本：Playwright 驱动本机
Chrome、自动填表登录、自动下 PDF、launchd 每天凌晨跑。做法本身没毛病，但装到
别人机器上的插件不能这么做：

1. **零依赖。** 插件现在 `dependencies: {}`，一个运行时代码包都不带。塞 Playwright
   要几百 MB，每个装插件的人跟着下。
2. **密码必须真实浏览器填。** 金智 authserver 的密码由页面自己的 `encrypt.js`
   用动态盐加密后写隐藏字段再提交，`fetch` 拼 POST 一定失败。而驱动浏览器在
   DSH 插件里没有可靠的跨平台实现。
3. **合规。** 知网风控会封整所学校出口 IP、可能停用学号。自动化批量下载不是
   插件该替所有人干的事。

所以插件的边界是：**检索我来，登录和下载你自己来。** 界面上把这条说清楚。

## 五、明确不做

- 不自动登录知网 / 不内嵌浏览器 / 不存账号密码 / 不存 cookie

- 不承诺按文献类型 / 学科 / 研究层次筛选（这三个参数实测无效）

- 不做学校直登入口那一层（用户 m01872 明确砍掉）
- 不发 npm、不推 GitHub（对外动作用户自己发起）

## 九、我理解的「再往前一步」
