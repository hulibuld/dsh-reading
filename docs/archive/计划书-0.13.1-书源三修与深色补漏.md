# 计划书 · 0.13.1 书源三修 + 深色补漏

写于 2026-11-21。上一版计划书（知网文献检索，0.12.0）已归档到 `docs/archive/计划书-0.12.0-知网文献检索.md`。

---

## 一、要交付什么

这一版做两件事：**把书源这一摊收拾干净** + **把深色下漏出来的白卡片补掉**。
先说书源：现在仓库里同时躺着两套互不相干的书源机制——
0.5.1 的「网页模板」书源（存在 `settings.bookSources`，最多 8 条）和 0.9.0 的 Legado 书源
（存在 `legado-sources.json`，你盘上现在 2583 条）。两套并存的结果是：界面上有两个「找书」入口、
两条错误码链、一套只能放 8 条而另一套没人管的清理逻辑。

顺带修第二件事：**深色主题下笔记面板漏出白卡片**。这不是书源面板的问题（30 个类逐条验过，
见 2.9），而是四个变量名写了但从来没定义，`var()` 静默取字面浅色兜底（见 3.6）。
修法三行定义 + 一处改名，不碰主题引擎。

不解决的事：不新做书源规则引擎、不改 Legado 解析器、不做书源的云端同步、不给 `.dr-root`
加 `data-theme`——这些在第四、五、3.6 节讲清原因。

四条验收：

1. 左上角「书源」按钮是唯一入口；「导入图书」弹窗里那截「③ 找书」整段消失，导入弹窗只剩三条路。
2. 往面板里贴一个 20MB 的 Legado 整包，能导进去不再报「出了点问题」；导入完自动清掉用不上的源，
   正在读的网络书一本都不坏（读那一章仍能抓到）。
3. 书源面板打开时，网络请求从 3.66MB 降到 300KB 以内；所有宿主错误码在界面上都是一句中文，
   不再出现「出了点问题，请稍后再试」。
4. 切到 DSH 深色主题：笔记面板的行、Markdown 预览块、四张画像卡都不再是白卡片；
   书源面板不出现除遮罩外的任何字面颜色。

### 2.3 「可用」到底怎么判

唯一权威出处是 `lib/legado.js:832-835`，`searchSource()` 进来先两道硬闸：

```js
if (!source.searchUrl) throw new Error(`「${source.name}」没有填搜索地址`)
if (!source.ruleSearch.bookList) throw new Error(`「${source.name}」没有填搜索结果列表规则`)
```

按这条判据实测本机数据：

| 分类 | 条数 |
| --- | --- |
| 可用（searchUrl 非空 **且** ruleSearch.bookList 非空） | 2041 |
| 不可用 | 542 |
| `enabled === false`（用户主动停用） | 36 |
| 停用 ∩ 不可用 | 4 |

**必须知道的坑**：不可用不等于「坏了」。这 542 条导入后用 `searchSource` 一定会 throw，
但它们的 `ruleToc` / `ruleContent` 可能仍然是好的——只是没有搜索入口。清掉它们不影响任何已有书的阅读，
因为进入书架的书走的是 `tocOfSource` / `contentOfSource`，不经过搜索闸。

### 2.4 清理最怕弄坏什么

`lib/store.js:1108` `addFromSource` 往 meta 里写 `sourceUrl`；
`lib/store.js:1143` 读章节时反查：

```js
const source = (await this.listLegadoSources()).find((item) => item.url === meta.sourceUrl)
if (!source) throw fail('E_SOURCE_MISSING', '读这一章需要用到当初导入的书源，但它被删掉了。重新导入书源即可。')
```

所以**清理必须排除掉被任一本书 meta 引用的源**，否则正在读的网络书当场断掉。
store 里没有「批量读全部 meta」的方法，只有 `this.paths.listBookDirs()`（`lib/paths.js:145`）
和 `this.readMeta(bookHash)`（`lib/store.js:829`）——清理逻辑得自己遍历，写法照抄
`listShelf()`（`lib/store.js:731-740`）。

本机当前 10 本书`sourceUrl` 全是空串（没有一本是网络书源来的），所以保护逻辑今天跑起来是空转，
但这正是要靠测试钉死的地方——测试里造一本引用了源的 meta。

### 2.5 为什么大包导不进来

`lib/routes.js:2170`：

```js
const limit = rest === 'shelf.import' ? importLimit : defaultLimit
```

`importLimit`（`:2127`）是 200MiB 折算 base64 后的量，专给 `shelf.import`；
`defaultLimit`（`:2128`）是 `8 * 1024 * 1024`。`source.legado.import` 掉进后者。
超限时 `readBody`（`:176-198`）抛 `E_BODY_TOO_BIG`。

## 三、方案

### 3.1 四件事

**一、砍掉老书源，只留 Legado。** 删 `settings.bookSources`、`source.search` 路由、
`shelf.js` 的「③ 找书」整段、`sources.js` 的四个纯函数与 `routes.js` 的 `fetchPage`。
留 `decodeEntities` / `guessFilename` / `sanitizeName` / `ensureExtension`（`shelf.importUrl` 猜文件名还要用）。

**二、导入后自动清理，但保护被引用的源。** 新增 `store.pruneLegadoSources()`：
清「不可用」（`searchUrl` 空 或 `ruleSearch.bookList` 空）与「已停用」（`enabled === false`），
**但要先把全部书的 `meta.sourceUrl` 收集起来，命中的一条不动**。
`source.legado.import` 成功后顺手调一次，结果塞进返回体 `pruned: { removed, protected }`，
面板 notice 里透出来。

**三、大包走大限额 + 错误码统一解包。** `lib/routes.js:2170` 加 `source.legado.import` 分支
（32MB）；`humanizeError` 在查表**之前**先做一次通用解包。顺带修一处自己把机器语言当人话的调用：
`lib/routes.js:838` 抛 `E_LEGADO_BAD_JSON` 时 message 直接塞了 `JSON.parse` 的原文
（`fail('E_LEGADO_BAD_JSON', String(error?.message ?? error), {detail: ...})`）——
原文给 detail，message 换成「这个文件不是合法的书源 JSON，检查一下有没有复制全」。

**四、list 瘦身。** 只发 `{ url, name, group, enabled, usable }`。

### 3.2 为什么这么设计

**为什么清理放在「导入后」而不是后台定时跑。** 后台定时写用户的文件是不可接受的——
插件不该在你没操作的时候改你的数据。导入是用户主动的动作，此刻顺手整理逻辑上说得通，
而且用户刚贴完一个大包，正是书源最多、最需要清理的时刻。

**为什么清理不做「撤销」。** 不可用的源本来就用不了（`searchSource` 第一行就 throw），
删掉它不损失任何能力；需要时重新导入那个包即可。为它加一个备份文件 + 一个 restore 路由，
是给一个不存在的需求付维护成本。

**为什么「停用」也一并清。** 用户明确说过停用的源要清。停用意味着「我知道它在这但我不想用」，
留着它仍然是 2583 条列表里的噪声。**但你正在读的书的源一律留**——哪怕它停用了，
停用的源读章节照样能工作（`contentOfSource` 不看 `enabled`），清了就真断了。

**为什么错误码用通用解包而不是逐条补表。** 56 条要补，而且以后每加一个码还可能漏。
宿主侧的错误 message 本来就是给人看的中文（这是 `lib/errors.js` 的既定契约），
真正的问题只是「码前缀把中文挡住了」。解包一次，一改全好，且天然覆盖未来新增的码。

**为什么 list 只给四个字段 + 一个布尔。** 浏览器要的只是「列出来、能点、能看状态」。
规则树（`ruleSearch`/`ruleToc`/`ruleContent`）全部留在宿主侧，
前端从来不需要、也不该看到——那三条树还含正则和 URL 模板，透到 DOM 里没有意义。

### 3.3 三个动作的接口

```js
// lib/store.js 新增
async pruneLegadoSources() {
  const all = await this.listLegadoSources()
  const referenced = new Set()
  for (const dirName of await this.paths.listBookDirs()) {
    const meta = await this.readJson(path.join(this.paths.bookDir(dirName), 'meta.json'))
    if (meta && typeof meta.sourceUrl === 'string' && meta.sourceUrl !== '') referenced.add(meta.sourceUrl)
  }
  const kept = []
  const removed = []
  for (const source of all) {
    if (referenced.has(source.url)) { kept.push(source); continue }
    const usable = isUsableSource(source)
    if (!usable) { removed.push({ url: source.url, name: source.name, reason: 'unusable' }); continue }
    if (source.enabled === false) { removed.push({ url: source.url, name: source.name, reason: 'disabled' }); continue }
    kept.push(source)
  }
  if (removed.length > 0) await this.saveLegadoSources(kept)
  return { removed, kept: kept.length, protected: all.length - kept.length - removed.length }
}
```

`isUsableSource` 放在 `lib/legado.js`（和那两道 throw 同一处，避免判据漂移）：

```js
export function isUsableSource(source) {
  if (!source || typeof source.searchUrl !== 'string' || source.searchUrl.trim() === '') return false
  const bookList = source.ruleSearch?.bookList
  return typeof bookList === 'string' && bookList.trim() !== ''
}
```

路由侧（`lib/routes.js`）：

```js
'source.legado.list': async () => {
  const sources = await store.listLegadoSources()
  return {
    sources: sources.map((item) => ({
      url: String(item.url),
      name: String(item.name),
      group: typeof item.group === 'string' ? item.group : '',
      enabled: item.enabled !== false,
      usable: isUsableSource(item),
    })),
  }
},
```

限额（`lib/routes.js:2168-2170` 附近）：

```js
const LEGADO_IMPORT_BYTES = 32 * 1024 * 1024
const limit = rest === 'shelf.import'
  ? importLimit
  : (rest === 'source.legado.import' ? LEGADO_IMPORT_BYTES : defaultLimit)
```

解包（`client/src/api.js`，插在 `:99` `humanizeError` 的 `if (text === '') return ''` 之后）：

```js
// 宿主契约是「CODE: 人话」。码前缀本身会被 MACHINE_PATTERNS 判成机器语言，
// 所以先剥掉它：后半段是中文且不含机器语言，就直接用它。
const unpacked = /^([A-Z][A-Z0-9_]{2,40}):\s*([\s\S]+)$/.exec(text)
if (unpacked) {
  const rest = unpacked[2].trim()
  if (rest !== '' && /[\u4e00-\u9fa5]/.test(rest) && !MACHINE_PATTERNS.some((re) => re.test(rest))) return rest
}
```

### 3.4 判据

清理之后，从书源面板能看见的源必须满足：要么可用（能搜到书），要么停用但被某本书引用着。
**「不可用且没人引用」这一类应该在文件里彻底不存在。**

### 3.6 深色模式：四处「变量没定义，字面浅色漏出来」

这是本轮新加的一节，来自用户报的第二个问题：「深色模式下书源面板白底看不清」。**先说结论：
书源面板本身是干净的**，30 个 `dr-*` 类逐个验过，只有 `.dr-modal-mask` 一处字面量
（`rgba(0,0,0,.42)`，遮罩本来就该是半透明黑），其余全走 `var()` 或宿主 token。
真正会漏出浅色的是另四处：**它们用了一个全仓从未定义的变量名**，于是固件里的字面兜底生效。

| 变量 | 使用点 | 兜底值 | 后果 |
| --- | --- | --- | --- |
| `--dsh-reading-ui-rule` | `style.js:3101` `.dr-paper-banner` | `#e2ded4` | 论文提示条浅描边 |
| | `style.js:3188` `.dr-notes-row` | `#e3e1dc` | 笔记行浅描边 |
| | `style.js:3219` `.dr-notes-preview` | `#ddd9d2` | 预览块浅虚框 |
| | `style.js:3248` `.dr-profile` | `rgba(0,0,0,.09)` | 四张卡浅描边 |
| `--dsh-reading-ui-bg-card` | `style.js:3190` `.dr-notes-row` | `#fbfaf7` | **笔记行白底（用户看到的那张白卡片）** |
| | `style.js:3234` `.dr-notes-preview-text` | `#fff` | Markdown 预览纯白底 |
| `--dsh-reading-mono` | `style.js:3229` `.dr-notes-preview-text` | `ui-monospace` 栈 | 只是字体，与颜色无关 |
| `--dsh-reading-accent` | `style.js:1065` `.dr-pagejump-input:focus` | `#4a7dff` | 页码输入框焦点环偏亮 |

**前置条件（验证过）：** 这四个使用点都落在 `CSS_TOKENS` 的选择器组里
（`style.js:1626-1630` = `.dr-root` / `.dr-reader` / `.dr-side` / `.dr-modal-mask` / `.dr-ask-backdrop`）——
`.dr-notes-row` / `.dr-notes-preview` / `.dr-profile` 都在笔记侧栏（`.dr-side` 内），
`.dr-paper-banner` 在 `.dr-root` 内。所以补了定义就一定能继承到，不需要再往别处复制声明。
**如果以后有人把卡片挪到这三个根之外，别名不会生效**——这条要写进 docs/17。

**顺便提醒下一轮的人：一个朴素的全仓变量扫描会报 8 个「未定义」，但其中 4 个是假警报。**
`--dsh-reading-ink`(14 次) / `--dsh-reading-paper`(5) / `--dsh-reading-rule`(4) /
`--dsh-reading-side-width`(2) 都是在 `client/src/reader.js:1801` 与 `:1816-1820` 用
JS 对象字面量内联设的（`style: { '--dsh-reading-paper': theme.paper, … }`），
朴素正则扫不到那种写法。真正该修的只有本节列的四个。

**为什么这四个名字不存在。** `CSS_TOKENS`（`style.js:1625-1675`）里定义的是
`--dsh-reading-ui-line` / `-ui-bg` / `-ui-bg-soft` / `-ui-bg-sink`，
写笔记面板那批规则的人用的是 `-ui-rule` / `-ui-bg-card` / `-mono`，
两批名字各写各的，谁也没报错——`var()` 找不到就静默取兜底，浏览器不会提醒。

**修法（只加三行 + 改一处名字，不动布局）。**

在 `CSS_TOKENS` 的 `--dsh-reading-ui-line-strong`（`:1637`）后面插三个别名：

```css
/* 笔记面板用的三个名字（0.13.0 写规则时漏了定义，深色下一直吃字面浅色）。 */
--dsh-reading-ui-rule: var(--dsh-reading-ui-line, #e2ded5);
--dsh-reading-ui-bg-card: var(--dsh-reading-ui-bg, #ffffff);
--dsh-reading-mono: ui-monospace, SFMono-Regular, Menlo, monospace;
```

**不把这四处使用点改成 `-ui-line` / `-ui-bg`。** 两个名字语义并不完全等价
（`bg-card` 是「卡片表面」，比 `bg` 多一层抬升的意味），改名要动 4 行、
要重新验对比度、收益为零。加别名是 3 行 diff，一处定义、四处生效，且可被测试钉住。

`style.js:1065` 的 `var(--dsh-reading-accent, #4a7dff)` 改成
`var(--dsh-reading-ui-accent, #4a7dff)`——后者已经在 `CSS_TOKENS` 里，
跟着宿主的 `brand-primary` 走，焦点环不再是一个自造的亮蓝。

**这一版明确不动的三件事。**

1. **不给 `.dr-root` 加 `data-theme`。** `style.js:2002-2016` 那段夜间高亮钩子同时写了
   `.dr-reader[data-theme=dark]` 和 `.dr-root[data-theme=dark]`，但 `.dr-root` 从来不带
   `data-theme`（`app.js:1913`、`app.js:2253-2275`、`shelf.js:1925-1927` 都不写），
   所以那半边是死代码。让它活过来会一次性改掉书架、笔记面板、弹窗的全部配色——
   那是重写主题引擎，不是修 bug。
2. **不让侧栏跟正文纸面走。** `.dr-side` 用宿主 token（`style.js:714-722`），
   `.dr-reader` 用内联纸面变量（`reader.js:1816-1820`）。宿主浅色 + 阅读器夜间时，
   左边深正文、右边白侧栏，观感确实割裂——但这是**设计取舍**（侧栏属于 App 外壳，
   不属于书本纸面），改了会把「夜间阅读」变成「整套 App 夜间」，
   与设置里那个只影响纸面的主题开关语义冲突。留到真有用户抱怨再谈，理由记在这里。
3. **不动 `.dr-modal`。** 它 `style.js:1247-1258` 用的是 `--dsw-alias-bg-base` +
   `--dsw-alias-label-primary`，深色下一律翻转，本来就对。

**判据。** 在 DSH 深色主题下：笔记面板的行、预览块、四张画像卡描边与底色都是深色系，
不出现 `#fbfaf7` / `#fff` / `#e3e1dc` 这一族浅色；书源面板不出现任何非遮罩的字面颜色。
这条由新建的 `test/dark_test.mjs` 守着（见第七节第 10 条）。

## 四、不做「自动后台清理」的原因

写在这里，是因为「自动清理」四个字很容易被理解成「插件自己找时机扫一遍」。

**插件在任何用户没有操作的时刻改用户的文件，是越界。** 用户可能正开着 Obsidian 整理笔记、
可能正把 2583 条源导出备份、可能刚导完一批准备明天慢慢筛。这时候后台把 542 条删了，
用户看到的是「我明明导进去的源怎么少了」。

导入后清理是另一回事：用户刚刚主动做了一个「让源变多」的动作，而清理是同一个动作的收尾，
语义上是「这次导入我帮你整理好了」，不是「我趁你不在动了你的东西」。

## 五、明确不做

1. **不做书源规则的自动修复**：542 条不可用的源里，有一部分只是 `searchUrl` 模板写错了一个字符。
   自动猜、自动改，改错了比删了更糟——用户会以为这个源是好的。宁可删掉，需要时重新导入。
2. **不做两套书源的数据迁移**：老的 `settings.bookSources` 最多 8 条，格式（id/name/searchUrl 模板）
   与 Legado 源（含完整规则树）根本不是一回事，没法自动转。删掉即可，用户要的话自己在
   Legado 面板导入对应的源。
3. **不改 Legado 解析器**（`lib/legado.js` 1013 行）：这版只加一个 `isUsableSource` 纯函数，
   其余一行不动。解析器的正确性由 `test/legado_test.mjs` 的 15 项断言守着。
4. **不做书源云端同步**：源是你自己的东西，插件不碰网络上的任何账号。
5. **不重写主题引擎**：深色下真正要修的是四个未定义变量（3.6），不是「给整个 App 加一套
   dark 主题」。`.dr-root` 目前不写 `data-theme`，靠宿主 `--dsw-alias-*` 自动翻转，
   这套机制本身是对的；加 `data-theme` 会一次性改掉书架、笔记面板、弹窗的全部配色，
   风险远大于收益。同理不动 `.dr-side` 的宿主 token 选择（侧栏属于 App 外壳，
   不属于书本纸面，与设置里那个「只影响纸面」的主题开关语义一致）。
