## 1. A｜点高亮即操作：命中判定

### 1.1 抄 foliate-js 的几何命中（MIT，可移植）

出处：`johnfactotum/foliate-js` · `overlayer.js:34-42`（`hitTest`），`view.js:406-419`（绑定）。

```js
// overlayer.js:34-42 —— 原样
hitTest({ x, y }) {
    const arr = Array.from(this.#map.entries())
    // loop in reverse to hit more recently added items first
    for (let i = arr.length - 1; i >= 0; i--) {
        const [key, obj] = arr[i]
        for (const { left, top, right, bottom } of obj.rects)
            if (top <= y && left <= x && bottom > y && right > x)
                return [key, obj.range]
    }
    return []
}
```

```js
// view.js:406-419 —— 绑定在 iframe 的 document 上，冒泡阶段（第三参 false）
doc.addEventListener('click', e => {
    const [value, range] = overlayer.hitTest(e)
    if (value && !value.startsWith(SEARCH_PREFIX)) {
        this.#emit('show-annotation', { value, index, range })
    }
}, false)
```

两个关键决定：

1. **命中的是坐标，不是 DOM 节点**。高亮层是 SVG，`pointer-events: none`（`overlayer.js:5-8`），所以文字选区完全不受影响；点击时用 `e.x/e.y` 去和 rects 比。
2. **逆序遍历**：后加的标注先命中，即「上层赢」。这同时就是重叠时的操作对象选择规则。

坐标要对齐：`range.getClientRects()` 在 iframe 文档里返回的是 **iframe 视口坐标**，`e.x/e.y` 也是，所以直接比，不用换算。我们的 `computeRects` 输出的是父窗口坐标，**需要另存一份 raw rects 给命中用**。

### 1.2 我们的改法（照抄 1.1，不引 SVG）

`.dr-hl` 本身 `pointer-events: auto`，比 foliate 更省事：委托一个 click 就够，不需要几何命中。

```js
// client/src/annotate.js · Overlayer()
// 1) box 上带 key
h('div', {
  key: box.key,
  'data-key': box.key,                    // 新增：命中后反查 record
  className: `dr-hl${box.isNote ? ' dr-hl-note' : ''}`,
  // ...
})

// 2) 层上委托（useEffect 里绑一次，随 layerRef 变化解绑）
useEffect(() => {
  const layer = layerRef.current
  if (!layer) return
  const onClick = (e) => {
    const el = e.target.closest && e.target.closest('.dr-hl')
    if (!el) return
    e.preventDefault()                    // 别让默认行为把选区清掉
    const key = el.dataset.key
    const rec = props.records.find((r) => r.id === key)
    if (rec) props.onActivate(rec, el.getBoundingClientRect())  // 交给 app.js 开工具条
  }
  layer.addEventListener('click', onClick)
  return () => layer.removeEventListener('click', onClick)
}, [props.records, props.onActivate])
```

如果以后要恢复「在高亮文字内部拖选」的能力，再换成 foliate 那套（`.dr-hl` 全部 `pointer-events: none` + 1.1 的 hitTest）。现在用户要的是「点一下选中整条」，div 可点反而更直接。

## 2. B｜点一下把整条高亮选中：从区间重建 Range

### 2.1 核心（我们已有 90%）

`computeRects` 里 Range 已经拿到了（`annotate.js:365` 的 `resolveCached`），只是丢了。点击时重算一次即可，成本可忽略（单条 CFI 解析）。

```js
// client/src/annotate.js —— 新增
export function selectRecord(frameWin, frameDoc, rec) {
  const range = resolveCached(frameWin, frameDoc, rec.cfi)   // 我们已有
  if (!range) return null
  const sel = frameWin.getSelection()
  sel.removeAllRanges()                                      // 必须先清，否则 addRange 变成多选区
  sel.addRange(range)
  frameWin.focus()                                           // 让 Cmd+C / 方向键立刻可用
  return range
}
```

接在 1.2 的 `onActivate` 里：

```js
const onActivate = (rec, rect) => {
  selectRecord(frameWin, frameDoc, rec)     // 先选中整条 → 用户马上能复制
  setActive({ rec, rect })                  // 再开工具条
}
```

### 2.2 为什么先选中

- 用户点高亮的第一个动作通常是复制/引用，选中态把这个动作变成零成本；
- 工具条里的「问 AI」「记笔记」都要拿选区文本，选中后直接 `frameWin.getSelection().toString()`，不用再按 CFI 取一次正文；
- readest 的做法相同（`Annotator.tsx:616-618` 注释：点击 overlay 打开 annotated 状态的工具条），它靠 CFI 反查 booknote，再渲染 popup。

注意：`sel.addRange` 之后**不要**再调 `frameDoc.execCommand`，会破坏选区。iframe 需要 `allow-same-origin`（我们已有），否则 `getSelection` 拿不到。

## 3. C｜重叠：判定与拆分

### 3.1 先抄 web-highlighter 的重叠模型（MIT，可移植）

出处：`alienzhou/web-highlighter` · `src/painter/dom.ts:274-291`。

```ts
// 已有 wrapper 被新标注覆盖：不新建节点，只把 id 记进去
const wrapOverlapNode = (selected, range, className) => {
    const $parent = selected.$node.parentNode as HTMLElement;
    const $wrap: HTMLElement = $parent;

    removeAllClass($wrap);
    addClass($wrap, className);

    const dataset = $parent.dataset;
    const formerId = dataset[CAMEL_DATASET_IDENTIFIER];

    dataset[CAMEL_DATASET_IDENTIFIER] = range.id;
    dataset[CAMEL_DATASET_IDENTIFIER_EXTRA] = dataset[CAMEL_DATASET_IDENTIFIER_EXTRA]
        ? formerId + ID_DIVISION + dataset[CAMEL_DATASET_IDENTIFIER_EXTRA]
        : formerId;

    return $wrap;
};
```

配套的 `wrapPartialNode`（`dom.ts:204-268`）负责把文本节点按 head/tail 拆开，`SplitType`（none/head/tail/both）记下来供删除时还原。它源码里的注释写得很直白（`dom.ts:293-302`）：

> Because of supporting the highlight-overlapping, Highlighter can't just wrap all nodes in a simple way.

**它允许重叠**：一个 wrapper 带主 id + `extra` 里一串历史 id，渲染时按 class 叠色，删除时从 extra 里摘一个 id。

**我们不要这套 DOM 手术**。我们的高亮是绝对定位 div，不在正文 DOM 里，拆分文本节点纯属自找麻烦。我们只需要它的两个语义：**后来的在上**、**删除只摘自己**。

### 3.2 判定：用原生 Range 比较，不碰 CFI

`Range.compareBoundaryPoints` 是浏览器自带的，跨章节时先判 `ownerDocument` 再比。

```js
// client/src/annotate.js —— 新增，range 都是 resolveCached 出来的
const R = typeof Range !== 'undefined' ? Range : { START_TO_START: 0, START_TO_END: 1, END_TO_END: 2, END_TO_START: 3 }

export function relateRanges(a, b) {
  if (!a || !b) return 'unknown'
  if (a.startContainer.ownerDocument !== b.startContainer.ownerDocument) return 'other-section'
  const aStartLtBEnd = a.compareBoundaryPoints(R.START_TO_END, b) < 0
  const bStartLtAEnd = b.compareBoundaryPoints(R.START_TO_END, a) < 0
  if (!aStartLtBEnd || !bStartLtAEnd) return 'disjoint'
  const aContainsB = a.compareBoundaryPoints(R.START_TO_START, b) <= 0
                  && a.compareBoundaryPoints(R.END_TO_END, b) >= 0
  const bContainsA = b.compareBoundaryPoints(R.START_TO_START, a) <= 0
                  && b.compareBoundaryPoints(R.END_TO_END, a) >= 0
  if (aContainsB) return 'contains'
  if (bContainsA) return 'inside'
  return 'partial'
}
```

调用点：`ann.put` 之前，把新 Range 与本章现有 records 逐一比。

| 结果 | 动作 | 理由 |
|---|---|---|
| `disjoint` / `other-section` | 放行 | 无冲突 |
| `contains` / `inside` | 放行，但 UI 提示「与已有划线重叠」 | 整段包含是最常见的合法场景（先划整段，再划其中一句） |
| `partial` | **拒绝**，把已有那条的状态改成「已合并」或提示用户先改色 | 部分重叠是唯一会让人看不懂的形态 |

不做「自动合并成一条」：合并要重算 CFI，收益低、坑多。

## 4. D｜多重叠时不叠色：矩形覆盖减法

不用 opacity 叠加，也不用拆分 DOM：把每条 box 按「先画的在下」排序，后画的把先画的矩形**减掉**，剩下的部分用**不透明**填充。这样无论叠几层，屏幕上永远只有一种颜色，且是最上层那条的颜色——和 foliate `hitTest` 逆序命中「上层赢」的语义完全一致。

```js
// client/src/annotate.js —— 新增
const hit = (a, b) => a.left < b.right && b.left < a.right && a.top < b.bottom && b.top < a.bottom

/** base 减去 cut，返回 0~4 个矩形 */
function subtractRect(base, cut) {
  if (!hit(base, cut)) return [base]
  const out = []
  if (cut.top > base.top) out.push({ ...base, bottom: Math.min(base.bottom, cut.top) })
  if (cut.bottom < base.bottom) out.push({ ...base, top: Math.max(base.top, cut.bottom) })
  const midTop = Math.max(base.top, cut.top)
  const midBottom = Math.min(base.bottom, cut.bottom)
  if (cut.left > base.left) out.push({ ...base, left: base.left, right: cut.left, top: midTop, bottom: midBottom })
  if (cut.right < base.right) out.push({ ...base, left: cut.right, right: base.right, top: midTop, bottom: midBottom })
  return out.filter((r) => r.right - r.left > 0.5 && r.bottom - r.top > 0.5)
}

export function flattenBoxes(boxes) {
  const painted = []
  for (const box of boxes) {                 // boxes 需按「下 → 上」排好（创建时间升序）
    let parts = [box]
    for (const prev of painted) parts = parts.flatMap((p) => subtractRect(p, prev))
    for (const p of parts) painted.push(p)
  }
  return painted
}
```

配套两行 CSS/样式改动：

```js
// 渲染时：fill 用不透明色；不要用 rgba 半透明
background: box.fillOpaque
// style.js：去掉 .dr-hl 的 opacity / mix-blend-mode（如果有）
```

`box.fill` 现在是半透明（`colorStyle` 产出）。取不透明色：把 `rgba(r,g,b,a)` 的 a 置 1，或直接维护 `{fill, fillSolid}` 两套色值。

性能：一章几十条标注、每条约 2-4 个 rect，`flattenBoxes` 是 O(n²)，实测可忽略；它是纯函数，可以只在 `records` 变化时算，翻页时用缓存。

## 7. 共性交互清单（≥5 条，照做即可）

1. **点高亮 → 就地浮工具条**，不跳页、不切侧栏（foliate / readest / hypothesis 全都这样）。
2. **工具条内容固定四组**：样式（划线/下划线/波浪）、颜色、笔记、删除。不要发明第五组。
3. **删除不弹确认框**，改为 toast + 撤销（readest 软删除、hypothesis `ToastMessages`）。
4. **重叠按「后加在上」处理**：命中取上层，渲染只显示上层颜色（foliate 逆序 hitTest 即此语义）。
5. **工具条位置跟着选区/高亮 rect 走**，上方放不下就翻到下方（hypothesis `AdderToolbar` 的 `arrowDirection: 'up' | 'down'`，`AdderToolbar.tsx:39-55`）。
6. **点高亮顺手选中整条文字**（我们加的第 2 节，成本最低、感知最强）。
7. **键盘可达**：工具条按钮可真 Tab 聚焦，`aria-label` 写全（readest `HighlightOptions.tsx:259/385`，hypothesis `useShortcut`）。
